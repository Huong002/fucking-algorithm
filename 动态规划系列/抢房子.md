## Trộm nhà I

Bài 198「Trộm nhà」trên LeetCode đề như sau:

Trên phố có một hàng nhà, dùng mảng chứa số nguyên không âm `nums`表示, mỗi phần tử `nums[i]`代表 số tiền mặt trong nhà thứ `i`. Giờ bạn là trộm chuyên nghiệp, bạn hy vọng trộm **nhiều nhất có thể** tiền mặt trong các nhà này, nhưng, **nhà kề nhau không được đồng thời trộm**, nếu không sẽ触发/chạm báo động, bạn就凉凉/toi.

Hãy viết thuật toán, tính với tiền đề không chạm báo động, trộm được nhiều nhất bao nhiêu tiền? Chữ ký hàm như sau:

```java
int rob(int[] nums);
```

Ví dụ nhập `nums=[2,1,7,9,3,1]`, thuật toán trả về 12, trộm có thể trộm ba nhà `nums[0], nums[3], nums[5]`, tổng tiền được là 2 + 9 + 1 = 12, là lựa chọn tối ưu.

Đề rất dễ hiểu, mà特征/biểu hiện quy hoạch động很明显. Bài trước [Giải thích chi tiết quy hoạch động](https://labuladong.online/algo/essential-technique/dynamic-programming-framework/) ta tổng kết, **giải bài toán quy hoạch động就是 tìm「trạng thái」và「lựa chọn」, chỉ vậy mà thôi**.






Giả tưởng bạn就是 tên trộm chuyên nghiệp này, đi từ trái sang phải qua hàng nhà này, trước mỗi nhà đều có hai **lựa chọn**: cướp hoặc không cướp.

Nếu bạn cướp nhà này, thì bạn **肯定/chắc chắn** không được cướp nhà kề tiếp theo, chỉ bắt đầu lựa chọn từ nhà kế tiếp nữa.

Nếu bạn không cướp nhà này, thì bạn đi tới trước nhà tiếp theo, tiếp tục lựa chọn.

Khi bạn đi qua nhà cuối cùng, bạn就没得/hết cái cướp, tiền cướp được hiển nhiên là 0 (**base case**).

Logic trên rất đơn giản吧, thật ra đã明确「trạng thái」và「lựa chọn」: **chỉ số nhà trước mặt bạn chính là trạng thái, cướp và không cướp chính là lựa chọn**.

![](https://labuladong.online/algo/images/robber/1.jpg)

Trong hai lựa chọn, mỗi lần都选/chọn kết quả lớn hơn, cuối cùng得到 chính là money trộm được nhiều nhất:

```java
class Solution {
    // Hàm chính
    public int rob(int[] nums) {
        return dp(nums, 0);
    }

    // Định nghĩa: trả về giá trị lớn nhất nums[start..] cướp được
    private int dp(int[] nums, int start) {
        if (start >= nums.length) {
            return 0;
        }
        
        int res = Math.max(
                // Không cướp, đi nhà tiếp
                dp(nums, start + 1), 
                // Cướp, đi nhà kế tiếp nữa
                nums[start] + dp(nums, start + 2)
            );
        return res;
    }
}
```

明确 chuyển trạng thái,就 phát hiện với cùng vị trí `start`, tồn tại bài toán con trùng lặp, như hình dưới:

![](https://labuladong.online/algo/images/robber/2.jpg)

Trộm có nhiều lựa chọn đi tới vị trí này, nếu mỗi lần tới đây都进入/đi vào đệ quy, chẳng phải lãng phí thời gian? Nên说 tồn tại bài toán con trùng lặp, dùng bảng ghi nhớ优化:

```java
class Solution {

    private int[] memo;
    // Hàm chính
    public int rob(int[] nums) {
        // Khởi tạo bảng ghi nhớ
        memo = new int[nums.length];
        Arrays.fill(memo, -1);
        // Trộm bắt đầu cướp từ nhà thứ 0
        return dp(nums, 0);
    }

    // Định nghĩa: trả về giá trị lớn nhất dp[start..] cướp được
    private int dp(int[] nums, int start) {
        if (start >= nums.length) {
            return 0;
        }
        // Tránh tính lặp
        if (memo[start] != -1) return memo[start];
        
        int res = Math.max(
            dp(nums, start + 1), 
            dp(nums, start + 2) + nums[start]
        );
        // Ghi vào bảng ghi nhớ
        memo[start] = res;
        return res;
    }
}
```

Đây就是解法 quy hoạch động top-down, ta cũng hơi sửa, viết ra解法 **bottom-up**:

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        // dp[i] = x表示:
        // Bắt đầu cướp từ nhà thứ i, tiền nhiều nhất cướp được là x
        // base case: dp[n] = 0
        int[] dp = new int[n + 2];
        for (int i = n - 1; i >= 0; i--) {
            dp[i] = Math.max(dp[i + 1], nums[i] + dp[i + 2]);
        }
        return dp[0];
    }
}
```

Ta lại phát hiện chuyển trạng thái chỉ liên quan hai trạng thái gần nhất của `dp[i]`, nên còn优化 thêm,降 độ phức tạp không gian xuống O(1).

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        // Ghi dp[i+1] và dp[i+2]
        int dp_i_1 = 0, dp_i_2 = 0;
        // Ghi dp[i]
        int dp_i = 0; 
        for (int i = n - 1; i >= 0; i--) {
            dp_i = Math.max(dp_i_1, nums[i] + dp_i_2);
            dp_i_2 = dp_i_1;
            dp_i_1 = dp_i;
        }
        return dp_i;
    }
}
```

流程 trên, trong [Giải thích chi tiết quy hoạch động](https://labuladong.online/algo/essential-technique/dynamic-programming-framework/) ta giải chi tiết, tin là mọi người đều手到擒来/dễ dàng. Mình thấy很有意思/thú vị là follow up của bài này, cần dựa思路 hiện tại做些/ứng biến巧妙.

## Trộm nhà II

Bài 213「Trộm nhà II」trên LeetCode và bài trước描述基本 giống, trộm依然 không được cướp nhà kề nhau, đầu vào依然 là một mảng, nhưng nói bạn **các nhà này không phải một hàng, mà quây thành một vòng**.

也就是说/giờ nhà đầu và nhà cuối cũng相当/coi như kề nhau, không được đồng thời cướp. Ví dụ nhập mảng `nums=[2,3,2]`, kết quả thuật toán trả về hẳn là 3 chứ không phải 4, vì đầu và cuối không được đồng thời cướp.

Ràng buộc này trông hẳn không khó giải, bài trước [Tổng hợp bài toán ngăn xếp đơn điệu](https://labuladong.online/algo/data-structure/monotonic-stack/) nói một phương án giải mảng vòng, vậy trên bài này xử lý thế nào?

Trước hết, phòng đầu cuối không được đồng thời cướp, thì chỉ có ba trường hợp khác nhau: hoặc đều không cướp; hoặc nhà đầu cướp nhà cuối không cướp; hoặc nhà cuối cướp nhà đầu không cướp.

![](https://labuladong.online/algo/images/robber/3.jpg)

Vậy就 đơn giản呀, ba trường hợp này, trường hợp nào kết quả lớn nhất, chính là đáp án cuối! Nhưng, thật ra ta không cần so ba trường hợp, chỉ cần so trường hợp hai và ba là được, **vì hai trường hợp này余地/dư địa chọn nhà lớn hơn trường hợp một呀, tiền trong nhà đều không âm, nên余地 chọn lớn, kết quả quyết định tối ưu肯定 không nhỏ**.

Nên chỉ sửa nhẹ解法 trước đó là được:

```java
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        if (n == 1) return nums[0];
        return Math.max(robRange(nums, 0, n - 2), 
                        robRange(nums, 1, n - 1));
    }

    // Định nghĩa: trả về giá trị lớn nhất cướp được trong khoảng đóng [start,end]
    int robRange(int[] nums, int start, int end) {
        int n = nums.length;
        int dp_i_1 = 0, dp_i_2 = 0;
        int dp_i = 0;
        for (int i = end; i >= start; i--) {
            dp_i = Math.max(dp_i_1, nums[i] + dp_i_2);
            dp_i_2 = dp_i_1;
            dp_i_1 = dp_i;
        }
        return dp_i;
    }
}
```

Tới đây, câu hai cũng giải xong.

## Trộm nhà III

Bài 337「Trộm nhà III」trên LeetCode lại想法設法/nghĩ cách变花样/đổi trò, tên trộm này phát hiện nhà đối mặt giờ không phải một hàng, không phải một vòng, mà là một cây nhị phân! Nhà nằm trên node cây nhị phân, hai nhà相连/nối nhau không được đồng thời cướp, quả là tội phạm trí tuệ cao传说/đồn. Chữ ký hàm như sau:

```java
int rob(TreeNode root);
```

Ví dụ nhập cây nhị phân như hình dưới:

```
     3
    / \
   2   3
    \   \ 
     3   1
```

Thuật toán nên trả về 7, vì cướp nhà tầng một và tầng ba được số tiền cao nhất 3 + 3 + 1 = 7.

Nếu nhập cây nhị phân như hình dưới:

```
     3
    / \
   4   5
  / \   \ 
 1   3   1
```

Vậy thuật toán nên trả về 9, nếu cướp nhà tầng hai được số tiền cao nhất 4 + 5 = 9.

思路 tổng thể hoàn toàn không đổi,还是 làm lựa chọn cướp hoặc không cướp, đi lựa chọn收益/lợi lớn hơn.甚至 Ta trực tiếp按套路 này viết code:

```java
class Solution {
    Map<TreeNode, Integer> memo = new HashMap<>();
    public int rob(TreeNode root) {
        if (root == null) return 0;
        // Dùng bảng ghi nhớ loại bỏ bài toán con trùng lặp
        if (memo.containsKey(root)) 
            return memo.get(root);
        // Cướp, rồi đi nhà kế tiếp nữa
        int do_it = root.val
            + (root.left == null ? 
                0 : rob(root.left.left) + rob(root.left.right))
            + (root.right == null ? 
                0 : rob(root.right.left) + rob(root.right.right));
        // Không cướp, rồi đi nhà tiếp
        int not_do = rob(root.left) + rob(root.right);
        
        int res = Math.max(do_it, not_do);
        memo.put(root, res);
        return res;
    }
}
```

Phân tích độ phức tạp thời gian, tuy看 cấu trúc đệ quy này似乎/hình như là cây bốn chạc, nhưng实际上 nhờ优化 bảng ghi nhớ, việc hàm đệ quy làm也就是 duyệt mỗi node, không vào cùng node nhiều lần, nên độ phức tạp thời gian还是 $O(N)$, `N` là số node cây. Độ phức tạp không gian là kích thước bảng ghi nhớ, tức $O(N)$.

Nếu困惑 về phân tích độ phức tạp thời/không gian, tham khảo [Hướng dẫn thực dụng phân tích độ phức tạp thời-không gian](https://labuladong.online/algo/essential-technique/complexity-analysis/).

Nhưng điểm巧妙 của bài này là, còn解法 đẹp hơn. Ví dụ một bạn đọc bình luận解法 thế này:

```java
class Solution {
    int rob(TreeNode root) {
        int[] res = dp(root);
        return Math.max(res[0], res[1]);
    }

    // Trả về mảng kích thước 2 arr
    // arr[0]表示 không cướp root, được số tiền lớn nhất
    // arr[1]表示 cướp root, được số tiền lớn nhất
    int[] dp(TreeNode root) {
        if (root == null)
            return new int[]{0, 0};
        int[] left = dp(root.left);
        int[] right = dp(root.right);
        // Cướp, nhà tiếp就不能 cướp
        int rob = root.val + left[0] + right[0];
        // Không cướp, nhà tiếp cướp hay không,取决/phụ thuộc收益 lớn nhỏ
        int not_rob = Math.max(left[0], left[1])
                    + Math.max(right[0], right[1]);
        
        return new int[]{not_rob, rob};
    }
}
```

Độ phức tạp thời gian还是 $O(N)$, độ phức tạp không gian chỉ空间 ngăn xếp hàm đệ quy cần, tức chiều cao cây $O(H)$, không cần không gian thêm của bảng ghi nhớ.

Bạn xem hắn và思路 của ta không giống, sửa định nghĩa hàm đệ quy, sửa nhẹ思路, khiến logic自洽/nhất quán,依然 ra đáp án đúng, mà code đẹp hơn. Đây就是妙用/vị trí sau của [Tư duy cây nhị phân (cương lĩnh)](https://labuladong.online/algo/essential-technique/binary-tree-summary/)讲 trong bài trước.

Thực tế,解法 này chạy nhanh得多 hơn解法 của ta, tuy层面 phân tích thuật toán độ phức tạp thời gian giống nhau. Nguyên nhân là解法 này không dùng bảng ghi nhớ thêm, giảm复杂 tính thao tác dữ liệu, nên hiệu quả chạy thực tế sẽ nhanh.
