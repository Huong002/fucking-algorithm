Biểu thức chính quy là một công cụ非常强力/rất mạnh, bài này sẽ xem cụ thể nguyên lý底层/tầng dưới của biểu thức chính quy là gì. Bài 10「Khớp biểu thức chính quy」trên LeetCode yêu cầu ta hiện thực một thuật toán khớp regex đơn giản, gồm ký tự đại diện「.」và「*」.

Hai ký tự đại diện này常用 nhất, trong đó dấu chấm「.」khớp được một ký tự bất kỳ, dấu sao「*」cho ký tự đứng trước nó lặp lại số lần bất kỳ (gồm 0 lần).

Ví dụ mẫu `".a*b"` khớp được văn bản `"zaaab"`, cũng khớp được `"cb"`; mẫu `"a..b"` khớp được văn bản `"amnb"`; mà mẫu `".*"` thì比较牛逼/rất bá, nó khớp được mọi văn bản.

Đề bài cho ta đầu vào hai chuỗi `s` và `p`, `s`代表/đại diện văn bản, `p`代表 mẫu, hãy判断/phán đoán mẫu `p` có khớp được văn bản `s` không. Ta có thể giả sử mẫu chỉ chứa chữ thường và hai ký tự đại diện trên mà nhất định hợp lệ, không xuất hiện mẫu không hợp lệ kiểu `*a` hay `b**`,

Chữ ký hàm như sau:

```java
boolean isMatch(string s, string p);
```

Với biểu thức chính quy ta sắp hiện thực,难点 ở đâu?

Dấu chấm其实很好/thật ra rất dễ hiện thực, ký tự bất kỳ nào trong `s`, gặp ký tự đại diện `.`, vô não khớp là xong. Chủ yếu là dấu sao khó hiện thực, một khi gặp ký tự đại diện `*`, ký tự trước nó có thể chọn lặp một lần, lặp nhiều lần, hoặc không xuất hiện lần nào, phải làm sao?

Với vấn đề này, đáp án rất đơn giản, với mọi trường hợp có thể xuất hiện, liệt kê hết một lượt, chỉ cần có một trường hợp hoàn thành khớp, thì coi như `p` khớp được `s`. Một khi liên quan tới liệt kê hai chuỗi, ta nên phản xạ có điều kiện nghĩ tới技巧 quy hoạch động.

## Một, phân tích思路

Ta腦補/hình dung trước, quá trình `s` và `p` khớp nhau大致/đại khái là, hai con trỏ `i, j`分别 di chuyển trên `s` và `p`, nếu cuối cùng hai con trỏ đều di chuyển tới cuối chuỗi, thì khớp thành công, ngược lại thì khớp thất bại.

**Nếu không xét ký tự đại diện `*`, đối mặt hai ký tự chờ khớp `s[i]` và `p[j]`, việc duy nhất ta làm được là xem chúng có khớp nhau không**:

```java
boolean isMatch(String s, String p) {
    int i = 0, j = 0;
    while (i < s.length() && j < p.length()) {
        // Ký tự đại diện「.」就是 dầu vạn năng
        if (s.charAt(i) == p.charAt(j) || p.charAt(j) == '.') {
            // Khớp, khớp tiếp s[i+1..] và p[j+1..]
            i++; j++;
        } else {
            // Không khớp
            return false;
        }
    }
    return i == j;
}
```

Vậy nghĩ xem, nếu thêm ký tự đại diện `*`, cục diện sẽ hơi phức tạp một chút, nhưng只要/miễn là phân trường hợp phân tích, cũng không khó hiểu.

**Khi `p[j + 1]` là ký tự đại diện `*`, ta thảo luận theo trường hợp**:

1、Nếu `s[i] == p[j]`, thì có hai trường hợp:

1.1 `p[j]` có thể khớp nhiều ký tự, ví dụ `s = "aaa", p = "a*"`, thì `p[0]` sẽ qua `*` khớp 3 ký tự `"a"`.

1.2 `p[i]` cũng có thể khớp 0 ký tự, ví dụ `s = "aa", p = "a*aa"`, vì ký tự sau khớp được `s`, nên `p[0]` chỉ khớp 0 lần.

2、Nếu `s[i] != p[j]`, chỉ có một trường hợp:

`p[j]` chỉ khớp 0 lần, rồi xem ký tự tiếp theo có khớp `s[i]` không. Ví dụ `s = "aa", p = "b*aa"`, lúc này `p[0]` chỉ khớp 0 lần.

Tổng hợp, có thể cải tạo code trước đó針對/nhắm vào ký tự đại diện `*`:

```java
if (s.charAt(i) == p.charAt(j) || p.charAt(j) == '.') {
    // Khớp
    if (j < p.length() - 1 && p.charAt(j + 1) == '*') {
        // Có ký tự đại diện *, có thể khớp 0 lần hoặc nhiều lần
    } else {
        // Không có *, ngoan ngoãn khớp 1 lần
        i++; j++;
    }
} else {
    // Không khớp
    if (j < p.length() - 1 && p.charAt(j + 1) == '*') {
        // Có *, chỉ khớp 0 lần
    } else {
        // Không có *, không thể khớp tiếp được nữa
        return false;
    }
}
```

思路 tổng thể đã很清晰/rất rõ, nhưng vấn đề giờ là, gặp ký tự đại diện `*` thì rốt cuộc nên khớp 0 lần hay nhiều lần? Nhiều là mấy lần?

Bạn xem, đây就是 một vấn đề làm「lựa chọn」, phải liệt kê mọi lựa chọn có thể mới ra kết quả. Cốt lõi của thuật toán quy hoạch động就是「trạng thái」và「lựa chọn」, **「trạng thái」chẳng qua就是 vị trí hai con trỏ `i` và `j`,「lựa chọn」就是 `p[j]` chọn khớp mấy ký tự**.

## Hai,解法 quy hoạch động

Theo「trạng thái」, ta có thể định nghĩa một hàm `dp`:




```java
boolean dp(String s, int i, String p, int j);
```



Định nghĩa hàm `dp` như sau:

**Nếu `dp(s, i, p, j) = true`,則表示/nghĩa là `s[i..]` khớp được `p[j..]`; nếu `dp(s, i, p, j) = false`,則表示 `s[i..]` không khớp được `p[j..]`**.

Theo định nghĩa này, đáp án ta muốn chính là kết quả hàm `dp` khi `i = 0, j = 0`, nên có thể dùng hàm `dp` này như sau:

```java
boolean isMatch(String s, String p) {
    // Con trỏ i, j di chuyển từ chỉ số 0
    return dp(s, 0, p, 0);
}
```

Có thể viết logic chính của hàm `dp` theo code trước đó:

```java
// Logic cốt lõi của hàm dp (mã giả)
// Định nghĩa: hàm trả về s[i..] có khớp được p[j..] không
boolean dp(String s, int i, String p, int j) {
    if (s.charAt(i) == p.charAt(j) || p.charAt(j) == '.') {
        // Khớp
        if (j < p.length() - 1 && p.charAt(j + 1) == '*') {
            // 1.1 Ký tự đại diện khớp 0 lần hoặc nhiều lần
            return dp(s, i, p, j + 2) || dp(s, i + 1, p, j);
        } else {
            // 1.2 Khớp thông thường 1 lần
            return dp(s, i + 1, p, j + 1);
        }
    } else {
        // Không khớp
        if (j < p.length() - 1 && p.charAt(j + 1) == '*') {
            // 2.1 Ký tự đại diện khớp 0 lần
            return dp(s, i, p, j + 2);
        } else {
            // 2.2 Không thể khớp tiếp
            return false;
        }
    }
}
```

**Theo định nghĩa hàm `dp`**, mấy trường hợp này đều rất dễ giải thích:

**1.1 Ký tự đại diện khớp 0 lần hoặc nhiều lần**

Đem `j` cộng 2, `i`不变/giữ nguyên,含义/nghĩa là nhảy thẳng qua `p[j]` và ký tự đại diện sau nó, tức ký tự đại diện khớp 0 lần.

Ngay cả khi `s[i] == p[j]`,依然/vẫn có thể xuất hiện trường hợp này, như hình:

![](https://labuladong.online/algo/images/regex/5.jpeg)

Đem `i` cộng 1, `j`不变,含义 là `p[j]` đã khớp `s[i]`, nhưng `p[j]` còn có thể khớp tiếp, tức trường hợp ký tự đại diện khớp nhiều lần:

![](https://labuladong.online/algo/images/regex/2.jpeg)

Hai trường hợp chỉ cần một trường hợp hoàn thành khớp là được, nên求/phép hoặc với hai trường hợp trên.

**1.2 Khớp thông thường 1 lần**

Vì nhánh này là khớp thông thường không có `*`, vậy nếu `s[i] == p[j]`,就是 `i` và `j`分别 cộng một:

![](https://labuladong.online/algo/images/regex/3.jpeg)

**2.1 Ký tự đại diện khớp 0 lần**

Tương tự trường hợp 1.1, đem `j` cộng 2, `i`不变:

![](https://labuladong.online/algo/images/regex/1.jpeg)

**2.2 Nếu không có ký tự đại diện `*`, mà cũng không khớp, thì chỉ说明 khớp thất bại**

![](https://labuladong.online/algo/images/regex/4.jpeg)

Xem hình理解 hẳn rất dễ, giờ có thể nghĩ về base case của hàm `dp`:

**Một base case là khi `j == p.length()`**, theo định nghĩa hàm `dp`, điều này意味着 mẫu `p` đã khớp xong, vậy nên xem văn bản `s` khớp tới đâu, nếu `s` cũng恰好/vừa khớp xong,則说明/khớp thành công:




```java
if (j == p.length()) {
    return i == s.length();
}
```



**Một base case khác là khi `i == s.length()`**, theo định nghĩa hàm `dp`, trường hợp này意味着 văn bản `s` đã khớp hết, vậy có phải chỉ cần đơn giản kiểm tra `p` có khớp xong không là được?




```java
if (i == s.length()) {
    // Như vậy行 không?
    return j == p.length();
}
```



**Điều này không đúng, lúc này并不能/không thể dựa vào `j` có bằng `p.length()` không để判断 khớp xong chưa, chỉ cần `p[j..]` khớp được chuỗi rỗng,就可以 tính là hoàn thành khớp**. Ví dụ `s = "a", p = "ab*c*"`, khi `i` đi tới cuối `s`, `j`并没有/chưa đi tới cuối `p`, nhưng `p`依然 khớp được `s`.

Nên ta viết code như sau:

```java
int m = s.length(), n = p.length();

if (i == s.length()) {
    // Nếu khớp được chuỗi rỗng, nhất định là ký tự và * xuất hiện thành cặp
    if ((n - j) % 2 == 1) {
        return false;
    }
    // Kiểm tra có phải形式 dạng x*y*z* không
    for (; j + 1 < p.length(); j += 2) {
        if (p.charAt(j + 1) != '*') {
            return false;
        }
    }
    return true;
}
```

Theo思路 trên,就 có thể viết code đầy đủ:

```java
class Solution {
    // Bảng ghi nhớ
    int[][] memo;

    public boolean isMatch(String s, String p) {
        int m = s.length(), n = p.length();
        memo = new int[m][n];
        for (int[] row : memo) {
            Arrays.fill(row, -1);
        }
        // Con trỏ i, j di chuyển từ chỉ số 0
        return dp(s, 0, p, 0);
    }

    // Tính p[j..] có khớp s[i..] không
    boolean dp(String s, int i, String p, int j) {
        int m = s.length(), n = p.length();
        // base case
        if (j == n) {
            return i == m;
        }
        if (i == m) {
            if ((n - j) % 2 == 1) {
                return false;
            }
            for (; j + 1 < n; j += 2) {
                if (p.charAt(j + 1) != '*') {
                    return false;
                }
            }
            return true;
        }

        // Tra bảng ghi nhớ,防/tránh tính lặp
        if (memo[i][j] != -1) {
            return memo[i][j] == 1;
        }

        boolean res = false;

        if (s.charAt(i) == p.charAt(j) || p.charAt(j) == '.') {
            if (j < n - 1 && p.charAt(j + 1) == '*') {
                res = dp(s, i, p, j + 2) || dp(s, i + 1, p, j);
            } else {
                res = dp(s, i + 1, p, j + 1);
            }
        } else {
            if (j < n - 1 && p.charAt(j + 1) == '*') {
                res = dp(s, i, p, j + 2);
            } else {
                res = false;
            }
        }
        // Ghi kết quả hiện tại vào bảng ghi nhớ
        memo[i][j] = res ? 1 : 0;
        return res;
    }
}
```

Trong code dùng bảng băm `memo` loại bỏ bài toán con trùng lặp. Làm sao nhìn một cái ra bài toán con trùng lặp? Có thể tham khảo技巧讲 trong bài trước [Giải đáp dòng quy hoạch động](https://labuladong.online/algo/dynamic-programming/faq-summary/), rút khung đệ quy của thuật toán biểu thức chính quy:

```java
boolean dp(String s, int i, String p, int j) {
    dp(s, i, p, j + 2);     // 1
    dp(s, i + 1, p, j);     // 2
    dp(s, i + 1, p, j + 1); // 3
    dp(s, i, p, j + 2);     // 4
}
```

Nếu bắt bạn từ `dp(s, i, p, j)`得到/đi tới `dp(s, i+2, p, j+2)`,至少/ít nhất có hai đường: `1 -> 2 -> 2` và `3 -> 3`. Điều này说明 việc tính trạng thái `(i+2, j+2)`必然 tồn tại lặp, cũng就说明 tồn tại bài toán con trùng lặp, ta cần dùng bảng ghi nhớ loại bỏ, nâng hiệu quả.

Độ phức tạp thời gian của quy hoạch động là「tổng số trạng thái」*「thời gian mỗi lần đệ quy tốn」, trong bài này tổng số trạng thái đương nhiên就是 tổ hợp của `i` và `j`,也就是 `M * N` (`M` là độ dài `s`, `N` là độ dài `p`); hàm đệ quy `dp`中 không có vòng lặp (base case中 không xét, vì số lần kích hoạt base case hữu hạn), nên thời gian một lần đệ quy là hằng số. Nhân hai cái, tổng độ phức tạp thời gian là $O(MN)$.

Độ phức tạp không gian rất đơn giản, chính là kích thước bảng ghi nhớ `memo`, tức $O(MN)$.
