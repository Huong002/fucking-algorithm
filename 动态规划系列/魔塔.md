「Tháp ma thuật」là một game hầm ngục kinh điển, gặp quái phải mất máu, ăn bình máu加 máu, bạn phải thu thập chìa khóa, lên từng tầng, cuối cùng cứu công chúa xinh đẹp.

Giờ trên điện thoại vẫn chơi được game này:

![](https://labuladong.online/algo/images/dungeons/0.png)

Ừm, tin là game này承包/bao thầu không ít ký ức tuổi thơ, nhớ hồi nhỏ, một mình cầm máy chơi, hai ba người围/xúm左右/trái phải chỉ tay, khiến người chơi体验极差/cực tệ, mà người左右异常快乐/cực vui 😂

Bài 174「Trò chơi hầm ngục」trên LeetCode là một bài tương tự:

<Problem slug="dungeon-game" />

**Nói đơn giản, chính là hỏi bạn ít nhất cần bao nhiêu máu khởi đầu, để hiệp sĩ đi từ góc trái trên tới góc phải dưới, mà bất cứ lúc nào máu都要 lớn hơn 0**.

Chữ ký hàm như sau:

```java
int calculateMinimumHP(int[][] grid);
```

Bài trước [Tổng đường đi nhỏ nhất](https://labuladong.online/algo/dynamic-programming/minimum-path-sum/) viết bài tương tự, hỏi bạn từ góc trái trên tới góc phải dưới tổng đường đi nhỏ nhất là bao nhiêu.

Ta làm bài thuật toán nhất định phải举一反三/suy một ra ba, cảm thấy bài hôm nay và tổng đường đi nhỏ nhất có点 quan hệ đúng không?

Muốn tối thiểu hóa máu khởi đầu của hiệp sĩ, có phải意味着 phải tối đa hóa bình máu trên路线/hành trình của hiệp sĩ? Có phải tương đương求「tổng đường đi lớn nhất」? Có phải套 thẳng思路 tính「tổng đường đi nhỏ nhất」?

Nhưng nghĩ thêm một chút, phát hiện推论/suy luận này không成立. Ăn nhiều bình máu nhất, không nhất định就 được máu khởi đầu nhỏ nhất.

Ví dụ trường hợp dưới, nếu muốn ăn nhiều bình máu nhất được「tổng đường đi lớn nhất」, nên đi theo mũi tên hình dưới, máu khởi đầu cần 11:

![](https://labuladong.online/algo/images/dungeons/2.png)

Nhưng cũng dễ thấy, đáp án đúng hẳn là路线 hình dưới mũi tên chỉ, máu khởi đầu chỉ cần 1:

![](https://labuladong.online/algo/images/dungeons/3.png)

**Nên, mấu chốt không在于 ăn nhiều bình máu nhất, mà在于 làm sao mất ít máu nhất**.

Dạng求最值 này,肯定 phải mượn技巧 quy hoạch động, phải thiết kế hợp lý định nghĩa mảng/hàm `dp`.类比 bài trước [Bài toán tổng đường đi nhỏ nhất](https://labuladong.online/algo/dynamic-programming/minimum-path-sum/), chữ ký hàm `dp`肯定 dài thế này:

```java
int dp(int[][] grid, int i, int j);
```

Nhưng định nghĩa hàm `dp` của bài này比较有意思,按常理, định nghĩa hàm `dp` này hẳn là:

**Từ góc trái trên (`grid[0][0]`) đi tới `grid[i][j]` ít nhất cần `dp(grid, i, j)` máu**.

Định nghĩa vậy, base case就是 khi `i, j` đều bằng 0, ta viết code thế này:

```java
int calculateMinimumHP(int[][] grid) {
    int m = grid.length;
    int n = grid[0].length;
    // Ta muốn tính máu nhỏ nhất từ góc trái trên tới góc phải dưới
    return dp(grid, m - 1, n - 1);
}

int dp(int[][] grid, int i, int j) {
    // base case
    if (i == 0 && j == 0) {
        // Đảm bảo hiệp sĩ落地/đáp đất không chết là được
        return grid[i][j] > 0 ? 1 : -grid[i][j] + 1;
    }
    ...
}
```

> [!NOTE]
> Để gọn, sau này `dp(grid, i, j)` viết gọn là `dp(i, j)`, mọi người理解 là được.

Tiếp theo ta cần tìm chuyển trạng thái, còn nhớ tìm phương trình chuyển trạng thái thế nào không? Định nghĩa hàm `dp` vậy có正确 chuyển trạng thái được không?

Ta hy vọng `dp(i, j)`能够 qua `dp(i-1, j)` và `dp(i, j-1)`推导 ra, như vậy就能不断逼近 base case, cũng就能正确 chuyển trạng thái.

Cụ thể,「máu nhỏ nhất tới `A`」hẳn能够由「máu nhỏ nhất tới `B`」và「máu nhỏ nhất tới `C`」推导 ra:

![](https://labuladong.online/algo/images/dungeons/4.png)

**Nhưng vấn đề là,推 được么?实际上 là không**.

Vì theo định nghĩa hàm `dp`, bạn chỉ biết「máu nhỏ nhất到达 được `B` từ góc trái trên」, nhưng không biết「máu khi tới `B`」.

「Máu khi tới `B`」là参考/tham khảo必要 để chuyển trạng thái, mình举 ví dụ bạn就 hiểu, giả sử trường hợp hình dưới:

![](https://labuladong.online/algo/images/dungeons/5.png)

Bạn nói trường hợp này,路线 tối ưu hiệp sĩ cứu công chúa là gì?

Hiển nhiên đi theo线 xanh tới `B`, cuối cùng tới `A` đúng không, vậy máu khởi đầu chỉ cần 1; nếu đi路线 mũi tên vàng, tới `C` trước rồi tới `A`, máu khởi đầu ít nhất cần 6.

Vì sao vậy? Hiệp sĩ đi tới `B` và `C` máu khởi đầu ít nhất đều là 1, vì sao cuối cùng đi từ `B` tới `A`, chứ không từ `C` tới `A`?

Vì hiệp sĩ đi tới `B` thì máu là 11, mà đi tới `C` thì máu依然 là 1.

Nếu hiệp sĩ执意/cố要 qua `C` tới `A`, thì máu khởi đầu必须加 tới 6 mới行; mà nếu qua `B` tới `A`, máu khởi đầu là 1就够, vì dọc đường ăn bình máu, máu đủ抗/chịu伤害/sát thương của quái trên `A`.

Đây hẳn nói rất rõ, ôn lại định nghĩa hàm `dp`, trường hợp hình trên, thuật toán chỉ biết `dp(1, 2) = dp(2, 1) = 1`, đều như nhau, làm sao做出 quyết định đúng, tính `dp(2, 2)`?

**Nên说, định nghĩa mảng `dp` trước đó của ta sai,信息量不足/thông tin không đủ, thuật toán không做出 chuyển trạng thái đúng được**.

Cách đúng cần思考 ngược,依然 là hàm `dp` dưới:

```java
int dp(int[][] grid, int i, int j);
```

Nhưng ta要 sửa định nghĩa hàm `dp`:

**Từ `grid[i][j]` tới终点/đích (góc phải dưới) máu ít nhất cần là `dp(grid, i, j)`**.

Vậy viết code thế này:

```java
int calculateMinimumHP(int[][] grid) {
    // Ta muốn tính máu nhỏ nhất từ góc trái trên tới góc phải dưới
    return dp(grid, 0, 0);
}

int dp(int[][] grid, int i, int j) {
    int m = grid.length;
    int n = grid[0].length;
    // base case
    if (i == m - 1 && j == n - 1) {
        return grid[i][j] >= 0 ? 1 : -grid[i][j] + 1;
    }
    ...
}
```

Theo định nghĩa hàm `dp` mới và base case, ta muốn求 `dp(0, 0)`,那就应该试图 qua `dp(i, j+1)` và `dp(i+1, j)`推 ra `dp(i, j)`, như vậy mới不断逼近 base case, chuyển trạng thái đúng.

Cụ thể,「máu ít nhất từ `A` tới góc phải dưới」hẳn由「máu ít nhất từ `B` tới góc phải dưới」và「máu ít nhất từ `C` tới góc phải dưới」推 ra:

![](https://labuladong.online/algo/images/dungeons/6.png)

推 ra được么? Lần này được, giả sử `dp(0, 1) = 5, dp(1, 0) = 4`, thì肯定要 từ `A`走向 `C`, vì 4 nhỏ hơn 5嘛.

Vậy推出 `dp(0, 0)` là bao nhiêu thế nào?

Giả sử giá trị `A` là 1,既然 biết bước tiếp往 `C`, mà `dp(1, 0) = 4`意味着 đi tới `grid[1][0]` thì ít nhất要有 4 máu, vậy就确定 hiệp sĩ xuất hiện tại điểm `A` cần 4 - 1 = 3 máu khởi đầu, đúng không.

Vậy nếu giá trị `A` là 10,落地 đáp đất nhặt được bình máu lớn,超出/vượt nhu cầu后续, 4 - 10 = -6意味着 máu khởi đầu của hiệp sĩ là số âm, điều này hiển nhiên không行, máu hiệp sĩ nhỏ hơn 1就挂/toi, nên trường hợp này máu khởi đầu của hiệp sĩ hẳn là 1.

Tổng hợp, phương trình chuyển trạng thái đã推 ra:




```java
int res = min(
    dp(i + 1, j),
    dp(i, j + 1)
) - grid[i][j];

dp(i, j) = res <= 0 ? 1 : res;
```

Theo logic cốt lõi này, thêm bảng ghi nhớ loại bỏ bài toán con trùng lặp,就 viết thẳng được code cuối:

```java
class Solution {
    // Hàm chính
    public int calculateMinimumHP(int[][] grid) {
        int m = grid.length;
        int n = grid[0].length;
        // Bảng ghi nhớ khởi tạo toàn -1
        memo = new int[m][n];
        for (int[] row : memo) {
            Arrays.fill(row, -1);
        }

        return dp(grid, 0, 0);
    }

    // Bảng ghi nhớ, loại bỏ bài toán con trùng lặp
    int[][] memo;

    // Định nghĩa: từ (i, j) tới góc phải dưới, máu khởi đầu ít nhất cần là bao nhiêu
    int dp(int[][] grid, int i, int j) {
        int m = grid.length;
        int n = grid[0].length;
        // base case
        if (i == m - 1 && j == n - 1) {
            return grid[i][j] >= 0 ? 1 : -grid[i][j] + 1;
        }
        if (i == m || j == n) {
            return Integer.MAX_VALUE;
        }
        // Tránh tính lặp
        if (memo[i][j] != -1) {
            return memo[i][j];
        }
        // Logic chuyển trạng thái
        int res = Math.min(
                dp(grid, i, j + 1),
                dp(grid, i + 1, j)
            ) - grid[i][j];
        // Máu hiệp sĩ ít nhất là 1
        memo[i][j] = res <= 0 ? 1 : res;

        return memo[i][j];
    }
}
```
