Queue là cấu trúc dữ liệu vào trước ra trước (FIFO), stack là cấu trúc vào sau ra trước (LIFO), minh họa trực quan như sau:

![](https://labuladong.online/algo/images/stack-queue/1.jpg)

Hai cấu trúc dữ liệu này底层thực ra đều cài đặt bằng mảng hoặc linked list, chỉ là API giới hạn đặc tính của chúng, cài đặt cụ thể xem [Nguyên lý & cài đặt Queue/Stack](https://labuladong.online/algo/data-structure-basic/queue-stack-basic/) ở chương kiến thức cơ bản.

Hôm nay xem cách dùng đặc tính của「stack」để cài đặt một「queue」, và dùng「queue」để cài đặt một「stack」.

### Một, dùng stack cài đặt queue

Bài 232 trên LeetCode「Dùng ngăn xếp cài đặt hàng đợi」yêu cầu cài đặt các API như sau:

```java
class MyQueue {
    
    // Thêm phần tử vào cuối hàng đợi
    public void push(int x);
    
    // Xóa phần tử đầu hàng đợi và trả về
    public int pop();
    
    // Trả về phần tử đầu hàng đợi
    public int peek();
    
    // Kiểm tra hàng đợi có rỗng không
    public boolean empty();
}
```

Chúng ta dùng hai stack `s1, s2` là có thể cài đặt được chức năng của một queue (đặt stack như vậy có thể dễ hiểu hơn):

![](https://labuladong.online/algo/images/stack-queue/2.jpg)

Khi gọi `push` để enqueue phần tử, chỉ cần push phần tử vào `s1` là được, ví dụ `push` vào 3 phần tử lần lượt là 1,2,3, thì cấu trúc底层như sau:

![](https://labuladong.online/algo/images/stack-queue/3.jpg)

Vậy lúc này nếu dùng `peek` để xem phần tử đầu hàng đợi thì sao? Theo lý phần tử đầu hàng đợi phải là 1, nhưng trong `s1` thì 1 đang bị đè dưới đáy stack, lúc này đến lượt `s2` đóng vai trò trung chuyển: khi `s2` rỗng, có thể lấy toàn bộ phần tử của `s1` ra rồi thêm vào `s2`, **lúc này phần tử trong `s2` chính là thứ tự vào trước ra trước**:

![](https://labuladong.online/algo/images/stack-queue/4.jpg)

Khi trong `s2` đã có phần tử, gọi trực tiếp thao tác `pop` của `s2`, phần tử pop ra chính là phần tử được chèn vào sớm nhất, tức đã cài đặt được thao tác `pop` của queue.

Code đầy đủ như sau:

```java
class MyQueue {
    private Stack<Integer> s1, s2;
    
    public MyQueue() {
        s1 = new Stack<>();
        s2 = new Stack<>();
    }

    // Thêm phần tử vào cuối hàng đợi
    public void push(int x) {
        s1.push(x);
    }
    
    // Trả về phần tử đầu hàng đợi
    public int peek() {
        if (s2.isEmpty())
            // Đẩy phần tử của s1 sang s2
            while (!s1.isEmpty()) {
                s2.push(s1.pop());
            }
        return s2.peek();
    }

    // Xóa phần tử đầu hàng đợi và trả về
    public int pop() {
        // Gọi peek trước để đảm bảo s2 không rỗng
        peek();
        return s2.pop();
    }

     // Kiểm tra hàng đợi có rỗng không
     // Chỉ khi cả hai stack đều rỗng mới说明hàng đợi rỗng
    public boolean empty() {
        return s1.isEmpty() && s2.isEmpty();
    }
}
```

Đến đây, đã dùng cấu trúc stack cài đặt xong một queue, tư tưởng cốt lõi là lợi dụng hai stack phối hợp với nhau.

Đáng nói thêm, độ phức tạp thời gian của mấy thao tác này là bao nhiêu?

Khá thú vị là thao tác `peek`, khi gọi nó có thể kích hoạt vòng lặp `while`, lúc đó độ phức tạp thời gian là O(N), nhưng đa số trường hợp vòng lặp `while` sẽ không bị kích hoạt, độ phức tạp thời gian là O(1). Vì thao tác `pop` đã gọi `peek`, nên độ phức tạp thời gian của nó giống `peek`.

Với trường hợp như vậy, có thể nói **độ phức tạp thời gian worst-case** của chúng là O(N), vì chứa vòng lặp `while`, **có thể** cần chuyển phần tử từ `s1` sang `s2`.

Nhưng **độ phức tạp thời gian摊还** của chúng là O(1), hiểu như sau: với một phần tử, nhiều nhất chỉ bị chuyển một lần, tức độ phức tạp thời gian của thao tác `peek`摊đều lên mỗi phần tử là O(1).

Về phương pháp phân tích độ phức tạp thời gian, xem chi tiết [Phương pháp phân tích độ phức tạp thời-không thực dụng](https://labuladong.online/algo/essential-technique/complexity-analysis/).

### Hai, dùng queue cài đặt stack

Nếu nói stack đôi cài đặt queue khá khéo léo, thì dùng queue cài đặt stack就比较đơn giản thô bạo, chỉ cần một queue làm cấu trúc dữ liệu底层là cài đặt được.

Bài 225 trên LeetCode「Dùng hàng đợi cài đặt ngăn xếp」yêu cầu cài đặt các API như sau:

```java
class MyStack {
    
    // Thêm phần tử vào đỉnh stack
    public void push(int x);
    
    // Xóa phần tử đỉnh stack và trả về
    public int pop();
    
    // Trả về phần tử đỉnh stack
    public int top();
    
    // Kiểm tra stack có rỗng không
    public boolean empty();
}
```

Nói trước về API `push`, đưa thẳng phần tử vào queue, đồng thời ghi lại phần tử cuối hàng đợi, vì phần tử cuối hàng đợi tương đương phần tử đỉnh stack, nếu muốn `top` xem phần tử đỉnh stack thì có thể trả về trực tiếp:

```java
class MyStack {
    Queue<Integer> q = new LinkedList<>();
    int top_elem = 0;

    // Thêm phần tử vào đỉnh stack
    public void push(int x) {
        // x là cuối hàng đợi, là đỉnh của stack
        q.offer(x);
        top_elem = x;
    }
    
    // Trả về phần tử đỉnh stack
    public int top() {
        return top_elem;
    }

    public boolean empty() {
        return q.isEmpty();
    }
}
```

Cấu trúc dữ liệu底层của chúng ta là queue vào trước ra trước, mỗi lần `pop` chỉ lấy được phần tử từ đầu hàng đợi; nhưng stack là vào sau ra trước, tức API `pop` phải lấy phần tử từ cuối hàng đợi:

![](https://labuladong.online/algo/images/stack-queue/5.jpg)

Cách giải quyết đơn giản thô bạo, lấy hết những phần tử phía trước queue ra rồi加入lại vào cuối hàng đợi, để phần tử cuối hàng đợi trước đó xếp lên đầu hàng đợi, như vậy là có thể lấy ra được:

![](https://labuladong.online/algo/images/stack-queue/6.jpg)

```java
class MyStack {
    // Để tiết kiệm篇幅,省略phần code đã cho ở trên...

    // Xóa phần tử đỉnh stack và trả về
    public int pop() {
        int size = q.size();
        while (size > 1) {
            q.offer(q.poll());
            size--;
        }
        // Phần tử cuối hàng đợi trước đó đã ra đầu hàng đợi
        return q.poll();
    }
}
```

Cách cài đặt như vậy còn một vấn đề nhỏ là, phần tử cuối hàng đợi ban đầu bị đẩy lên đầu hàng đợi rồi xóa, nhưng biến `top_elem` chưa được cập nhật, chúng ta còn cần sửa nhỏ một chút:

```java
class MyStack {
    // Để tiết kiệm篇幅,省略phần code đã cho ở trên...

    // Xóa phần tử đỉnh stack và trả về
    public int pop() {
        int size = q.size();
        // Để lại 2 phần tử cuối hàng đợi
        while (size > 2) {
            q.offer(q.poll());
            size--;
        }
        // Ghi lại phần tử cuối hàng đợi mới
        top_elem = q.peek();
        q.offer(q.poll());
        // Xóa phần tử cuối hàng đợi trước đó
        return q.poll();
    }
}
```

Như vậy là cài đặt xong, code đầy đủ như sau:

```java
class MyStack {
    Queue<Integer> q = new LinkedList<>();
    int top_elem = 0;

    // Thêm phần tử vào đỉnh stack
    public void push(int x) {
        q.offer(x);
        top_elem = x;
    }
    
    // Xóa phần tử đỉnh stack và trả về
    public int pop() {
        int size = q.size();
        while (size > 2) {
            q.offer(q.poll());
            size--;
        }
        top_elem = q.peek();
        q.offer(q.poll());
        return q.poll();
    }
    
    // Trả về phần tử đỉnh stack
    public int top() {
        return top_elem;
    }
    
    // Kiểm tra stack có rỗng không
    public boolean empty() {
        return q.isEmpty();
    }
}
```

Rất rõ ràng, dùng queue cài đặt stack thì thao tác `pop` có độ phức tạp thời gian là O(N), các thao tác khác đều là O(1).

Cá nhân cho rằng, dùng queue cài đặt stack không có điểm sáng gì, nhưng dùng stack đôi cài đặt queue thì đáng học.

![](https://labuladong.online/algo/images/stack-queue/4.jpg)

Sau khi chuyển phần tử từ stack `s1` sang `s2`, phần tử trong `s2`就变成thứ tự vào trước ra trước của queue, đặc tính này hơi giống「âm âm得dương」, thực sự không dễ nghĩ ra.
