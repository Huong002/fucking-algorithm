## Tầm quan trọng của cây nhị phân

Lấy ví dụ, như hai thuật toán sắp xếp kinh điển [sắp xếp nhanh](https://labuladong.online/algo/practice-in-action/quick-sort/) và [sắp xếp归并](https://labuladong.online/algo/practice-in-action/merge-sort/), với nó俩, bạn có hiểu gì?

**Nếu bạn nói tôi, sắp xếp nhanh chính là duyệt tiền序của cây nhị phân, sắp xếp归并chính là duyệt hậu序của cây nhị phân, vậy tôi就biết bạn là cao thủ thuật toán**.

Tại sao sắp xếp nhanh và sắp xếp归并能và cây nhị phân扯quan hệ? Chúng ta phân tích đơn giản tư tưởng thuật toán và khung code của chúng:

Logic của sắp xếp nhanh là, nếu要với `nums[lo..hi]` sắp xếp, chúng ta tìm một điểm phân界 `p` trước, qua hoán đổi phần tử khiến `nums[lo..p-1]` đều nhỏ hơn hoặc bằng `nums[p]`, và `nums[p+1..hi]` đều lớn hơn `nums[p]`, rồi đệ quy去 `nums[lo..p-1]` và `nums[p+1..hi]` tìm điểm phân界mới, cuối cùng cả mảng就被sắp xếp.

Khung code của sắp xếp nhanh như sau:

```java
void sort(int[] nums, int lo, int hi) {
    // ****** Vị trí duyệt tiền序 ******
    // Qua hoán đổi phần tử dựng điểm phân界 p
    int p = partition(nums, lo, hi);
    // ************************

    sort(nums, lo, p - 1);
    sort(nums, p + 1, hi);
}
```

Dựng điểm phân界trước, rồi去mảng con trái/phải dựng điểm phân界, bạn xem đây không phải duyệt tiền序của một cây nhị phân sao?

Nói tiếp logic của sắp xếp归并, nếu要với `nums[lo..hi]` sắp xếp, chúng ta sắp xếp `nums[lo..mid]` trước, rồi sắp xếp `nums[mid+1..hi]`, cuối cùng把hai mảng con có thứ tự này归并, cả mảng就xếp tốt.

Khung code của sắp xếp归并như sau:

```java
// Định nghĩa: sắp xếp nums[lo..hi]
void sort(int[] nums, int lo, int hi) {
    int mid = (lo + hi) / 2;
    // Sắp xếp nums[lo..mid]
    sort(nums, lo, mid);
    // Sắp xếp nums[mid+1..hi]
    sort(nums, mid + 1, hi);

    // ****** Vị trí hậu序 ******
    //归并 nums[lo..mid] và nums[mid+1..hi]
    merge(nums, lo, mid, hi);
    // *********************
}
```

Sắp xếp mảng con trái/phải trước, rồi归并 (logic类似归并linked list có thứ tự), bạn xem đây có phải khung duyệt hậu序của cây nhị phân? Ngoài ra, đây không phải thuật toán chia để trị传说嘛,不过如此呀.

Nếu bạn liếc就识破底细của những thuật toán sắp xếp này, còn cần背những thuật toán kinh điển này không? Không cần. Bạn có thể动手拈来, từ khung duyệt cây nhị phân là có thể mở rộng ra thuật toán.

Nói nhiều vậy,旨在说明, tư tưởng thuật toán của cây nhị phân dùng rộng, thậm chí có thể nói, chỉ cần liên quan đệ quy, đều có thể trừu tượng thành vấn đề cây nhị phân.

Tiếp theo chúng ta讲起từ tiền/trung/hậu序của cây nhị phân, để bạn hiểu sâu魅力của cấu trúc dữ liệu này.

## Hiểu sâu tiền/trung/hậu序

Tôi先némcho bạn mấy câu hỏi, mời默默nghĩ 30 giây:

1、Duyệt tiền/trung/hậu序cây nhị phân bạn hiểu là gì,仅仅là ba List thứ tự khác nhau sao?

2、Mời phân tích, duyệt hậu序có đặc thù gì?

3、Mời phân tích, tại sao cây đa chạc không có duyệt trung序?

Trả lời không được,说明bạn hiểu tiền/trung/hậu序仅仅giới hạn ở sách giáo khoa, nhưng không sao, tôi dùng cách类比giải thích duyệt tiền/trung/hậu序 trong mắt tôi.

Trước hết, ôn lại khung duyệt đệ quy cây nhị phân nói ở [Duyệt DFS/BFS cây nhị phân](https://labuladong.online/algo/data-structure-basic/binary-tree-traverse-basic/):

```java
void traverse(TreeNode root) {
    if (root == null) {
        return;
    }
    // Vị trí tiền序
    traverse(root.left);
    // Vị trí trung序
    traverse(root.right);
    // Vị trí hậu序
}
```

Tạm kệ cái gọi là tiền/trung/hậu序, chỉ看hàm `traverse`, bạn nói nó đang làm gì?

Thực ra nó chính là một hàm能duyệt mọi Node của cây nhị phân, và bạn duyệt mảng hoặc linked list bản chất không khác:

```java
// Duyệt lặp mảng
void traverse(int[] arr) {
    for (int i = 0; i < arr.length; i++) {

    }
}

// Duyệt đệ quy mảng
void traverse(int[] arr, int i) {
    if (i == arr.length) {
        return;
    }
    // Vị trí tiền序
    traverse(arr, i + 1);
    // Vị trí hậu序
}

// Duyệt lặp单链表
void traverse(ListNode head) {
    for (ListNode p = head; p != null; p = p.next) {

    }
}

// Duyệt đệ quy单链表
void traverse(ListNode head) {
    if (head == null) {
        return;
    }
    // Vị trí tiền序
    traverse(head.next);
    // Vị trí hậu序
}
```

Duyệt单链表và mảng có thể lặp, cũng có thể đệ quy, **cấu trúc cây nhị phân chẳng qua là链表nhị chạc**, nó không cách nào改đơn giản thành dạng lặp của vòng for, nên chúng ta duyệt cây nhị phân thường đều dùng dạng đệ quy.

Bạn cũng chú ý, chỉ cần là duyệt dạng đệ quy, đều có thể có vị trí tiền序và hậu序, lần lượt trước và sau đệ quy.

**Cái gọi là vị trí tiền序, chính là lúc vừa vào một Node (phần tử), vị trí hậu序 chính là lúc sắp rời một Node (phần tử)**, vậy tiến thêm, bạn viết code ở vị trí khác nhau, thời cơ chạy code cũng khác:

![](https://labuladong.online/algo/images/binary-tree-summary/1.jpeg)

Ví dụ, nếu bắt bạn **in ngược** giá trị mọi Node trên một单链表, bạn làm sao?

Cách cài đặt dĩ nhiên nhiều, nhưng nếu bạn hiểu đệ quy đủ透, có thể lợi dụng vị trí hậu序để thao tác:

```java
// Duyệt đệ quy单链表, in ngược phần tử linked list
void traverse(ListNode head) {
    if (head == null) {
        return;
    }
    traverse(head.next);
    // Vị trí hậu序
    print(head.val);
}
```

Kết hợp hình trên, bạn phải biết tại sao đoạn code này能in ngược单链表, bản chất là lợi dụng stack của đệ quy giúp bạn cài đặt hiệu quả duyệt ngược.

Vậy nói về cây nhị phân cũng giống, chỉ là thêm một vị trí trung序mà thôi.

Trong sách giáo khoa chỉ hỏi bạn kết quả duyệt tiền/trung/hậu序lần lượt là gì, nên với một người chỉ học khóa cấu trúc dữ liệu đại học, anh ta大概cho rằng tiền/trung/hậu序của cây nhị phân chẳng qua tương ứng ba danh sách `List<Integer>` thứ tự khác nhau.

Nhưng tôi muốn nói, **tiền/trung/hậu序là ba thời điểm đặc biệt xử lý mỗi Node trong quá trình duyệt cây nhị phân**, tuyệt không仅仅là ba List thứ tự khác nhau:

Code vị trí tiền序chạy lúc vừa vào một Node cây nhị phân;

Code vị trí hậu序chạy lúc sắp rời một Node cây nhị phân;

Code vị trí trung序chạy lúc cây con trái của một Node cây nhị phân đều duyệt xong, sắp bắt đầu duyệt cây con phải.

Bạn chú ý dùng từ của bài này, tôi一直nói「vị trí」tiền/trung/hậu序, chính là muốn khác với「duyệt」tiền/trung/hậu序 mọi người thường nói: bạn có thể ở vị trí tiền序viết code往một List塞phần tử, vậy cuối ra chính là kết quả duyệt tiền序; nhưng không phải nói bạn就不可以viết code phức tạp hơn làm việc phức tạp hơn.

Vẽ thành hình, ba vị trí tiền/trung/hậu序trên cây nhị phân như sau:

![](https://labuladong.online/algo/images/binary-tree-summary/2.jpeg)

**Bạn có thể phát hiện mỗi Node đều có「duy nhất」vị trí tiền/trung/hậu序thuộc mình**, nên tôi nói duyệt tiền/trung/hậu序là ba thời điểm đặc biệt xử lý mỗi Node trong quá trình duyệt cây nhị phân.

Ở đây bạn cũng hiểu tại sao cây đa chạc không có vị trí trung序, vì mỗi Node của cây nhị phân chỉ切换một lần duy nhất cây con trái sang phải, mà Node cây đa chạc có thể nhiều Node con, sẽ nhiều lần切换cây con để duyệt, nên Node cây đa chạc không có vị trí duyệt trung序「duy nhất」.

Nói nhiều cơ bản vậy, chính là muốn giúp bạn建立nhận thức đúng về cây nhị phân, rồi bạn sẽ phát hiện:

**Mọi vấn đề của cây nhị phân, chính là bắt bạn注入logic code khéo ở vị trí tiền/trung/hậu序, để đạt mục đích của mình, bạn chỉ cần nghĩ riêng mỗi Node phải làm gì, còn lại不用bạn管, ném cho khung duyệt cây nhị phân, đệ quy sẽ làm thao tác giống nhau trên mọi Node**.

Bạn cũng thấy, [Cơ bản thuật toán đồ thị](https://labuladong.online/algo/data-structure-basic/graph-basic/)把khung duyệt cây nhị phân mở rộng tới đồ thị, và lấy duyệt làm cơ sở cài đặt các thuật toán kinh điển của lý thuyết đồ thị, nhưng đây là chuyện sau, bài này就不nói nhiều.






## Hai思路解题

Bài trước [Tâm đắc học thuật toán của tôi](https://labuladong.online/algo/essential-technique/algorithm-summary/) nói:

**解đệ quy của bài cây nhị phân có thể chia hai类思路,类một là duyệt một lần cây nhị phân ra đáp án,类hai là qua phân rã bài toán tính ra đáp án, hai类思路này lần lượt tương ứng [Khung cốt lõi thuật toán quay lui](https://labuladong.online/algo/essential-technique/backtrack-framework/) và [Khung cốt lõi quy hoạch động](https://labuladong.online/algo/essential-technique/dynamic-programming-framework/)**.

> [!TIP]
> Ở đây nói thói quen đặt tên hàm của tôi: khi dùng思路duyệt解trong cây nhị phân chữ ký hàm thường là `void traverse(...)`, không có giá trị trả về,靠cập nhật biến ngoài để tính kết quả, mà khi dùng思路phân rã bài toán解tên hàm dựa vào chức năng cụ thể của hàm đó, mà thường sẽ có giá trị trả về, giá trị trả về là kết quả tính của bài con.
>
> Tương ứng, bạn sẽ phát hiện chữ ký hàm tôi给trong [Khung cốt lõi thuật toán quay lui](https://labuladong.online/algo/essential-technique/backtrack-framework/) thường cũng là `void backtrack(...)` không có giá trị trả về, mà trong [Khung cốt lõi quy hoạch động](https://labuladong.online/algo/essential-technique/dynamic-programming-framework/) chữ ký hàm给là hàm `dp`带giá trị trả về. Đây cũng说明liên hệ千丝万缕giữa nó俩và cây nhị phân.
>
> Dù đặt tên hàm không có yêu cầu cứng, nhưng tôi vẫn khuyên bạn cũng theo phong cách này của tôi, như vậy更nổi bật tác dụng của hàm và mô thức tư duy解题, tiện bạn tự hiểu và dùng.

Lúc đó tôi dùng vấn đề độ sâu lớn nhất của cây nhị phân để ví dụ, trọng điểm là把hai思路này so với quy hoạch động và thuật toán quay lui, mà trọng điểm của bài này là phân tích hai思路này giải bài cây nhị phân thế nào.

Bài 104 trên LeetCode「Độ sâu lớn nhất của cây nhị phân」chính là bài độ sâu lớn nhất, cái gọi là độ sâu lớn nhất chính là số Node trên đường dài nhất từ Node gốc tới Node lá「xa nhất」, ví dụ nhập cây nhị phân này, thuật toán phải trả về 3:

![](https://labuladong.online/algo/images/binary-tree-summary/tree.jpg)

思路làm bài này của bạn là gì? Hiển nhiên duyệt một lần cây nhị phân, dùng một biến ngoài ghi độ sâu mỗi Node tới, lấy giá trị lớn nhất là ra độ sâu lớn nhất, **đây chính là思路duyệt cây nhị phân tính đáp án**.

Code解法như sau:

```java
class Solution {
    // Ghi độ sâu lớn nhất
    int res = 0;

    // Ghi độ sâu của Node duyệt tới
    int depth = 0;

    public int maxDepth(TreeNode root) {
        traverse(root);
        return res;
    }

    // Khung duyệt cây nhị phân
    void traverse(TreeNode root) {
        if (root == null) {
            return;
        }
        // Vị trí tiền序
        depth++;
        if (root.left == null && root.right == null) {
            // Tới Node lá, cập nhật độ sâu lớn nhất
            res = Math.max(res, depth);
        }
        traverse(root.left);
        traverse(root.right);
        // Vị trí hậu序
        depth--;
    }
}
```

解法này phải rất dễ hiểu, nhưng tại sao cần ở vị trí tiền序tăng `depth`, ở vị trí hậu序giảm `depth`?

Vì phía trước nói, vị trí tiền序là lúc vào một Node, vị trí hậu序là lúc rời một Node, `depth` ghi độ sâu Node đệ quy tới hiện tại, bạn把 `traverse` hiểu thành một con trỏ游走trên cây nhị phân, nên dĩ nhiên要维护vậy.

Còn cập nhật `res`, bạn放到vị trí tiền/trung/hậu序 đều được, chỉ cần đảm bảo sau khi vào Node, trước khi rời Node (tức sau khi `depth` tự tăng, trước khi tự giảm) là được.

Dĩ nhiên, bạn cũng rất dễ phát hiện độ sâu lớn nhất của một cây nhị phân có thể qua độ sâu lớn nhất của cây con推ra, **đây chính là思路phân rã bài toán tính đáp án**.

Code解法như sau:

```java
class Solution {
    // Định nghĩa: nhập Node gốc, trả về độ sâu lớn nhất của cây nhị phân này
    public int maxDepth(TreeNode root) {
        if (root == null) {
            return 0;
        }
        // Lợi dụng định nghĩa, tính độ sâu lớn nhất của cây con trái/phải
        int leftMax = maxDepth(root.left);
        int rightMax = maxDepth(root.right);
        // Độ sâu lớn nhất của cả cây bằng độ sâu lớn nhất của cây con trái/phải lấy max,
        // Rồi cộng thêm Node gốc自己
        int res = Math.max(leftMax, rightMax) + 1;

        return res;
    }
}
```

Chỉ cần明确định nghĩa của hàm đệ quy,解法này cũng không khó hiểu, nhưng tại sao logic code chính tập trung ở vị trí hậu序?

Vì cốt lõi đúng của思路này là, bạn đúng có thể qua độ sâu lớn nhất của cây con推ra độ sâu của cây gốc, nên dĩ nhiên要先lợi dụng định nghĩa của hàm đệ quy tính độ sâu lớn nhất của cây con trái/phải, rồi推出độ sâu lớn nhất của cây gốc, logic chính tự nhiên放在vị trí hậu序.

Nếu bạn hiểu hai思路của vấn đề độ sâu lớn nhất này, **vậy chúng ta quay đầu xem lại duyệt tiền/trung/hậu序cơ bản nhất của cây nhị phân**, ví dụ bài 144 trên LeetCode「Duyệt tiền序cây nhị phân」, bắt bạn tính kết quả duyệt tiền序.

解法quen thuộc của chúng ta chính là dùng思路「duyệt」, tôi nghĩ phải không có gì要nói:

```java
class Solution {
    //存放kết quả duyệt tiền序
    List<Integer> res = new LinkedList<>();

    // Trả về kết quả duyệt tiền序
    public List<Integer> preorderTraversal(TreeNode root) {
        traverse(root);
        return res;
    }

    // Hàm duyệt cây nhị phân
    void traverse(TreeNode root) {
        if (root == null) {
            return;
        }
        // Vị trí tiền序
        res.add(root.val);
        traverse(root.left);
        traverse(root.right);
    }
}
```

Nhưng bạn có thể dùng思路「phân rã bài toán」,来tính kết quả duyệt tiền序 không?

Nói cách khác, đừng dùng hàm phụ như `traverse` và bất kỳ biến ngoài nào, đơn thuần dùng hàm `preorderTraverse` đề cho đệ quy解题, bạn biết không?

Chúng ta biết đặc điểm của duyệt tiền序là, giá trị Node gốc xếp đầu, tiếp là kết quả duyệt tiền序của cây con trái, cuối là kết quả duyệt tiền序của cây con phải:

![](https://labuladong.online/algo/images/binary-tree-summary/3.jpeg)

Vậy đây không phải có thể phân rã bài toán sao, **kết quả duyệt tiền序của một cây nhị phân = Node gốc + kết quả duyệt tiền序của cây con trái + kết quả duyệt tiền序của cây con phải**.

Nên, bạn có thể cài đặt thuật toán duyệt tiền序thế này:

```java
class Solution {
    // Định nghĩa: nhập Node gốc của một cây nhị phân, trả về kết quả duyệt tiền序của cây này
    List<Integer> preorderTraversal(TreeNode root) {
        List<Integer> res = new LinkedList<>();
        if (root == null) {
            return res;
        }
        // Kết quả của duyệt tiền序, root.val ở đầu
        res.add(root.val);
        // Lợi dụng định nghĩa hàm, phía sau接着kết quả duyệt tiền序của cây con trái
        res.addAll(preorderTraversal(root.left));
        // Lợi dụng định nghĩa hàm, cuối接着kết quả duyệt tiền序của cây con phải
        res.addAll(preorderTraversal(root.right));
        return res;
    }
}
```

Duyệt trung序và hậu序 cũng类似, chỉ cần把 `add(root.val)`放到vị trí trung序và hậu序tương ứng là được.

解法này ngắn gọn, nhưng tại sao không thường gặp?

Một nguyên nhân là **độ phức tạp của thuật toán này không dễ把控**,比较phụ thuộc đặc tính ngôn ngữ.

Java的话dù ArrayList hay LinkedList, độ phức tạp của phương thức `addAll` đều O(N), nên tổng worst-case độ phức tạp thời gian sẽ đạt O(N^2), trừ phi bạn tự cài đặt một phương thức `addAll` độ phức tạp O(1),底层dùng linked list的话là có thể làm được, vì nhiều linked list chỉ cần thao tác con trỏ đơn giản là có thể nối lại.

Dĩ nhiên, nguyên nhân chủ yếu vẫn vì sách giáo khoa chưa bao giờ dạy vậy...

Trên举hai ví dụ đơn giản, nhưng còn không ít bài cây nhị phân có thể đồng thời dùng hai思路để nghĩ và求解, đây就要靠bạn tự多luyện và nghĩ, đừng仅仅满足với một思路解法quen thuộc.

Tổng hợp, quá trình nghĩ tổng quát khi gặp một bài cây nhị phân là:

**1、Có thể qua duyệt một lần cây nhị phân ra đáp án không**? Nếu được, dùng một hàm `traverse`配合biến ngoài để cài đặt.

**2、Có thể định nghĩa một hàm đệ quy, qua đáp án của bài con (cây con)推ra đáp án của bài gốc không**? Nếu được, viết định nghĩa của hàm đệ quy này, và tận dụng giá trị trả về của hàm này.

**3、Dù dùng mô thức tư duy nào, bạn都要明白mỗi Node của cây nhị phân cần làm gì, cần làm lúc nào (tiền/trung/hậu序)**.

Ở [Luyện chuyên đề đệ quy cây nhị phân](https://labuladong.online/algo/intro/binary-tree-practice/) của站列hơn 100 bài cây nhị phân, hoàn toàn dùng hai mô thức tư duy trên dẫn bạn luyện từng bước, giúp bạn nắm hoàn toàn tư duy đệ quy, dễ hiểu thuật toán cao cấp hơn.






## Đặc thù của vị trí hậu序

Trước khi nói vị trí hậu序, nói đơn giản tiền序và trung序trước.

Vị trí tiền序本身thực ra không có tính chất特别gì, sở dĩ bạn phát hiện似乎nhiều bài đều ở vị trí tiền序viết code, thực tế vì chúng ta quen把những code không nhạy với vị trí tiền/trung/hậu序viết ở vị trí tiền序mà thôi.

Vị trí trung序chủ yếu dùng trong场景BST, bạn hoàn toàn có thể把duyệt trung序của BST cho là duyệt mảng có thứ tự.

> [!IMPORTANT]
> **Quan sát kỹ, code vị trí tiền/trung/hậu序, năng lực依次tăng强**.
>
> Code vị trí tiền序chỉ能từ tham số hàm lấy dữ liệu Node cha truyền tới.
>
> Code vị trí trung序không chỉ có thể lấy dữ liệu tham số, còn có thể lấy dữ liệu cây con trái qua giá trị trả về của hàm truyền về.
>
> Code vị trí hậu序mạnh nhất, không chỉ có thể lấy dữ liệu tham số, còn có thể đồng thời lấy dữ liệu cây con trái/phải qua giá trị trả về của hàm truyền về.
>
> Nên, vài trường hợp把code chuyển tới vị trí hậu序hiệu suất cao nhất; vài việc, chỉ code vị trí hậu序làm được.

Lấy vài ví dụ cụ thể để感受区别năng lực của chúng. Giờ cho bạn một cây nhị phân, tôi hỏi bạn hai vấn đề đơn giản:

1、Nếu xem Node gốc là tầng 1, in tầng mỗi Node thế nào?

2、In cây con trái/phải của mỗi Node各có bao nhiêu Node thế nào?

Vấn đề một có thể viết code thế này:

```java
// Hàm duyệt cây nhị phân
void traverse(TreeNode root, int level) {
    if (root == null) {
        return;
    }
    // Vị trí tiền序
    printf("Node %s at level %d", root.val, level);
    traverse(root.left, level + 1);
    traverse(root.right, level + 1);
}

// Gọi thế này
traverse(root, 1);
```

Vấn đề hai có thể viết code thế này:

```java
// Định nghĩa: nhập một cây nhị phân, trả về tổng số Node của cây này
int count(TreeNode root) {
    if (root == null) {
        return 0;
    }
    int leftCount = count(root.left);
    int rightCount = count(root.right);
    // Vị trí hậu序
    printf("Node %s 的cây con trái có %d Node, cây con phải có %d Node",
            root, leftCount, rightCount);

    return leftCount + rightCount + 1;
}
```

> [!NOTE]
> Một Node ở tầng mấy, bạn từ Node gốc duyệt qua的过程là có thể顺带ghi, dùng tham số của hàm đệ quy là có thể truyền xuống; mà lấy một Node làm gốc cả cây con có bao nhiêu Node, bạn必須duyệt xong cây con后mới đếm rõ, rồi qua giá trị trả về của hàm đệ quy lấy đáp án.
>
> Kết hợp hai vấn đề đơn giản này, bạn品vị đặc điểm của vị trí hậu序, chỉ vị trí hậu序mới qua giá trị trả về lấy thông tin của cây con.
>
> **Vậy nói cách khác, một khi bạn phát hiện đề liên quan cây con,大概率要cho hàm đặt định nghĩa và giá trị trả về hợp, ở vị trí hậu序viết code**.

Tiếp theo xem vị trí hậu序phát huy tác dụng trong bài thực tế thế nào,聊đơn giản bài 543 trên LeetCode「Đường kính của cây nhị phân」, bắt bạn tính độ dài đường kính dài nhất của một cây nhị phân.

Cái gọi là「đường kính」của cây nhị phân, chính là độ dài đường đi giữa hai结点bất kỳ.「Đường kính」dài nhất không nhất định要xuyên Node gốc, ví dụ cây nhị phân dưới:

![](https://labuladong.online/algo/images/binary-tree-summary/tree1.png)

Đường kính dài nhất của nó là 3, tức mấy「đường kính」 `[4,2,1,3]`, `[4,2,1,9]` hoặc `[5,2,1,3]` này.

Mấu chốt giải bài này là, **độ dài「đường kính」mỗi cây nhị phân, chính là tổng độ sâu lớn nhất của cây con trái/phải của một Node**.

Giờ bắt tôi求đường kính dài nhất trong cả cây, vậy思路trực tiếp chính là duyệt mỗi Node trong cả cây, rồi qua độ sâu lớn nhất của cây con trái/phải của mỗi Node tính「đường kính」mỗi Node, cuối cùng把mọi「đường kính」求max là được.

Thuật toán độ sâu lớn nhất chúng ta vừa cài đặt xong,思路trên là có thể viết code sau:

```java
class Solution {
    // Ghi độ dài đường kính lớn nhất
    int maxDiameter = 0;

    public int diameterOfBinaryTree(TreeNode root) {
        // Với mỗi Node tính đường kính,求đường kính lớn nhất
        traverse(root);
        return maxDiameter;
    }

    // Duyệt cây nhị phân
    void traverse(TreeNode root) {
        if (root == null) {
            return;
        }
        // Với mỗi Node tính đường kính
        int leftMax = maxDepth(root.left);
        int rightMax = maxDepth(root.right);
        int myDiameter = leftMax + rightMax;
        // Cập nhật đường kính lớn nhất toàn cục
        maxDiameter = Math.max(maxDiameter, myDiameter);
        
        traverse(root.left);
        traverse(root.right);
    }

    // Tính độ sâu lớn nhất của cây nhị phân
    int maxDepth(TreeNode root) {
        if (root == null) {
            return 0;
        }
        int leftMax = maxDepth(root.left);
        int rightMax = maxDepth(root.right);
        return 1 + Math.max(leftMax, rightMax);
    }
}
```

解法này đúng, nhưng thời gian chạy rất dài, nguyên nhân cũng rất rõ, `traverse` duyệt mỗi Node还gọi hàm đệ quy `maxDepth`, mà `maxDepth` là要duyệt mọi Node của cây con, nên worst-case độ phức tạp thời gian là O(N^2).

Đây就xuất hiện tình huống vừa thảo luận, **vị trí tiền序không cách nào lấy thông tin cây con, nên chỉ能để mỗi Node gọi hàm `maxDepth`去tính độ sâu của cây con**.

Vậy tối ưu thế nào? Chúng ta phải把logic tính「đường kính」放在vị trí hậu序, chính xác phải放在vị trí hậu序của `maxDepth`, vì vị trí hậu序của `maxDepth` là biết độ sâu lớn nhất của cây con trái/phải.

Nên, sửa chút logic code là ra解法tốt hơn:

```java
class Solution {
    // Ghi độ dài đường kính lớn nhất
    int maxDiameter = 0;

    public int diameterOfBinaryTree(TreeNode root) {
        maxDepth(root);
        return maxDiameter;
    }

    int maxDepth(TreeNode root) {
        if (root == null) {
            return 0;
        }
        int leftMax = maxDepth(root.left);
        int rightMax = maxDepth(root.right);
        // Vị trí hậu序, tiện tính đường kính lớn nhất
        int myDiameter = leftMax + rightMax;
        maxDiameter = Math.max(maxDiameter, myDiameter);

        return 1 + Math.max(leftMax, rightMax);
    }
}
```

> [!NOTE]
> Bài lợi dụng vị trí hậu序, thường đều dùng思路「phân rã bài toán」. Vì Node hiện tại nhận và lợi dụng thông tin cây con trả về, đây就意味着bạn把bài gốc phân thành bài con của Node hiện tại + cây con trái/phải.
>
> Ngược lại, nếu bạn viết解法đệ quy lồng đệ quy类似lúc đầu,大概率cũng cần反思có thể qua duyệt hậu序tối ưu không.

Thêm nhiều bài lợi dụng vị trí hậu序xem [Dẫn bạn刷cây nhị phân từng bước (Phần hậu序)](https://labuladong.online/algo/data-structure/binary-tree-part3/)、[Dẫn bạn刷cây tìm kiếm nhị phân từng bước (Phần hậu序)](https://labuladong.online/algo/data-structure/bst-part4/) và [【Luyện tập tăng cường】Dùng vị trí hậu序解题](https://labuladong.online/algo/problem-set/binary-tree-post-order-i/).






## Nhìn thuật toán QHD/quay lui/DFS từ góc cây khác biệt và liên hệ

Bài trước tôi nói quy hoạch động/thuật toán quay lui chính là hai思路khác nhau của thuật toán cây nhị phân表现, tin độc giả能thấy tới đây phải cũng认可quan điểm này của tôi. Nhưng có độc giả tinh ý thường hỏi: cách nghĩ của bạn khiến tôi豁然开朗, nhưng bạn似乎一直chưa讲thuật toán DFS?

Thực ra tôi ở [Một bài diệt gọn mọi bài đảo](https://labuladong.online/algo/frequency-interview/island-dfs-summary/) chính là dùng thuật toán DFS, nhưng tôi đúng chưa dùng riêng một bài讲thuật toán DFS, **vì thuật toán DFS và thuật toán quay lui非常类似, chỉ khác chi tiết**.

 Khác chi tiết này là gì? Thực ra chính là「làm lựa chọn」và「hủy lựa chọn」rốt cuộc ở ngoài hay trong vòng for区别, thuật toán DFS ở ngoài, thuật toán quay lui ở trong.

Tại sao có区别này? Vẫn要kết hợp cây nhị phân hiểu. Phần này tôi就把ba tư tưởng thuật toán kinh điển thuật toán quay lui, thuật toán DFS, quy hoạch động, và liên hệ区别của chúng với thuật toán cây nhị phân, dùng một câu để说明:

> [!IMPORTANT]
> Thuật toán QHD/DFS/quay lui đều có thể xem mở rộng của vấn đề cây nhị phân, chỉ là điểm quan tâm của chúng khác:
>
> - Thuật toán quy hoạch động thuộc思路phân rã bài toán (chia để trị), điểm quan tâm của nó ở cả「cây con」.
> - Thuật toán quay lui thuộc思路duyệt, điểm quan tâm của nó ở「cành cây」giữa Node.
> - Thuật toán DFS thuộc思路duyệt, điểm quan tâm của nó ở单个「Node」.

Hiểu thế nào? Tôi lần lượt举ba ví dụ bạn就hiểu.

### Ví dụ một: thể hiện tư tưởng phân rã bài toán

**Ví dụ một**, cho bạn một cây nhị phân, mời bạn dùng思路phân rã bài toán viết một hàm `count`, tính cây nhị phân này tổng cộng bao nhiêu Node. Code rất đơn giản, trên đều viết:

```java
// Định nghĩa: nhập một cây nhị phân, trả về tổng số Node của cây này
int count(TreeNode root) {
    if (root == null) {
        return 0;
    }
    // Node hiện tại quan tâm là tổng số Node của hai cây con lần lượt bao nhiêu
    // Vì dùng kết quả của bài con có thể推ra kết quả của bài gốc
    int leftCount = count(root.left);
    int rightCount = count(root.right);
    // Vị trí hậu序, số Node của cây con trái/phải cộng自己chính là số Node của cả cây
    return leftCount + rightCount + 1;
}
```

**Bạn xem, đây chính là思路phân rã bài toán của quy hoạch động, điểm nhìn của nó mãi là bài con cấu trúc giống nhau toàn bộ,类比lên cây nhị phân chính là「cây con」**.

Bạn xem lại vấn đề quy hoạch động cụ thể, ví dụ ví dụ Fibonacci舉trong [套路Khung quy hoạch động详解](https://labuladong.online/algo/essential-technique/dynamic-programming-framework/), điểm quan tâm của chúng ta ở giá trị trả về của từng cây con:

```java
int fib(int N) {
    if (N == 1 || N == 2) return 1;
    return fib(N - 1) + fib(N - 2);
}
```

![](https://labuladong.online/algo/images/dynamic-programming/2.jpg)



### Ví dụ hai: thể hiện tư tưởng thuật toán quay lui

**Ví dụ hai**, cho bạn một cây nhị phân, mời bạn dùng思路duyệt viết một hàm `traverse`, in quá trình duyệt cây nhị phân này, bạn xem code:

```java
void traverse(TreeNode root) {
    if (root == null) return;
    printf("Từ Node %s vào Node %s", root, root.left);
    traverse(root.left);
    printf("Từ Node %s về Node %s", root.left, root);

    printf("Từ Node %s vào Node %s", root, root.right);
    traverse(root.right);
    printf("Từ Node %s về Node %s", root.right, root);
}
```

Không khó hiểu đúng không, tốt, giờ chúng ta từ cây nhị phân进阶thành cây đa chạc, code cũng类似:

```java
// Node cây đa chạc
class Node {
    int val;
    Node[] children;
}

void traverse(Node root) {
    if (root == null) return;
    for (Node child : root.children) {
        printf("Từ Node %s vào Node %s", root, child);
        traverse(child);
        printf("Từ Node %s về Node %s", child, root);
    }
}
```

Khung duyệt cây đa chạc này là có thể延伸ra khung thuật toán quay lui trong [Khung套路thuật toán quay lui详解](https://labuladong.online/algo/essential-technique/backtrack-framework/):

```java
// Khung thuật toán quay lui
void backtrack(...) {
    // base case
    if (...) return;

    for (int i = 0; i < ...; i++) {
        // Làm lựa chọn
        ...

        // Vào tầng cây quyết định tiếp theo
        backtrack(...);

        // Hủy lựa chọn vừa làm
        ...
    }
}
```



**Bạn xem, đây chính là思路duyệt của thuật toán quay lui, điểm nhìn của nó mãi là quá trình di chuyển giữa Node,类比lên cây nhị phân chính là「cành cây」**.

Bạn xem lại vấn đề thuật toán quay lui cụ thể, ví dụ hoán vị toàn phần講trong [Thuật toán quay lui diệt gọn chín loại排列组合tập con](https://labuladong.online/algo/essential-technique/permutation-combination-subset-all-in-one/), điểm quan tâm của chúng ta ở từng cành cây:

```java
// Phần code cốt lõi thuật toán quay lui
void backtrack(int[] nums) {
    // Khung thuật toán quay lui
    for (int i = 0; i < nums.length; i++) {
        // Làm lựa chọn
        used[i] = true;
        track.addLast(nums[i]);

        // Vào cây quay lui tầng tiếp theo
        backtrack(nums);

        // Hủy lựa chọn
        track.removeLast();
        used[i] = false;
    }
}
```

![](https://labuladong.online/algo/images/permutation/2.jpeg)



### Ví dụ ba: thể hiện tư tưởng DFS

**Ví dụ ba**, tôi cho bạn một cây nhị phân, mời bạn viết một hàm `traverse`,把giá trị mỗi Node trên cây nhị phân này đều加một. Rất đơn giản đúng không, code như sau:

```java
void traverse(TreeNode root) {
    if (root == null) return;
    // Giá trị mỗi Node duyệt qua加một
    root.val++;
    traverse(root.left);
    traverse(root.right);
}
```

**Bạn xem, đây chính là思路duyệt của thuật toán DFS, điểm nhìn của nó mãi ở单个Node,类比lên cây nhị phân chính là xử lý mỗi「Node」**.

Bạn xem lại vấn đề thuật toán DFS cụ thể, ví dụ mấy bài đầu講trong [Một bài diệt gọn mọi bài đảo](https://labuladong.online/algo/frequency-interview/island-dfs-summary/), điểm quan tâm của chúng ta là mỗi ô (Node) của mảng `grid`, chúng ta要với ô duyệt qua làm ít xử lý, nên tôi nói dùng thuật toán DFS giải mấy bài này:

```java
// Logic cốt lõi thuật toán DFS
void dfs(int[][] grid, int i, int j) {
    int m = grid.length, n = grid[0].length;
    if (i < 0 || j < 0 || i >= m || j >= n) {
        return;
    }
    if (grid[i][j] == 0) {
        return;
    }
    // Mỗi ô duyệt qua đánh dấu thành 0
    grid[i][j] = 0;
    dfs(grid, i + 1, j);
    dfs(grid, i, j + 1);
    dfs(grid, i - 1, j);
    dfs(grid, i, j - 1);
}
```

![](https://labuladong.online/algo/images/island/5.jpg)



Tốt, mời bạn品kỹ ba ví dụ đơn giản trên, có phải như tôi nói: quy hoạch động quan tâm cả「cây con」, thuật toán quay lui quan tâm「cành cây」giữa Node, thuật toán DFS quan tâm单个「Node」.

Có lót này, bạn就rất dễ hiểu tại sao logic「làm lựa chọn」và「hủy lựa chọn」trong code thuật toán quay lui và thuật toán DFS vị trí khác nhau, xem hai đoạn code dưới:

```java
// Thuật toán DFS把logic「làm lựa chọn」「hủy lựa chọn」放在ngoài vòng for
void dfs(Node root) {
    if (root == null) return;
    // Làm lựa chọn
    print("enter node %s", root);
    for (Node child : root.children) {
        dfs(child);
    }
    // Hủy lựa chọn
    print("leave node %s", root);
}

// Thuật toán quay lui把logic「làm lựa chọn」「hủy lựa chọn」放在trong vòng for
void backtrack(Node root) {
    if (root == null) return;
    for (Node child : root.children) {
        // Làm lựa chọn
        print("I'm on the branch from %s to %s", root, child);
        backtrack(child);
        // Hủy lựa chọn
        print("I'll leave the branch from %s to %s", child, root);
    }
}
```

Thấy chứ, bạn thuật toán quay lui必須把logic「làm lựa chọn」và「hủy lựa chọn」放在trong vòng for, nếu không sao lấy hai端点của「cành cây」?

## Duyệt層序

Loại bài cây nhị phân chủ yếu dùng bồi dưỡng tư duy đệ quy, mà duyệt層序thuộc duyệt lặp, cũng比较đơn giản, ở đây就lướt khung code:

```java
// Nhập Node gốc của một cây nhị phân, duyệt層序cây này
void levelTraverse(TreeNode root) {
    if (root == null) return;
    Queue<TreeNode> q = new LinkedList<>();
    q.offer(root);

    // Duyệt mỗi tầng của cây nhị phân từ trên xuống dưới
    while (!q.isEmpty()) {
        int sz = q.size();
        // Duyệt mỗi Node của mỗi tầng từ trái sang phải
        for (int i = 0; i < sz; i++) {
            TreeNode cur = q.poll();
            // Cho Node tầng tiếp theo vào hàng đợi
            if (cur.left != null) {
                q.offer(cur.left);
            }
            if (cur.right != null) {
                q.offer(cur.right);
            }
        }
    }
}
```

Trong này vòng while và vòng for分管duyệt từ trên xuống dưới và từ trái sang phải:

![](https://labuladong.online/algo/images/dijkstra/1.jpeg)

Bài trước [Khung thuật toán BFS](https://labuladong.online/algo/essential-technique/bfs-framework/) chính là từ duyệt層序của cây nhị phân mở rộng ra, thường dùng求vấn đề **đường ngắn nhất** của đồ thị không trọng số.

Dĩ nhiên khung này còn có thể sửa linh hoạt, bài không cần ghi tầng (bước) có thể bỏ vòng for trong khung trên, ví dụ bài trước [Thuật toán Dijkstra](https://labuladong.online/algo/data-structure/dijkstra/) tính vấn đề đường ngắn nhất của đồ thị có trọng số, thảo luận chi tiết mở rộng của thuật toán BFS.

Đáng nói, vài bài cây nhị phân rất rõ cần dùng技巧duyệt層序, cũng có thể dùng cách duyệt đệ quy để giải, mà技巧性sẽ强hơn,非常khảo bạn把控tiền/trung/hậu序.

Tốt rồi, bài này đã够dài,围绕vị trí tiền/trung/hậu序算là把套路trong bài cây nhị phân讲透, thực能dùng ra bao nhiêu,就需要bạn tự刷题thực hành và nghĩ.

Hy vọng mọi người能khám phá càng nhiều解法càng tốt, chỉ cần参透nguyên lý của cấu trúc dữ liệu cơ bản cây nhị phân này, vậy就rất dễ trên đường học thuật toán cao cấp khác tìm抓手,打通mạch,形成khép vòng (thủ động狗头).

Cuối cùng, [Luyện chuyên đề đệ quy cây nhị phân](https://labuladong.online/algo/intro/binary-tree-practice/) sẽ dẫn bạn từng bước dùng技巧bài này講.

## Trả lời câu hỏi khu bình luận

Về duyệt層序 (và [Khung thuật toán BFS](https://labuladong.online/algo/essential-technique/bfs-framework/) mở rộng từ nó), tôi ở cuối nói thêm mấy câu.

Nếu bạn đủ quen cây nhị phân, có thể nghĩ nhiều cách qua hàm đệ quy ra kết quả duyệt層序, ví dụ cách viết dưới:

```java
class Solution {
    List<List<Integer>> res = new ArrayList<>();

    public List<List<Integer>> levelTraverse(TreeNode root) {
        if (root == null) {
            return res;
        }
        // root xem là tầng 0
        traverse(root, 0);
        return res;
    }

    void traverse(TreeNode root, int depth) {
        if (root == null) {
            return;
        }
        // Vị trí tiền序, xem đã lưu Node tầng depth chưa
        if (res.size() <= depth) {
            // Lần đầu vào tầng depth
            res.add(new LinkedList<>());
        }
        // Vị trí tiền序, ở tầng depth thêm giá trị của Node root
        res.get(depth).add(root.val);
        traverse(root.left, depth + 1);
        traverse(root.right, depth + 1);
    }
}
```

思路này xét từ kết quả确实có thể ra kết quả duyệt層序, nhưng bản chất của nó vẫn là duyệt tiền序của cây nhị phân, hay nói là思路của DFS, chứ không phải duyệt層序, hay nói思路của BFS. Vì解法này là dựa vào đặc điểm thứ tự tự trên xuống dưới, tự trái sang phải của duyệt tiền序ra kết quả đúng.

**Trừu tượng nói,解法này更像「duyệt cột」từ trái sang phải, chứ không phải「duyệt tầng」tự trên xuống dưới**. Nên với场景tính khoảng cách nhỏ nhất,解法này hoàn toàn等同thuật toán DFS, không có优势hiệu năng của thuật toán BFS.

Còn có độc giả ưu tú bình luận思路đệ quy duyệt層序thế này:

```java
class Solution {

    List<List<Integer>> res = new LinkedList<>();

    public List<List<Integer>> levelTraverse(TreeNode root) {
        if (root == null) {
            return res;
        }
        List<TreeNode> nodes = new LinkedList<>();
        nodes.add(root);
        traverse(nodes);
        return res;
    }

    void traverse(List<TreeNode> curLevelNodes) {
        // base case
        if (curLevelNodes.isEmpty()) {
            return;
        }
        // Vị trí tiền序, tính giá trị tầng hiện tại và danh sách Node tầng tiếp theo
        List<Integer> nodeValues = new LinkedList<>();
        List<TreeNode> nextLevelNodes = new LinkedList<>();
        for (TreeNode node : curLevelNodes) {
            nodeValues.add(node.val);
            if (node.left != null) {
                nextLevelNodes.add(node.left);
            }
            if (node.right != null) {
                nextLevelNodes.add(node.right);
            }
        }
        // Vị trí tiền序thêm kết quả, có thể ra duyệt層序tự trên xuống dưới
        res.add(nodeValues);
        traverse(nextLevelNodes);
        // Vị trí hậu序thêm kết quả, có thể ra kết quả duyệt層序tự dưới lên trên
        // res.add(nodeValues);
    }
}
```

Hàm `traverse` này rất giống hàm đệ quy duyệt单链表, thực ra chính là把mỗi tầng của cây nhị phân trừu tượng hiểu thành một Node của单链表để duyệt.

So解法đệ quy trước,解法đệ quy này là「duyệt tầng」tự trên xuống dưới,更gần奥义của BFS, có thể làm cài đặt đệ quy của thuật toán BFS mở rộng思维.
