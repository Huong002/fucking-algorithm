## Thuật toán phát hiện vòng (bản DFS)

Xem trước bài 207 trên LeetCode「Thời khóa biểu」:

<Problem slug="course-schedule" />

```java
// Chữ ký hàm như sau
boolean canFinish(int numCourses, int[][] prerequisites);
```

Đề phải không khó hiểu, khi nào không修xong mọi khóa? Khi tồn tại phụ thuộc vòng.

Thực ra场景này trong đời thực cũng十分thường gặp, ví dụ chúng ta viết code import package cũng là một ví dụ,必須thiết kế hợp lý cấu trúc thư mục code, nếu không sẽ xuất hiện phụ thuộc vòng, trình biên dịch sẽ báo lỗi, nên trình biên dịch thực tế cũng dùng thuật toán类似để判断code của bạn có biên dịch thành công không.

**Thấy vấn đề phụ thuộc, đầu tiên nghĩ tới chính là把vấn đề chuyển thành cấu trúc dữ liệu「đồ thị có hướng」, chỉ cần đồ thị tồn tại vòng,就说明tồn tại phụ thuộc vòng**.

Cụ thể, chúng ta trước hết có thể xem khóa thành Node trong「đồ thị có hướng」,编号Node lần lượt `0, 1, ..., numCourses-1`, xem quan hệ phụ thuộc giữa khóa thành cạnh có hướng giữa Node.

Ví dụ必須học xong khóa `1` mới去học khóa `3`, vậy就có một cạnh có hướng từ Node `1`指向 `3`.

Nên chúng ta có thể dựa vào mảng `prerequisites` nhập của đề sinh một đồ thị类似thế này:

![](https://labuladong.online/algo/images/topological-sort/1.jpeg)

**Nếu phát hiện đồ thị có hướng này tồn tại vòng,就说明giữa khóa tồn tại phụ thuộc vòng,肯定không cách nào học hết; ngược lại, nếu không có vòng, vậy肯定học xong toàn bộ khóa**.

Tốt, vậy muốn giải vấn đề này, trước hết chúng ta要把nhập của đề chuyển thành một đồ thị có hướng, rồi判断đồ thị có tồn tại vòng không.

Chuyển thành đồ thị thế nào? Bài trước [Lưu trữ cấu trúc đồ thị](https://labuladong.online/algo/data-structure-basic/graph-basic/) viết hai dạng lưu đồ thị, ma trận kề và danh sách kề.

Ở đây tôi dùng dạng danh sách kề lưu đồ thị, trước hết có thể viết một hàm dựng đồ thị:

```java
List<Integer>[] buildGraph(int numCourses, int[][] prerequisites) {
    // Tổng cộng numCourses Node trong đồ thị
    List<Integer>[] graph = new LinkedList[numCourses];
    for (int i = 0; i < numCourses; i++) {
        graph[i] = new LinkedList<>();
    }
    for (int[] edge : prerequisites) {
        int from = edge[1], to = edge[0];
        // Thêm một cạnh có hướng từ from指向to
        // Hướng cạnh là quan hệ「被phụ thuộc」, tức học xong khóa from mới học khóa to
        graph[from].add(to);
    }
    return graph;
}
```

Đồ thị dựng ra rồi,判断đồ thị có vòng không thế nào?

Rất đơn giản, chẳng qua muốn考bạn duyệt mọi đường đi trong đồ thị嘛, nếu tôi能duyệt mọi đường đi, vậy đường đi có thành vòng không就dễ tính ra sao?

[Duyệt DFS/BFS cơ bản của đồ thị](https://labuladong.online/algo/data-structure-basic/graph-traverse-basic/) viết dùng thuật toán DFS duyệt mọi đường đi của đồ thị thế nào, quên thì去ôn, dưới đây要用.

Tôi ở đây套thẳng template code DFS duyệt mọi đường đi, dùng một biến `hasCycle` ghi có tồn tại vòng không, **khi lặp duyệt tới Node trong `onPath`,就说明gặp vòng, đặt `hasCycle = true`**.

Dựa vào思路này, xem code bản đầu (sẽ timeout):

```java
class Solution {
    // Ghi Node trong stack đệ quy
    boolean[] onPath;
    // Ghi đồ thị có vòng không
    boolean hasCycle = false;

    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<Integer>[] graph = buildGraph(numCourses, prerequisites);
        
        onPath = new boolean[numCourses];
        
        for (int i = 0; i < numCourses; i++) {
            // Duyệt mọi Node trong đồ thị
            traverse(graph, i);
        }
        // Chỉ cần không có phụ thuộc vòng là có thể hoàn thành mọi khóa
        return !hasCycle;
    }

    // Hàm duyệt đồ thị, duyệt mọi đường đi
    void traverse(List<Integer>[] graph, int s) {
        if (hasCycle) {
            // Nếu đã tìm được vòng, cũng不用duyệt nữa
            return;
        }

        if (onPath[s]) {
            // s đã trên đường đệ quy,说明thành vòng
            hasCycle = true;
            return;
        }
        
        // Vị trí code tiền序
        onPath[s] = true;
        for (int t : graph[s]) {
            traverse(graph, t);
        }
        // Vị trí code hậu序
        onPath[s] = false;
    }

    List<Integer>[] buildGraph(int numCourses, int[][] prerequisites) {
        // Code xem bài trước
    }
}
```

Chú ý đồ thị không phải mọi Node đều相连, nên要用vòng for把mọi Node đều làm起点gọi một lần thuật toán tìm kiếm DFS.

Thực ra解法này đã đúng rồi, vì duyệt mọi đường đi,肯定có thể判定có thành vòng không. Nhưng解法này không qua được mọi test case, sẽ timeout. Vậy nguyên nhân肯定cũng đoán được, **có tính冗余**呗.

冗余tính ở đâu? Tôi举ví dụ bạn就hiểu.

Giả sử giờ bạn lấy Node `2` làm起点duyệt mọi đường đi tới được, cuối cùng phát hiện không có vòng.

Giả sử Node `5` khác có một cạnh指向 `2`, khi bạn lấy `5` làm起点duyệt mọi đường đi tới được,肯定còn đi tới `2`, vậy xin hỏi, lúc này bạn có cần tiếp tục duyệt mọi đường đi tới được của `2` nữa không?

Đáp án là không cần, vì lần đầu bạn không tìm được vòng, vậy lần này cũng không thể tìm được vòng. Hiểu冗余tính trong này chưa? Nếu bạn thấy có反例, có thể tự vẽ, thực tế là không có反例.

Vậy对症下药là được: nếu chúng ta phát hiện một Node trước đó被duyệt qua, có thể bỏ qua thẳng,不用lặp duyệt nữa.

Code tối ưu như sau:

```java
class Solution {
    // Ghi Node trong một stack đệ quy
    boolean[] onPath;
    // Ghi Node có被duyệt qua không
    boolean[] visited;
    // Ghi đồ thị có vòng không
    boolean hasCycle = false;

    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<Integer>[] graph = buildGraph(numCourses, prerequisites);
        
        onPath = new boolean[numCourses];
        visited = new boolean[numCourses];
        
        for (int i = 0; i < numCourses; i++) {
            // Duyệt mọi Node trong đồ thị
            traverse(graph, i);
        }
        // Chỉ cần không có phụ thuộc vòng là có thể hoàn thành mọi khóa
        return !hasCycle;
    }

    // Hàm duyệt đồ thị, duyệt mọi đường đi
    void traverse(List<Integer>[] graph, int s) {
        if (hasCycle) {
            // Nếu đã tìm được vòng, cũng不用duyệt nữa
            return;
        }

        if (onPath[s]) {
            // s đã trên đường đệ quy,说明thành vòng
            hasCycle = true;
            return;
        }
        
        if (visited[s]) {
            //不用lặp duyệt Node đã duyệt qua nữa
            return;
        }

        // Vị trí code tiền序
        visited[s] = true;
        onPath[s] = true;
        for (int t : graph[s]) {
            traverse(graph, t);
        }
        // Vị trí code hậu序
        onPath[s] = false;
    }


    List<Integer>[] buildGraph(int numCourses, int[][] prerequisites) {
        // Code xem bài trước
    }
}
```

Bài này giải xong, cốt lõi chính là判断một đồ thị có hướng có tồn tại vòng không.

Nhưng nếu người ra đề hỏi tiếp, bắt bạn không chỉ判断có tồn tại vòng không, còn要trả về vòng này cụ thể có những Node nào, làm sao?

Bạn có thể nói, index true trong `onPath`, không phải chính là编号Node组成vòng sao?

Không phải, giả sử duyệt bắt đầu từ Node `0`, Node xanh trong hình dưới là đường đệ quy, chúng trong `onPath` đều true, nhưng hiển nhiên Node thành vòng chỉ là một phần trong đó:

![](https://labuladong.online/algo/images/topological-sort/4.jpeg)

Vấn đề này mọi người có thể nghĩ trước,办法肯定có nhiều, tôi chỉ给ra một解法thường dùng.

> [!NOTE]
>解法đơn giản trực tiếp nhất là, trên cơ sở mảng `boolean[] onPath`, chúng ta dùng thêm một stack `Stack<Integer> path`,把thứ tự Node经过trong quá trình duyệt cũng lưu lại.
>
> Ví dụ按thứ tự duyệt xanh ở hình trên, phần tử từ đáy tới đỉnh của `path` chính là `[0,4,5,9,8,7,6]`. Lúc này lại gặp Node `5` một lần, vậy là có thể biết phần `[5,9,8,7,6]` này là vòng.

Tiếp theo, chúng ta来讲một thuật toán đồ thị kinh điển: sắp xếp topo.

## Thuật toán sắp xếp topo (bản DFS)

Xem bài 210 trên LeetCode「Thời khóa biểu II」:

<Problem slug="course-schedule-ii" />

Bài này chính là bản nâng của bài trên, không仅仅bắt bạn判断có thể hoàn thành mọi khóa không, mà tiến thêm bắt bạn trả về một thứ tự học hợp lý, đảm bảo khi bắt đầu học mỗi khóa, khóa前置đều đã học xong.

Chữ ký hàm như sau:

```java
int[] findOrder(int numCourses, int[][] prerequisites);
```

Ở đây tôi nói trước danh từ sắp xếp topo (Topological Sorting), định nghĩa search trên mạng rất toán, ở đây dứt khoát dùng một hình của Baidu Baike để bạn cảm nhận trực quan:

![](https://labuladong.online/algo/images/topological-sort/top.jpg)

**Nói trực quan chính là, bắt bạn把một đồ thị「kéo phẳng」, mà trong đồ thị「kéo phẳng」này, mọi hướng mũi tên đều nhất quán**, ví dụ mọi mũi tên ở hình trên đều hướng右.

Rất hiển nhiên, nếu một đồ thị có hướng tồn tại vòng, không cách nào sắp xếp topo, vì肯定không làm được mọi hướng mũi tên nhất quán; ngược lại, nếu một đồ thị là「đồ thị có hướng không chu trình」, vậy肯定có thể sắp xếp topo.

Nhưng bài này và sắp xếp topo có quan hệ gì?

**Thực ra cũng không khó看出, nếu把khóa trừu tượng thành Node,把quan hệ phụ thuộc giữa khóa trừu tượng thành cạnh có hướng, vậy kết quả sắp xếp topo của đồ thị này chính là thứ tự học**.

Trước hết, chúng ta判断khóa phụ thuộc nhập của đề có thành vòng không, thành vòng thì không cách nào sắp xếp topo, nên chúng ta có thể复用hàm chính của bài trước:

```java
public int[] findOrder(int numCourses, int[][] prerequisites) {
    if (!canFinish(numCourses, prerequisites)) {
        // Không thể hoàn thành mọi khóa
        return new int[]{};
    }
    // ...
}
```

Vậy vấn đề mấu chốt tới rồi, sắp xếp topo thế nào? Có phải lại要秀技巧cao大上gì?

**Thực ra特别đơn giản,把kết quả duyệt hậu序 của cấu trúc đồ thị反转, chính là kết quả sắp xếp topo**.

::: note Có cần反转không?

Có độc giả nhắc, anh ta thấy trên mạng thuật toán sắp xếp topo chính là kết quả duyệt hậu序, không cần反转kết quả duyệt hậu序, tại sao?

Bạn đúng có thể thấy解法như vậy, nguyên nhân là định nghĩa cạnh của anh ta khi dựng đồ thị khác tôi. Đồ thị tôi dựng hướng mũi tên là quan hệ「被phụ thuộc」, ví dụ Node `1`指向 `2`,含义là Node `1`被Node `2` phụ thuộc, tức làm xong `1` mới去làm `2`, vì vậy更符合trực giác của chúng ta.

Nếu bạn ngược lại,把cạnh có hướng định nghĩa là quan hệ「phụ thuộc」, vậy toàn bộ cạnh trong đồ thị反转, là có thể không反转kết quả duyệt hậu序. Cụ thể, chính là把trong code解法của tôi `graph[from].add(to);` đổi thành `graph[to].add(from);` là có thể không反转.

:::

Xem thẳng code解法, trên cơ sở code phát hiện vòng của bài trước thêm logic ghi kết quả duyệt hậu序:

```java
class Solution {
    // Ghi kết quả duyệt hậu序
    List<Integer> postorder = new ArrayList<>();
    // Ghi có tồn tại vòng không
    boolean hasCycle = false;
    boolean[] visited, onPath;

    // Hàm chính
    public int[] findOrder(int numCourses, int[][] prerequisites) {
        List<Integer>[] graph = buildGraph(numCourses, prerequisites);
        visited = new boolean[numCourses];
        onPath = new boolean[numCourses];
        // Duyệt đồ thị
        for (int i = 0; i < numCourses; i++) {
            traverse(graph, i);
        }
        // Đồ thị có vòng không cách nào sắp xếp topo
        if (hasCycle) {
            return new int[]{};
        }
        // Kết quả duyệt hậu序ngược即là kết quả sắp xếp topo
        Collections.reverse(postorder);
        int[] res = new int[numCourses];
        for (int i = 0; i < numCourses; i++) {
            res[i] = postorder.get(i);
        }
        return res;
    }

    // Hàm duyệt đồ thị
    void traverse(List<Integer>[] graph, int s) {
        if (onPath[s]) {
            // Phát hiện vòng
            hasCycle = true;
        }
        if (visited[s] || hasCycle) {
            return;
        }
        // Vị trí duyệt tiền序
        onPath[s] = true;
        visited[s] = true;
        for (int t : graph[s]) {
            traverse(graph, t);
        }
        // Vị trí duyệt hậu序
        postorder.add(s);
        onPath[s] = false;
    }

    // Hàm dựng đồ thị
    List<Integer>[] buildGraph(int numCourses, int[][] prerequisites) {
        // Code xem bài trước
    }
}
```

Code dù nhìn nhiều, nhưng logic phải rất rõ, chỉ cần đồ thị không vòng, vậy chúng ta就gọi hàm `traverse` duyệt DFS đồ thị, ghi kết quả duyệt hậu序, cuối cùng把kết quả duyệt hậu序反转, làm đáp án cuối.

**Vậy tại sao kết quả反转duyệt hậu序 chính là sắp xếp topo**?

Tôi ở đây cũng tránh chứng minh toán, dùng một ví dụ trực quan để giải thích, chúng ta就nói cây nhị phân, đây là khung duyệt cây nhị phân chúng ta nói nhiều lần:

```java
void traverse(TreeNode root) {
    // Vị trí code duyệt tiền序
    traverse(root.left)
    // Vị trí code duyệt trung序
    traverse(root.right)
    // Vị trí code duyệt hậu序
}
```

Duyệt hậu序 của cây nhị phân là khi nào? Duyệt xong cây con trái/phải后mới chạy code vị trí hậu序. Nói cách khác, khi Node của cây con trái/phải đều被cho vào danh sách kết quả后, Node gốc mới被cho vào.

**Đặc điểm này của duyệt hậu序 rất quan trọng, sở dĩ cơ sở của sắp xếp topo là duyệt hậu序, vì một nhiệm vụ必須đợi mọi nhiệm vụ nó phụ thuộc đều hoàn thành后mới bắt đầu thực hiện**.

Bạn把cây nhị phân hiểu thành một đồ thị có hướng, hướng cạnh是由Node cha指向Node con, vậy就是hình dưới:

![](https://labuladong.online/algo/images/topological-sort/2.jpeg)

Với kết quả duyệt hậu序 chuẩn, Node gốc xuất hiện cuối cùng, chỉ cần把kết quả duyệt反lại, chính là kết quả sắp xếp topo:

![](https://labuladong.online/algo/images/topological-sort/3.jpeg)

Tôi biết có độc giả sẽ hỏi, kết quả反转duyệt hậu序, và kết quả duyệt tiền序có quan hệ gì?

Với cây nhị phân bạn nhìn似乎có quan hệ, thực tế hai者không có quan hệ gì. Bạn千万đừng cho rằng kết quả反转duyệt hậu序等同kết quả duyệt tiền序.

区别mấu chốt của nó俩ở [Tư tưởng cây nhị phân (Phần cương lĩnh)](https://labuladong.online/algo/essential-technique/binary-tree-summary/) đã讲, code vị trí hậu序 là đợi cây con trái/phải đều duyệt xong mới chạy, chỉ nó mới thể hiện được quan hệ「phụ thuộc」, thứ tự duyệt khác đều không làm được.






## Thuật toán phát hiện vòng (bản BFS)

Vừa讲dùng thuật toán DFS lợi dụng mảng `onPath`判断có tồn tại vòng không; cũng讲dùng thuật toán DFS lợi dụng duyệt hậu序ngược sắp xếp topo.

Thực ra thuật toán BFS mượn mảng `indegree` ghi「bậc vào」mỗi Node, cũng có thể cài đặt hai thuật toán này. Độc giả không quen thuật toán BFS có thể đọc bài trước [Khung cốt lõi thuật toán BFS](https://labuladong.online/algo/essential-technique/bfs-framework/).

Cái gọi là「bậc ra」và「bậc vào」là khái niệm trong「đồ thị có hướng」, rất trực quan: nếu một Node `x` có `a` cạnh指向Node khác, đồng thời被 `b` cạnh chỉ, thì称bậc ra của Node `x` là `a`, bậc vào là `b`.

Nói trước thuật toán phát hiện vòng, xem thẳng code解法BFS:

```java
class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        // Dựng đồ thị, cạnh có hướng đại diện quan hệ「被phụ thuộc」
        List<Integer>[] graph = buildGraph(numCourses, prerequisites);
        // Dựng mảng bậc vào
        int[] indegree = new int[numCourses];
        for (int[] edge : prerequisites) {
            int from = edge[1], to = edge[0];
            // Bậc vào của Node to加một
            indegree[to]++;
        }

        // Dựa vào bậc vào khởi tạo Node trong hàng đợi
        Queue<Integer> q = new LinkedList<>();
        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) {
                // Node i không có bậc vào, tức không có Node phụ thuộc
                // Có thể làm起点sắp xếp topo,加入hàng đợi
                q.offer(i);
            }
        }

        // Ghi số Node duyệt
        int count = 0;
        // Bắt đầu chạy vòng BFS
        while (!q.isEmpty()) {
            // Pop Node cur, và giảm bậc vào của Node nó指向một
            int cur = q.poll();
            count++;
            for (int next : graph[cur]) {
                indegree[next]--;
                if (indegree[next] == 0) {
                    // Nếu bậc vào thành 0,说明Node next phụ thuộc đều被duyệt
                    q.offer(next);
                }
            }
        }

        // Nếu mọi Node đều被duyệt qua,说明không thành vòng
        return count == numCourses;
    }

    // Hàm dựng đồ thị
    List<Integer>[] buildGraph(int n, int[][] edges) {
        // Xem bài trước
    }
}
```

Tôi tóm tắt思路đoạn thuật toán BFS này trước:

1、Dựng danh sách kề, như trước, hướng cạnh表示quan hệ「被phụ thuộc」.

2、Dựng một mảng `indegree` ghi bậc vào mỗi Node, tức `indegree[i]` ghi bậc vào của Node `i`.

3、Khởi tạo Node trong hàng đợi BFS,装Node bậc vào 0 vào hàng đợi trước.

**4、Bắt đầu chạy vòng BFS,不断pop Node trong hàng đợi, giảm bậc vào của Node kề, và加入Node bậc vào thành 0 vào hàng đợi**.

**5、Nếu cuối cùng mọi Node đều被duyệt qua (`count` bằng số Node),则说明không tồn tại vòng, ngược lại则说明tồn tại vòng**.

![](https://labuladong.online/algo/images/topological-sort/6.jpeg)

![](https://labuladong.online/algo/images/topological-sort/7.jpeg)

## Thuật toán sắp xếp topo (bản BFS)

**Nếu bạn看懂thuật toán phát hiện vòng bản BFS, vậy就rất dễ ra thuật toán sắp xếp topo bản BFS, vì thứ tự duyệt Node chính là kết quả sắp xếp topo**.

Ví dụ ví dụ đầu vừa举, giá trị trong mỗi Node ở hình dưới即thứ tự入队:

![](https://labuladong.online/algo/images/topological-sort/13.jpeg)

Hiển nhiên, thứ tự này chính là một kết quả sắp xếp topo可行.

Nên, chúng ta sửa chút thuật toán phát hiện vòng bản BFS, ghi thứ tự duyệt Node là ra kết quả sắp xếp topo:

```java
class Solution {

    public int[] findOrder(int numCourses, int[][] prerequisites) {
        // Dựng đồ thị, giống thuật toán phát hiện vòng
        List<Integer>[] graph = buildGraph(numCourses, prerequisites);
        // Tính bậc vào, giống thuật toán phát hiện vòng
        int[] indegree = new int[numCourses];
        for (int[] edge : prerequisites) {
            int from = edge[1], to = edge[0];
            indegree[to]++;
        }

        // Dựa vào bậc vào khởi tạo Node trong hàng đợi, giống thuật toán phát hiện vòng
        Queue<Integer> q = new LinkedList<>();
        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) {
                q.offer(i);
            }
        }

        // Ghi kết quả sắp xếp topo
        int[] res = new int[numCourses];
        // Ghi thứ tự duyệt Node (index)
        int count = 0;
        // Bắt đầu chạy thuật toán BFS
        while (!q.isEmpty()) {
            int cur = q.poll();
            // Thứ tự pop Node即là kết quả sắp xếp topo
            res[count] = cur;
            count++;
            for (int next : graph[cur]) {
                indegree[next]--;
                if (indegree[next] == 0) {
                    q.offer(next);
                }
            }
        }

        if (count != numCourses) {
            // Tồn tại vòng, sắp xếp topo không tồn tại
            return new int[]{};
        }
        
        return res;
    }

    // Hàm dựng đồ thị
    List<Integer>[] buildGraph(int n, int[][] edges) {
        // Xem bài trước
    }
}
```

Theo lý, [duyệt đồ thị](https://labuladong.online/algo/data-structure-basic/graph-basic/) đều cần mảng `visited`防止đi回头路, thuật toán BFS ở đây thực ra là qua mảng `indegree` cài đặt tác dụng của mảng `visited`, chỉ Node bậc vào 0 mới入队, nhờ đó đảm bảo không xuất hiện vòng lặp vô hạn.

Tốt rồi, tới đây thuật toán phát hiện vòng, cài đặt BFS của thuật toán sắp xếp topo cũng讲xong, tiếp tục để một bài nghĩ:

Với thuật toán phát hiện vòng của BFS, nếu hỏi bạn Node形成vòng cụ thể là những ai, bạn phải cài đặt thế nào?
