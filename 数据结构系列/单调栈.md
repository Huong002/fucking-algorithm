Stack là cấu trúc dữ liệu rất đơn giản, thứ tự logic vào sau ra trước, phù hợp đặc điểm một số bài toán, ví dụ stack gọi hàm. Ngăn xếp đơn điệu (monotonic stack) thực ra chính là stack, chỉ là lợi dụng một số logic khéo léo, khiến sau mỗi lần phần tử mới入stack, các phần tử trong stack đều giữ有序 (đơn điệu tăng hoặc đơn điệu giảm).

Nghe hơi giống heap? Không phải, ngăn xếp đơn điệu用途không rộng, chỉ xử lý một类bài toán điển hình, ví dụ「phần tử lớn hơn tiếp theo」,「phần tử nhỏ hơn trước đó」v.v. Bài này dùng讲解template thuật toán hàng đợi đơn điệu để giải vấn đề「phần tử lớn hơn tiếp theo」liên quan, và thảo luận chiến lược xử lý「mảng vòng」. Còn các biến thể khác và ví dụ kinh điển, tôi sẽ讲解ở bài tiếp [Biến thể ngăn xếp đơn điệu và bài tập kinh điển](https://labuladong.online/algo/problem-set/monotonic-stack/).

## Template ngăn xếp đơn điệu

Giờ cho bạn một bài thế này: nhập một mảng `nums`, hãy trả về một mảng kết quả等长, trong mảng kết quả index tương ứng lưu phần tử lớn hơn tiếp theo, nếu không có phần tử lớn hơn, lưu -1. Chữ ký hàm như sau:

```java
int[] calculateGreaterElement(int[] nums);
```

Ví dụ, nhập mảng `nums = [2,1,2,4,3]`, bạn trả về mảng `[4,2,4,-1,-1]`. Vì số 2 đầu tiên phía sau số lớn hơn 2 là 4; phía sau 1 số lớn hơn 1 là 2; số 2 thứ hai phía sau số lớn hơn 2 là 4; phía sau 4 không có số lớn hơn 4, điền -1; phía sau 3 không có số lớn hơn 3, điền -1.

解法brute-force của bài này rất dễ nghĩ, là quét phía sau mỗi phần tử, tìm phần tử lớn hơn đầu tiên là được. Nhưng độ phức tạp thời gian của解法brute-force là $O(n^2)$.

Vấn đề này có thể tư duy trừu tượng thế này: tưởng tượng phần tử mảng thành người đứng song song, kích thước phần tử tưởng tượng thành chiều cao. Những người này đối mặt bạn đứng thành một hàng, làm sao求phần tử「2」có phần tử lớn hơn tiếp theo? Rất đơn giản, nếu nhìn được phần tử「2」, vậy người đầu tiên nhìn được phía sau nó chính là phần tử lớn hơn tiếp theo của「2」, vì phần tử nhỏ hơn「2」chiều cao không đủ, đều bị「2」che, người đầu tiên lộ ra chính là đáp án.

![](https://labuladong.online/algo/images/monotonic-stack/1.jpeg)

Tình huống này dễ hiểu đúng không? Mang theo tình huống trừu tượng này, xem code trước.

```java
int[] calculateGreaterElement(int[] nums) {
    int n = nums.length;
    // Mảng存放đáp án
    int[] res = new int[n];
    Stack<Integer> s = new Stack<>(); 
    // Duyệt ngược往stack里放
    for (int i = n - 1; i >= 0; i--) {
        //判定cao thấp
        while (!s.isEmpty() && s.peek() <= nums[i]) {
            // Thấp cút ra, đằng nào cũng bị che。。。
            s.pop();
        }
        // Phần tử lớn hơn phía sau nums[i]
        res[i] = s.isEmpty() ? -1 : s.peek();
        s.push(nums[i]);
    }
    return res;
}
```

Đây chính là template giải quyết vấn đề của hàng đợi đơn điệu. Vòng for phải quét phần tử từ sau ra trước, vì chúng ta mượn cấu trúc của stack,入stack ngược thực ra là出stack正. Vòng while là loại phần tử giữa hai phần tử「cao」vì sự tồn tại của chúng vô nghĩa, phía trước chặn một phần tử「cao hơn」, nên chúng không thể làm phần tử lớn hơn tiếp theo của phần tử vào sau nữa.

Độ phức tạp thời gian của thuật toán này không trực quan, nếu bạn thấy vòng for lồng vòng while, có thể cho rằng độ phức tạp của thuật toán này cũng là $O(n^2)$, nhưng thực ra độ phức tạp của thuật toán này chỉ $O(n)$.

Phân tích độ phức tạp thời gian của nó, phải nhìn tổng thể: tổng cộng `n` phần tử, mỗi phần tử đều被 `push`入stack một lần, mà nhiều nhất bị `pop` một lần, không có thao tác冗余nào. Nên tổng quy mô tính toán tỉ lệ thuận với quy mô phần tử `n`, tức độ phức tạp $O(n)$.

### 496. Phần tử lớn hơn tiếp theo I

Trước hết một biến dạng đơn giản, bài 496 trên LeetCode「Phần tử lớn hơn tiếp theo I」:

<Problem slug="next-greater-element-i" />

Bài này cho bạn nhập hai mảng `nums1` và `nums2`, bắt bạn求phần tử trong `nums1` có phần tử lớn hơn tiếp theo trong `nums2`, chữ ký hàm như sau:

```java
int[] nextGreaterElement(int[] nums1, int[] nums2)
```

Thực ra改code vừa rồi là có thể giải bài này, vì đề nói `nums1` là tập con của `nums2`, vậy chúng ta tính trước phần tử lớn hơn tiếp theo của mỗi phần tử trong `nums2`存vào một map, rồi để phần tử trong `nums1`去tra bảng là được:

```java
class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {
        // Ghi lại phần tử lớn hơn tiếp theo của mỗi phần tử trong nums2
        int[] greater = calculateGreaterElement(nums2);
        // Chuyển thành map: phần tử x -> phần tử lớn nhất tiếp theo của x
        HashMap<Integer, Integer> greaterMap = new HashMap<>();
        for (int i = 0; i < nums2.length; i++) {
            greaterMap.put(nums2[i], greater[i]);
        }
        // nums1 là tập con của nums2, nên dựa vào greaterMap có thể ra kết quả
        int[] res = new int[nums1.length];
        for (int i = 0; i < nums1.length; i++) {
            res[i] = greaterMap.get(nums1[i]);
        }
        return res;
    }

    int[] calculateGreaterElement(int[] nums) {
        // Xem phần trên
    }
}
```

### 739. Nhiệt độ hằng ngày

Xem tiếp bài 739 trên LeetCode「Nhiệt độ hằng ngày」:

Cho bạn một mảng `temperatures`, mảng này存放nhiệt độ thời tiết mấy ngày gần đây, bạn trả về một mảng等长, tính: với mỗi ngày, bạn còn phải đợi ít nhất mấy ngày mới đợi được nhiệt độ ấm hơn; nếu không đợi được ngày đó, điền 0. Chữ ký hàm như sau:

```java
int[] dailyTemperatures(int[] temperatures);
```

Ví dụ cho bạn nhập `temperatures = [73,74,75,71,69,76]`, bạn trả về `[1,1,3,2,1,0]`. Vì ngày đầu 73 độ F, ngày hai 74 độ F, lớn hơn 73, nên với ngày đầu, chỉ cần đợi một ngày là đợi được nhiệt độ ấm hơn, phía sau tương tự.

Vấn đề này bản chất cũng là tìm phần tử lớn hơn tiếp theo, chỉ là giờ không hỏi bạn giá trị phần tử lớn hơn tiếp theo là bao nhiêu, mà hỏi bạn khoảng cách index từ phần tử hiện tại tới phần tử lớn hơn tiếp theo mà thôi.

思路giống nhau, gọi thẳng template thuật toán ngăn xếp đơn điệu, sửa chút là được, lên thẳng code:

```java
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] res = new int[n];
        // Ở đây放index phần tử, chứ không phải phần tử
        Stack<Integer> s = new Stack<>(); 
        // Template ngăn xếp đơn điệu
        for (int i = n - 1; i >= 0; i--) {
            while (!s.isEmpty() && temperatures[s.peek()] <= temperatures[i]) {
                s.pop();
            }
            // Ra khoảng cách index
            res[i] = s.isEmpty() ? 0 : (s.peek() - i); 
            // Đẩy index入stack, chứ không phải phần tử
            s.push(i); 
        }
        return res;
    }
}
```

讲解xong ngăn xếp đơn điệu, dưới đây bắt đầu trọng điểm khác: xử lý「mảng vòng」thế nào.

## Xử lý mảng vòng thế nào

Vẫn là求phần tử lớn hơn tiếp theo, giờ giả sử mảng cho bạn là vòng, xử lý sao? Bài 503 trên LeetCode「Phần tử lớn hơn tiếp theo II」chính là vấn đề này: nhập một「mảng vòng」, hãy tính phần tử lớn hơn tiếp theo của mỗi phần tử trong đó.

Ví dụ nhập `[2,1,2,4,3]`, bạn phải trả về `[4,2,4,-1,4]`, vì có thuộc tính vòng, **phần tử cuối 3绕một vòng后tìm được phần tử 4 lớn hơn mình**.

Nếu bạn xem [Kỹ xảo mảng vòng](https://labuladong.online/algo/data-structure-basic/cycle-array/) ở chương kiến thức cơ bản chắc比较quen, chúng ta thường dùng toán tử %求模 (số dư),来mô phỏng特效vòng:

```java
int[] arr = {1,2,3,4,5};
int n = arr.length, index = 0;
while (true) {
    // Xoay vòng trong mảng vòng
    print(arr[index % n]);
    index++;
}
```

Vấn đề này chắc chắn vẫn要用template解题của ngăn xếp đơn điệu, nhưng khó ở chỗ, ví dụ nhập là `[2,1,2,4,3]`, với phần tử cuối 3, tìm phần tử 4 làm phần tử lớn hơn tiếp theo thế nào.

**Với nhu cầu này,套路thường dùng là nhân đôi độ dài mảng**:

![](https://labuladong.online/algo/images/monotonic-stack/2.jpeg)

Như vậy, phần tử 3 là có thể tìm phần tử 4 làm phần tử lớn hơn tiếp theo, mà các phần tử khác đều có thể被tính đúng.

Có思路, cách cài đặt đơn giản nhất dĩ nhiên có thể dựng mảng độ dài gấp đôi này ra, rồi套template thuật toán. Nhưng, **chúng ta có thể không cần dựng mảng mới, mà lợi dụng kỹ xảo mảng vòng来mô phỏng hiệu quả nhân đôi độ dài mảng**. Xem thẳng code:

```java
class Solution {
    public int[] nextGreaterElements(int[] nums) {
        int n = nums.length;
        int[] res = new int[n];
        Stack<Integer> s = new Stack<>();
        // Nhân đôi độ dài mảng mô phỏng mảng vòng
        for (int i = 2 * n - 1; i >= 0; i--) {
            // Index i要求模, còn lại giống template
            while (!s.isEmpty() && s.peek() <= nums[i % n]) {
                s.pop();
            }
            res[i % n] = s.isEmpty() ? -1 : s.peek();
            s.push(nums[i % n]);
        }
        return res;
    }
}
```
