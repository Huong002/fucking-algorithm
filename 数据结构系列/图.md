### Cấu trúc logic và cài đặt cụ thể của đồ thị

Một đồ thị gồm **Node** và **cạnh** cấu thành, cấu trúc logic như sau:

![](https://labuladong.online/algo/images/图/0.jpg)

**Gì叫「cấu trúc logic」? Tức là để tiện nghiên cứu, chúng ta把đồ thị trừu tượng thành bộ dạng này**.

Dựa vào cấu trúc logic này, chúng ta có thể cho rằng cài đặt mỗi Node như sau:

<!-- muliti_language -->
```java
/* Cấu trúc logic của Node đồ thị */
class Vertex {
    int id;
    Vertex[] neighbors;
}
```

Thấy cài đặt này, bạn có quen không? Nó gần như giống hệt Node cây đa chạc chúng ta nói trước đó:

<!-- muliti_language -->
```java
/* Node cây N chạc cơ bản */
class TreeNode {
    int val;
    TreeNode[] children;
}
```

Cho nên, đồ thị thực không có gì cao深, bản chất chính là cây đa chạc cao cấp hơn mà thôi, thuật toán duyệt DFS/BFS áp dụng cho cây, toàn bộ áp dụng cho đồ thị.

Nhưng, cài đặt trên là「về logic」, thực tế chúng ta hiếm dùng lớp `Vertex` này cài đặt đồ thị, mà dùng **danh sách kề và ma trận kề** thường nói để cài đặt.

Ví dụ vẫn đồ thị vừa rồi:

![](https://labuladong.online/algo/images/图/0.jpg)

Cách lưu danh sách kề và ma trận kề như sau:

![](https://labuladong.online/algo/images/图/2.jpeg)

Danh sách kề rất trực quan, tôi存lân cận mỗi Node `x` vào một danh sách, rồi关联 `x` với danh sách này, như vậy là có thể qua một Node `x` tìm mọi Node kề của nó.

Ma trận kề则là một mảng boolean hai chiều, chúng ta姑且gọi là `matrix`, nếu Node `x` và `y`相连, vậy就把 `matrix[x][y]` đặt thành `true` (ô xanh lá ở hình trên đại diện `true`). Nếu muốn tìm lân cận của Node `x`,去quét một vòng `matrix[x][..]` là được.

Nếu dùng dạng code để表现, danh sách kề và ma trận kề大概长thế này:

<!-- muliti_language -->
```java
// Danh sách kề
// graph[x] lưu mọi Node lân cận của x
List<Integer>[] graph;

// Ma trận kề
// matrix[x][y] ghi x có cạnh指向y không
boolean[][] matrix;
```

**Vậy, tại sao có hai cách lưu đồ thị này?肯定vì chúng各có优劣**.

Với danh sách kề, lợi là tốn ít không gian.

Bạn xem ma trận kề trống nhiều vị trí vậy,肯定cần nhiều không gian lưu hơn.

Nhưng, danh sách kề không判断nhanh hai Node có kề nhau không.

Ví dụ tôi muốn判断Node `1` và Node `3` có kề nhau không, tôi要去trong danh sách lân cận `1` tương ứng ở danh sách kề tìm `3` có tồn tại không. Nhưng với ma trận kề就đơn giản, chỉ cần xem `matrix[1][3]` là biết, hiệu suất cao.

Cho nên, dùng cách nào cài đặt đồ thị,要xem tình huống cụ thể.

::: tip

Trong bài thuật toán常规, dùng danh sách kề sẽ thường xuyên hơn, chủ yếu vì thao tác起来较为đơn giản, nhưng không意味着ma trận kề phải被xem nhẹ. Ma trận là một công cụ toán mạnh, vài tính chất隐晦của đồ thị có thể mượn tính ma trận tinh diệu展现ra. Nhưng bài này không chuẩn bị引入nội dung toán, nên độc giả hứng thú có thể tự tìm học.

:::

Cuối cùng, chúng ta明确thêm khái niệm **bậc** (degree) đặc有trong lý thuyết đồ thị, trong đồ thị vô hướng,「bậc」chính là số cạnh mỗi Node相连.

Vì cạnh của đồ thị có hướng có hướng, nên trong đồ thị có hướng「bậc」mỗi Node被chia thành **bậc vào** (indegree) và **bậc ra** (outdegree), ví dụ hình dưới:

![](https://labuladong.online/algo/images/图/0.jpg)

Trong đó bậc vào của Node `3` là 3 (có ba cạnh指向nó), bậc ra là 1 (nó có 1 cạnh指向Node khác).

Tốt rồi, với cấu trúc dữ liệu「đồ thị」này,看懂những cái trên就绰绰có thừa.

Vậy bạn có thể hỏi, mô hình đồ thị chúng ta nói trên仅仅là「đồ thị có hướng không trọng số」, không phải còn đồ thị có trọng số, đồ thị vô hướng, vân vân...

**Thực ra, những mô hình phức tạp hơn này đều dựa trên đồ thị đơn giản nhất này衍生ra**.

**Đồ thị có hướng có trọng số cài đặt sao**? Rất đơn giản呀:

Nếu là danh sách kề, chúng ta không chỉ lưu mọi Node lân cận của một Node `x` nào đó, còn lưu trọng số từ `x` tới mỗi lân cận, không phải cài đặt đồ thị có hướng có trọng số sao?

Nếu là ma trận kề, `matrix[x][y]` không còn là boolean, mà là một giá trị int, 0表示không相连, giá trị khác表示trọng số, không phải thành đồ thị có hướng có trọng số sao?

Nếu dùng dạng code để表现,大概长thế này:

<!-- muliti_language -->
```java
// Danh sách kề
// graph[x] lưu mọi Node lân cận của x và trọng số tương ứng
List<int[]>[] graph;

// Ma trận kề
// matrix[x][y] ghi trọng số cạnh x指向y, 0表示không kề
int[][] matrix;
```

**Đồ thị vô hướng cài đặt sao**? Cũng rất đơn giản, cái gọi là「vô hướng」, có phải等同「hai chiều」?

![](https://labuladong.online/algo/images/图/3.jpeg)

Nếu nối Node `x` và `y` trong đồ thị vô hướng,把 `matrix[x][y]` và `matrix[y][x]` đều thành `true` không phải được; danh sách kề cũng thao tác类似, thêm `y` trong danh sách lân cận của `x`, đồng thời thêm `x` trong danh sách lân cận của `y`.

Hợp技巧trên lại,就thành đồ thị vô hướng có trọng số...

Tốt rồi, giới thiệu cơ bản về đồ thị tới đây, giờ dù来đồ thị乱七八糟gì, trong lòng bạn phải đều có底.

Dưới đây xem vấn đề mọi cấu trúc dữ liệu đều không逃được: duyệt.

### Duyệt đồ thị

**[Tư duy khung học cấu trúc dữ liệu và thuật toán](https://labuladong.online/algo/essential-technique/abstraction-of-algorithm/) nói, các cấu trúc dữ liệu被phát minh ra chẳng qua để duyệt và truy cập, nên「duyệt」là cơ bản của mọi cấu trúc dữ liệu**.

Đồ thị duyệt sao? Vẫn câu đó, tham khảo cây đa chạc, khung duyệt DFS cây đa chạc như sau:

<!-- muliti_language -->
```java
/* Khung duyệt cây đa chạc */
void traverse(TreeNode root) {
    if (root == null) return;
    // Vị trí tiền序
    for (TreeNode child : root.children) {
        traverse(child);
    }
    // Vị trí hậu序
}
```

Khác biệt lớn nhất của đồ thị và cây đa chạc là, đồ thị có thể chứa vòng, bạn duyệt bắt đầu từ một Node nào của đồ thị, có thể đi một vòng lại về Node này, mà cây không xuất hiện tình huống này, xuất phát từ một Node必然đi tới Node lá, tuyệt không thể về chính nó.

Nên, nếu đồ thị chứa vòng, khung duyệt就要một mảng `visited` phụ trợ:

<!-- muliti_language -->
```java
// Ghi Node被duyệt qua
boolean[] visited;
// Ghi đường đi từ起点tới Node hiện tại
boolean[] onPath;

/* Khung duyệt đồ thị */
void traverse(Graph graph, int s) {
    if (visited[s]) return;
    // Đi qua Node s, đánh dấu đã duyệt
    visited[s] = true;
    // Làm lựa chọn: đánh dấu Node s trên đường đi
    onPath[s] = true;
    for (int neighbor : graph.neighbors(s)) {
        traverse(graph, neighbor);
    }
    // Hủy lựa chọn: Node s rời đường đi
    onPath[s] = false;
}
```

Chú ý khác biệt của mảng `visited` và mảng `onPath`, vì cây nhị phân算là đồ thị đặc biệt, nên dùng quá trình duyệt cây nhị phân để hiểu khác biệt hai mảng này:

![](https://labuladong.online/algo/images/迭代遍历二叉树/1.gif)

**GIF trên mô tả quá trình đệ quy duyệt cây nhị phân, Node被đánh dấu true trong `visited`用màu xám表示, Node被đánh dấu true trong `onPath`用màu xanh表示**,类比game rắn tham ăn, `visited` ghi ô rắn đi qua, mà `onPath`仅仅ghi thân rắn. Trong quá trình duyệt đồ thị, `onPath` dùng判断có thành vòng không,类比cảnh rắn tự cắn mình (thành vòng), giờ bạn hiểu khác biệt hai者rồi chứ.

Nếu bắt bạn xử lý vấn đề liên quan đường đi, biến `onPath` này肯定sẽ被dùng, ví dụ [sắp xếp topo](https://labuladong.online/algo/data-structure/topological-sort/)就有dùng.

Ngoài ra, bạn phải chú ý, thao tác mảng `onPath` này rất giống [套路cốt lõi thuật toán quay lui](https://labuladong.online/algo/essential-technique/backtrack-framework/) làm「làm lựa chọn」và「hủy lựa chọn」, khác ở vị trí:「làm lựa chọn」và「hủy lựa chọn」của thuật toán quay lui trong vòng for, mà thao tác với mảng `onPath` ngoài vòng for.

Tại sao có khác biệt này? Đây chính là khác biệt của thuật toán quay lui và thuật toán DFS講trong [Đông ca dẫn bạn刷cây nhị phân (Phần cương lĩnh)](https://labuladong.online/algo/essential-technique/binary-tree-summary/): thuật toán quay lui quan tâm không phải Node, mà là cành cây. Nếu không nhớ,强烈khuyên đọc lại bài trước.

Với thuật toán quay lui, chúng ta cần làm lựa chọn và hủy lựa chọn trên「cành cây」:

![](https://labuladong.online/algo/images/backtracking/5.jpg)

Khác biệt của chúng có thể phản ánh vào code thế này:

<!-- muliti_language -->
```java
// Thuật toán DFS, điểm quan tâm ở Node
void traverse(TreeNode root) {
    if (root == null) return;
    printf("Vào Node %s", root);
    for (TreeNode child : root.children) {
        traverse(child);
    }
    printf("Rời Node %s", root);
}

// Thuật toán quay lui, điểm quan tâm ở cành cây
void backtrack(TreeNode root) {
    if (root == null) return;
    for (TreeNode child : root.children) {
        // Làm lựa chọn
        printf("Từ %s tới %s", root, child);
        backtrack(child);
        // Hủy lựa chọn
        printf("Từ %s tới %s", child, root);
    }
}
```

Nếu chạy đoạn code này, bạn sẽ phát hiện Node gốc bị漏:

<!-- muliti_language -->
```java
void traverse(TreeNode root) {
    if (root == null) return;
    for (TreeNode child : root.children) {
        printf("Vào Node %s", child);
        traverse(child);
        printf("Rời Node %s", child);
    }
}
```

Nên với duyệt「đồ thị」ở đây, chúng ta phải dùng thuật toán DFS, tức把thao tác `onPath`放到ngoài vòng for, nếu không sẽ漏ghi duyệt điểm khởi đầu.

Nói nhiều mảng `onPath` vậy, nói tiếp mảng `visited`, mục đích của nó rất rõ, vì đồ thị có thể chứa vòng, mảng `visited` chính là防止đệ quy lặp duyệt cùng một Node进入vòng lặp vô hạn.

Dĩ nhiên, nếu đề nói với bạn đồ thị không chứa vòng, có thể省hết mảng `visited`,基本chính là duyệt cây đa chạc.

### Thực hành bài tập

Dưới đây chúng ta xem bài 797 trên LeetCode「Mọi đường đi có thể」, chữ ký hàm như sau:

```java
List<List<Integer>> allPathsSourceTarget(int[][] graph);
```

Đề nhập một **đồ thị có hướng không chu trình**, đồ thị này chứa `n` Node, đánh số `0, 1, 2,..., n - 1`, hãy tính mọi đường đi từ Node `0` tới Node `n - 1`.

`graph` nhập này thực ra chính là đồ thị biểu diễn「danh sách kề」, `graph[i]` lưu mọi Node lân cận của Node `i`.

Ví dụ nhập `graph = [[1,2],[3],[3],[]]`,就đại diện đồ thị dưới:

![](https://labuladong.online/algo/images/图/1.jpg)

Thuật toán phải trả về `[[0,1,3],[0,2,3]]`, tức mọi đường đi từ `0` tới `3`.

**解法rất đơn giản, lấy `0` làm起点duyệt đồ thị, đồng thời ghi đường đi duyệt qua, khi duyệt tới终点thì ghi đường đi lại là được**.

Vì đồ thị nhập là không vòng, chúng ta就不需要mảng `visited` phụ trợ,套thẳng khung duyệt đồ thị:

<!-- muliti_language -->
```java
class Solution {
    // Ghi mọi đường đi
    List<List<Integer>> res = new LinkedList<>();
        
    public List<List<Integer>> allPathsSourceTarget(int[][] graph) {
        //维护đường đi经过trong quá trình đệ quy
        LinkedList<Integer> path = new LinkedList<>();
        traverse(graph, 0, path);
        return res;
    }

    /* Khung duyệt đồ thị */
    void traverse(int[][] graph, int s, LinkedList<Integer> path) {
        // Thêm Node s vào đường đi
        path.addLast(s);

        int n = graph.length;
        if (s == n - 1) {
            // Tới终点
            res.add(new LinkedList<>(path));
            // Có thể return thẳng ở đây, nhưng要removeLast维护đúng path
            // path.removeLast();
            // return;
            // Không return cũng được, vì đồ thị không chứa vòng, không xuất hiện đệ quy vô hạn
        }

        // Đệ quy mỗi Node kề
        for (int v : graph[s]) {
            traverse(graph, v, path);
        }
        
        //移Node s khỏi đường đi
        path.removeLast();
    }
}
```

Bài này giải vậy xong, chú ý đặc tính ngôn ngữ Java, vì tham số hàm Java truyền là引用đối tượng, nên khi thêm `path` vào `res` cần copy một danh sách mới, nếu không cuối cùng danh sách trong `res` đều rỗng.

Cuối cùng tóm tắt, cách lưu đồ thị chủ yếu có danh sách kề và ma trận kề, dù đồ thị花里胡哨gì, đều có thể dùng hai cách này lưu.

Trong笔试, thuật toán thi nhiều nhất là duyệt đồ thị, rất类似với khung duyệt cây đa chạc.

Dĩ nhiên, đồ thị còn nhiều thuật toán thú vị khác, ví dụ [判定đồ thị hai phần](https://labuladong.online/algo/data-structure/bipartite-graph/), [phát hiện vòng và sắp xếp topo](https://labuladong.online/algo/data-structure/topological-sort/) (kiểm tra引用vòng của trình biên dịch就是thuật toán类似), [cây khung nhỏ nhất](https://labuladong.online/algo/data-structure/kruskal/), [thuật toán đường ngắn nhất Dijkstra](https://labuladong.online/algo/data-structure/dijkstra/) vân vân, độc giả hứng thú có thể xem, bài này tới đây thôi.
