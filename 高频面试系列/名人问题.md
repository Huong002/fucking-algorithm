Hôm nay bàn bài kinh điển 「vấn đề名人」:

Cho bạn quan hệ xã hội của `n` người (bạn biết hai người tùy ý có quen nhau không), rồi hãy bạn tìm 「名人」 trong những người này.

Cái gọi 「名人」 có hai điều kiện:

1, Mọi người khác đều quen 「名人」.

2, 「名人」 không quen bất kỳ ai khác.

Đây là một bài toán thuật toán liên quan图, quan hệ xã hội嘛,本质上 là trừu tượng thành một图.

Nếu coi mỗi người là node trong图, quan hệ 「quen」 coi là cạnh có hướng giữa các node, vậy名人 chính là một node đặc殊 trong图 này:

![](https://labuladong.online/algo/images/celebrity/1.jpeg)

**Node này không có một cạnh có hướng nào trỏ tới node khác; mà mọi node khác đều có một cạnh trỏ tới node này**.

Hay nói chuyên nghiệp một chút, bậc ra của node名人 bằng 0, bậc vào `n - 1`.

Vậy, quan hệ xã hội của `n` người này biểu thị thế nào?

Bài trước [cơ bản thuật toán图论](https://labuladong.online/algo/data-structure-basic/graph-basic/) nói,图 có hai dạng lưu, một là danh sách kề, một là ma trận kề,优势 chủ yếu của danh sách kề là tiết kiệm không gian lưu;优势 chủ yếu của ma trận kề là có thể nhanh判断 hai node có kề nhau không.

Với vấn đề名人,显然会 hay cần判断 hai người có quen nhau không, chính là hai node có kề nhau không, nên ta có thể dùng ma trận kề để biểu thị quan hệ xã hội người với người.

Vậy,把 vấn đề名流 mô tả thành dạng thuật toán chính là thế này:

Cho bạn input một mảng hai chiều cỡ `n x n` (ma trận kề) `graph` biểu thị một图 có `n` node, mỗi người là một node trong图, đánh số `0` tới `n - 1`.

Nếu `graph[i][j] == 1` đại diện người thứ `i` quen người thứ `j`, nếu `graph[i][j] == 0` đại diện người thứ `i` không quen người thứ `j`.

Có图 này biểu thị quan hệ người với người, hãy bạn tính, trong `n` người này, có tồn tại 「名人」 không?

Nếu tồn tại, thuật toán trả về số hiệu名人 này, nếu không tồn tại, thuật toán trả về -1.

Chữ ký hàm như sau:

```java
int findCelebrity(int[][] graph);
```

Ví dụ ma trận kề input长这样:

![](https://labuladong.online/algo/images/celebrity/2.jpeg)

Vậy thuật toán nên trả về 2.

LeetCode 277 「tìm名人」 chính là vấn đề kinh điển này, nhưng并不是把 ma trận kề truyền thẳng bạn, mà chỉ nói bạn tổng số người `n`, đồng thời cung cấp một API `knows` để查 quan hệ xã hội người với người:

```java
// 可以直接调用，能够返回 i 是否认识 j -> Có thể gọi thẳng, trả về i có quen j không
boolean knows(int i, int j);

// 请你实现：返回「名人」的编号 -> Hãy bạn implement: trả về số hiệu 「名人」
int findCelebrity(int n) {
    // todo
}
```

很明显, API `knows`本质上 vẫn đang truy cập ma trận kề. Để đơn giản, sau ta就按 dạng đề LeetCode探讨 vấn đề kinh điển này.

##解法暴力

Ta vỗ đầu là viết ra một thuật toán đơn giản thô bạo:

```java
class Solution extends Relation {
    public int findCelebrity(int n) {
        for (int cand = 0; cand < n; cand++) {
            int other;
            for (other = 0; other < n; other++) {
                if (cand == other) continue;
                // 保证其他人都认识 cand，且 cand 不认识任何其他人 -> Đảm bảo người khác đều quen cand, mà cand không quen ai khác
                // 否则 cand 就不可能是名人 -> Nếu không cand就不可能是名人
                if (knows(cand, other) || !knows(other, cand)) {
                    break;
                }
            }
            if (other == n) {
                // 找到名人 -> Tìm thấy名人
                return cand;
            }
        }
        // 没有一个人符合名人特性 -> Không ai符合特性名人
        return -1;
    }
}
```

`cand` là viết tắt候选人 (candidate), thuật toán暴力 của ta chính là穷举 từ đầu, coi mỗi người là候选人,判断 có符合 điều kiện 「名人」 không.

Vừa cũng nói, hàm `knows`底层 chính là đang truy cập một ma trận kề hai chiều, một lần gọi độ phức tạp thời gian O(1), nên解法暴力 tổng độ phức tạp thời gian xấu nhất O(N^2).

Vậy, có cách cao minh khác tối ưu độ phức tạp thời gian không? Thực ra có không gian tối ưu, bạn nghĩ xem, chỗ tốn thời gian nhất của ta giờ ở đâu?

Với mỗi候选人 `cand`, ta đều phải dùng một vòng for trong去判断 `cand` này到底符不符合 điều kiện 「名人」.

Vòng for trong này trông就蠢, dù判断 một người 「là名人」必须 dùng một vòng for, nhưng判断 một người 「không phải名人」就不用麻烦 vậy.

**Vì định nghĩa 「名人」 đảm bảo tính duy nhất 「名人」, nên ta có thể lợi dụng phép loại trừ, trước loại những người显然 không phải 「名人」, từ đó tránh lồng vòng for,降低 độ phức tạp thời gian**.






##解法 tối ưu

Tôi lặp lại một lần định nghĩa cái gọi 「名人」:

1, Mọi người khác đều quen名人.

2,名人 không quen bất kỳ ai khác.

Định nghĩa này就 rất thú vị, nó đảm bảo trong đám đông nhiều nhất một名人.

Rất dễ hiểu, nếu có hai người đồng thời là名人, vậy hai định nghĩa này就自相矛盾.

**Nói cách khác, chỉ cần quan sát quan hệ hai候选人 tùy ý, tôi nhất định能 xác định một người trong đó không phải名人, loại nó**.

Còn候选人 kia có phải名人 không, chỉ看 quan hệ hai người肯定 không xác định được, nhưng điều này không quan trọng, quan trọng là loại được một候选人必然 không phải名人, thu hẹp vòng vây.

Đây là cốt lõi tối ưu, cũng比较 khó hiểu, nên ta trước nói vì sao quan sát quan hệ hai候选人 tùy ý,就 loại được một.

Bạn nghĩ xem, quan hệ giữa hai người có thể thế nào?

无非 bốn loại: bạn quen tôi tôi không quen bạn, tôi quen bạn bạn không quen tôi,咱俩 quen nhau,咱俩 không quen nhau.

Nếu比 người làm node, cạnh có hướng đỏ biểu thị không quen, cạnh có hướng xanh biểu thị quen, vậy quan hệ hai người无非 bốn trường hợp sau:

![](https://labuladong.online/algo/images/celebrity/3.jpeg)

Không ngại coi số hiệu hai người này lần lượt là `cand` và `other`, rồi ta逐一 phân tích mỗi trường hợp, xem loại một người sao.

Với trường hợp một, `cand` quen `other`, nên `cand`肯定 không phải名人, loại. Vì名人 không thể quen người khác.

Với trường hợp hai, `other` quen `cand`, nên `other`肯定 không phải名人, loại.

Với trường hợp ba, hai người quen nhau,肯定 đều không phải名人, có thể tùy loại một.

Với trường hợp bốn, hai người không quen nhau,肯定 đều không phải名人, có thể tùy loại một. Vì名人 hẳn被 mọi người khác quen.

Tóm lại, chỉ cần quan sát quan hệ tùy ý hai người,就 ít nhất能 xác định một người không phải名人,判断 tình huống trên có thể dùng code sau biểu thị:

```java
if (knows(cand, other) || !knows(other, cand)) {
    // cand 不可能是名人 -> cand không thể là名人
} else {
    // other 不可能是名人 -> other không thể là名人
}
```

Nếu hiểu được đặc điểm này, vậy viết ra解法 tối ưu就 đơn giản.

**Ta có thể不断 từ候选人 chọn hai ra, rồi loại một, tới cuối chỉ còn một候选人, lúc này再 dùng một vòng for判断候选人 này có phải 「名人」 hàng thật không**.

思路 này code đầy đủ như sau:

```java
class Solution extends Relation {
    public int findCelebrity(int n) {
        if (n == 1) return 0;
        // 将所有候选人装进队列 -> Bỏ mọi候选人 vào hàng đợi
        LinkedList<Integer> q = new LinkedList<>();
        for (int i = 0; i < n; i++) {
            q.addLast(i);
        }
        // 一直排除，直到只剩下一个候选人停止循环 -> Loại mãi, tới chỉ còn một候选人 dừng vòng
        while (q.size() >= 2) {
            // 每次取出两个候选人，排除一个 -> Mỗi lần lấy hai候选人, loại một
            int cand = q.removeFirst();
            int other = q.removeFirst();
            if (knows(cand, other) || !knows(other, cand)) {
                // cand 不可能是名人，排除，让 other 归队 -> cand không thể là名人, loại, để other về đội
                q.addFirst(other);
            } else {
                // other 不可能是名人，排除，让 cand 归队 -> other không thể là名人, loại, để cand về đội
                q.addFirst(cand);
            }
        }

        // 现在排除得只剩一个候选人，判断他是否真的是名人 -> Giờ loại chỉ còn một候选人,判断 hắn có thật là名人 không
        int cand = q.removeFirst();
        for (int other = 0; other < n; other++) {
            if (other == cand) {
                continue;
            }
            // 保证其他人都认识 cand，且 cand 不认识任何其他人 -> Đảm bảo người khác đều quen cand, mà cand không quen ai khác
            if (!knows(other, cand) || knows(cand, other)) {
                return -1;
            }
        }
        // cand 是名人 -> cand là名人
        return cand;
    }
}
```

Thuật toán này tránh lồng vòng for, độ phức tạp thời gian xuống O(N), nhưng引入 một hàng đợi để lưu tập候选人, dùng độ phức tạp không gian O(N).

> [!NOTE]
> Tác dụng `LinkedList` chỉ là đóng vai container装候选人, mỗi lần tìm hai ra so và loại, còn至于 cụ thể tìm hai nào, đều無所謂, nghĩa là thứ tự候选人 về đội無所謂, ta dùng `addFirst` chỉ tiện tối ưu sau, bạn完全 có thể dùng `addLast`, kết quả đều giống.

Có thể tối ưu thêm, 把 độ phức tạp không gian cũng tối ưu掉?

##解法 cuối

Nếu bạn hiểu解法 tối ưu trên,其实 có thể không cần không gian phụ giải vấn đề này, code như sau:

```java
class Solution extends Relation {
    public int findCelebrity(int n) {
        int cand = 0;
        for (int other = 1; other < n; other++) {
            if (!knows(other, cand) || knows(cand, other)) {
                // cand 不可能是名人，排除 -> cand không thể là名人, loại
                // 假设 other 是名人 -> Giả sử other là名人
                cand = other;
            } else {
                // other 不可能是名人，排除 -> other không thể là名人, loại
                // 什么都不用做，继续假设 cand 是名人 -> Không cần làm gì, tiếp giả sử cand là名人
            }
        }

        // 现在的 cand 是排除的最后结果，但不能保证一定是名人 -> cand giờ là kết quả cuối loại, nhưng không đảm bảo nhất định là名人
        for (int other = 0; other < n; other++) {
            if (cand == other) continue;
            // 需要保证其他人都认识 cand，且 cand 不认识任何其他人 -> Cần đảm bảo người khác đều quen cand, mà cand không quen ai khác
            if (!knows(other, cand) || knows(cand, other)) {
                return -1;
            }
        }

        return cand;
    }
}
```

解法 trước của ta dùng `LinkedList` đóng vai hàng đợi, để lưu tập候选人, còn解法 tối ưu này lợi dụng交替 biến `other` và `cand`, mô phỏng quá trình thao tác hàng đợi trước của ta, tránh dùng không gian lưu phụ.

Giờ,解法 vấn đề名人 độ phức tạp thời gian O(N), không gian O(1), đã là解法 tối ưu.
