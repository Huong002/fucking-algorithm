Trước phỏng vấn, bị hỏi một bài thuật toán rất kinh điển mà rất thực dụng: bài toán sắp xếp phòng họp.

Bài tương tự trên LeetCode là đề会员, bạn có thể không làm được, nhưng với loại đề thuật toán kinh điển này, nắm思路 vẫn cần.

Nói trước đề, LeetCode 253 「Phòng họp II」:

Cho bạn input vài khoảng dạng `[begin, end]`, đại diện thời gian bắt đầu và kết thúc vài cuộc họp, hãy tính ít nhất cần xin bao nhiêu phòng họp.

Chữ ký hàm như sau:

```java
// 返回需要申请的会议室数量 -> Trả về số phòng họp cần xin
int minMeetingRooms(int[][] meetings);
```

Ví dụ cho bạn input `meetings = [[0,30],[5,10],[15,20]]`, thuật toán nên trả về 2, vì hai cuộc họp sau xung đột thời gian với cuộc đầu, ít nhất xin hai phòng mới để mọi cuộc họp suôn sẻ.

Nếu thời gian giữa các cuộc họp重叠, thì得 xin thêm phòng để họp, muốn求 ít nhất cần bao nhiêu phòng, chính là bắt bạn tính cùng thời điểm nhiều nhất có bao nhiêu cuộc họp đồng thời.

Nói cách khác, **nếu coi thời gian bắt đầu mỗi cuộc họp là một đoạn khoảng, thì đề chính là bắt bạn求 nhiều nhất có mấy khoảng重叠**, chỉ vậy thôi.

Ta trước cũng học thuật toán liên quan khoảng, nếu bạn có ấn tượng với [技巧 mảng hiệu](https://labuladong.online/algo/data-structure/diff-array/), hẳn đầu tiên nghĩ dùng技巧 đó giải bài này.

Bài này相当于是 nói, cho bạn một mảng vốn toàn 0, rồi cho bạn vài khoảng, bắt bạn cộng 1 mọi phần tử trong mỗi khoảng, hỏi bạn cuối cùng giá trị lớn nhất trong mảng là bao nhiêu. Đây chính là cảnh thực dụng kinh điển của mảng hiệu đúng không,套 thẳng class `Difference` bài trước cho là giải được.

Nhưng技巧 mảng hiệu có một vấn đề, chính là bạn必须把 mảng khởi đầu toàn 0 đó dựng ra. Vì ta dùng chỉ số mảng biểu thị thời gian, nên độ dài mảng này取决 vào giá trị lớn nhất của khoảng thời gian.

Ví dụ input `meetings = [[0,30],[5,10],[15,20]]`, vậy bạn得 dựng một mảng dài 30. Vậy nếu input `meetings = [[0,30],[5,10],[10^8,10^9]]`, thì bạn得 dựng một mảng dài 10^9, điều này显然 có vấn đề. Nhưng đề này cho quy mô dữ liệu取值 thời gian nhiều nhất 10^6, không算 đặc biệt lớn, dùng cách mảng hiệu hẳn qua được.

Nhưng bài này dạy bạn thêm một技巧 xử lý khoảng, không cần dựng mảng lớn vậy, cũng巧 giải được bài này.






## Mở rộng đề

Ta trước viết nhiều bài liên quan调度 khoảng, ở đây tiện giúp mọi người梳理思路 loại vấn đề này:

**Cảnh một**, giả sử giờ chỉ có một phòng họp, còn vài cuộc họp, bạn làm sao xếp càng nhiều cuộc họp vào phòng này càng tốt?

Vấn đề này cần将 các cuộc họp (khoảng) này排序 theo thời gian kết thúc (đầu phải), rồi xử lý, xem chi tiết bài trước [thuật toán tham lam quản thời gian](https://labuladong.online/algo/frequency-interview/interval-scheduling/).

**Cảnh hai**, cho bạn vài đoạn video ngắn, và một đoạn video dài, hãy bạn từ đoạn ngắn挑 càng ít càng tốt vài đoạn,拼接 ra đoạn dài này.

Vấn đề này cần将 các đoạn video (khoảng) này排序 theo thời gian bắt đầu (đầu trái), rồi xử lý, xem chi tiết bài trước [cắt video ra một thuật toán tham lam](https://labuladong.online/algo/frequency-interview/cut-video/).

**Cảnh ba**, cho bạn vài khoảng, trong đó có thể vài khoảng比较 ngắn, bị khoảng khác bao phủ完全, hãy bạn xóa các khoảng bị bao phủ này.

Vấn đề này cần将 các khoảng này排序 theo đầu trái, rồi就能 tìm và xóa những khoảng bị bao phủ完全, xem chi tiết bài trước [xóa khoảng bao phủ](https://labuladong.online/algo/practice-in-action/interval-problem-summary/).

**Cảnh bốn**, cho bạn vài khoảng, hãy bạn gộp mọi khoảng có phần重叠.

Vấn đề này cần将 các khoảng này排序 theo đầu trái, tiện tìm ra khoảng tồn tại重叠, xem chi tiết bài trước [gộp khoảng重叠](https://labuladong.online/algo/practice-in-action/interval-problem-summary/).

**Cảnh năm**, có hai phòng ban đồng thời đặt vài đoạn thời gian của cùng một phòng họp, hãy bạn tính đoạn xung đột của phòng họp.

Vấn đề này chính là cho bạn hai list khoảng, hãy bạn tìm交集 hai nhóm khoảng này, điều này cần bạn将 các khoảng này排序 theo đầu trái, xem chi tiết bài trước [vấn đề交集 khoảng](https://labuladong.online/algo/practice-in-action/interval-problem-summary/).

**Cảnh sáu**, giả sử giờ chỉ có một phòng họp, còn vài cuộc họp, sắp xếp họp sao để thời gian nhàn rỗi của phòng này ít nhất?

Vấn đề này cần động não, nói trắng đây chính là một biến dạng bài toán ba lô 0-1:

Phòng họp có thể coi là một ba lô, mỗi cuộc họp có thể coi là một vật phẩm, giá trị vật phẩm chính là时长 cuộc họp, hỏi bạn chọn vật phẩm (cuộc họp) thế nào mới tối đa hóa giá trị (thời gian dùng phòng) trong ba lô?

Đương nhiên, ở đây约束 ba lô không phải một trọng lượng lớn nhất, mà là các vật phẩm (cuộc họp) không thể xung đột nhau. Sắp các cuộc họp theo thời gian kết thúc, rồi tham khảo思路 bài trước [chi tiết bài toán ba lô 0-1](https://labuladong.online/algo/dynamic-programming/knapsack1/) và TreeMap là giải được.

LeetCode 1235 「lập kế hoạch làm兼职」 chính là đề tương tự, tôi ở思路 plugin cho解答 chi tiết, bạn có thể cài [plugin Chrome](https://labuladong.online/algo/intro/chrome/) của tôi để xem, ở đây tôi就不 tốn篇幅.

**Cảnh bảy**, chính là cảnh bài này muốn讲, cho bạn vài cuộc họp, để bạn tối thiểu hóa số phòng họp xin.

Rồi, ví dụ nhiều vậy, xem vấn đề hôm nay giải sao.






## Phân tích đề

Lặp lại本质 đề:

**Cho bạn input vài khoảng thời gian, để bạn tính cùng thời điểm 「nhiều nhất」 có mấy khoảng重叠**.

Điểm mấu chốt đề在于, cho bạn thời điểm tùy ý, bạn có thể nói ra thời điểm này có mấy cuộc họp không?

Nếu làm được, vậy tôi duyệt mọi thời điểm, tìm giá trị lớn nhất, chính là số phòng họp cần xin.

Có cấu trúc dữ liệu hay thuật toán nào, cho tôi input vài khoảng, tôi能 biết mỗi vị trí có bao nhiêu khoảng重叠?

Độc giả cũ肯定 liên tưởng tới một技巧 thuật toán trước nói: [技巧 mảng hiệu](https://labuladong.online/algo/data-structure/diff-array/).

Tưởng tượng trục thời gian thành một mảng giá trị khởi đầu 0, mỗi khoảng thời gian `[i, j]`就相当 một mảng con, khoảng thời gian này có một cuộc họp, vậy tôi就把 mọi phần tử mảng con này cộng một.

Cuối, mỗi thời điểm có mấy cuộc họp tôi chẳng phải biết sao? Tôi duyệt cả mảng, chẳng phải biết ít nhất cần mấy phòng sao?

Lấy ví dụ, nếu input `meetings = [[0,30],[5,10],[15,20]]`, vậy ta就给 mảng中 `[0,30],[5,10],[15,20]` mấy khoảng chỉ số này lần lượt cộng một, cuối duyệt mảng,求 giá trị lớn nhất là được.

Còn nhớ không,技巧 mảng hiệu có thể trong thời gian O(1) cộng trừ phần tử cả khoảng, nên có thể拿来 giải bài này.

Nhưng, hiệu suất解法 này không算 cao, nên tôi ở đây không chuẩn bị viết cụ thể解法 mảng hiệu, tham照 nguyên lý [技巧 mảng hiệu](https://labuladong.online/algo/data-structure/diff-array/), bạn hứng thú có thể tự thử implement.






**靠思路 mảng hiệu, ta có thể推 ra một解法 hiệu quả hơn,优雅 hơn**.

Ta trước投影 các khoảng thời gian cuộc họp này:

![](https://labuladong.online/algo/images/arrange-room/1.jpeg)

Điểm đỏ đại diện thời điểm bắt đầu mỗi cuộc họp, điểm xanh đại diện thời điểm kết thúc mỗi cuộc họp.

Giờ假想 có một đường帶计数器, quét trên trục thời gian từ trái sang phải, mỗi gặp điểm đỏ,计数器 `count` cộng một, mỗi gặp điểm xanh,计数器 `count` trừ một:

![](https://labuladong.online/algo/images/arrange-room/2.jpeg)

**Như vậy, mỗi thời điểm có bao nhiêu cuộc họp đồng thời, chính là giá trị计数器 `count`, giá trị lớn nhất của `count`, chính là số phòng họp cần xin**.

Độc giả quen技巧 mảng hiệu一眼 là thấy, quét đường này其实 chính là quá trình duyệt mảng hiệu, nên ta nói đây là解法衍生 từ技巧 mảng hiệu.

## Implement code

Vậy, viết code sao implement quá trình quét này?

Trước,投影 khoảng,就相当排序 riêng起点 và终点 mỗi khoảng:

![](https://labuladong.online/algo/images/arrange-room/3.jpeg)

```java
int minMeetingRooms(int[][] meetings) {
    int n = meetings.length;
    int[] begin = new int[n];
    int[] end = new int[n];
    // 把左端点和右端点单独拿出来 -> Lấy riêng đầu trái và đầu phải ra
    for(int i = 0; i < n; i++) {
        begin[i] = meetings[i][0];
        end[i] = meetings[i][1];
    }
    // 排序后就是图中的红点 -> Sắp xong chính là điểm đỏ trong图
    Arrays.sort(begin);
    // 排序后就是图中的绿点 -> Sắp xong chính là điểm xanh trong图
    Arrays.sort(end);

    // ...
}
```

Rồi就 đơn giản, đường quét tiến từ trái sang phải, gặp điểm đỏ就 cộng một计数器, gặp điểm xanh就 trừ một计数器, giá trị lớn nhất của计数器 `count` chính là đáp án:

```java
class Solution {
    public int minMeetingRooms(int[][] meetings) {
        int n = meetings.length;
        int[] begin = new int[n];
        int[] end = new int[n];
        for(int i = 0; i < n; i++) {
            begin[i] = meetings[i][0];
            end[i] = meetings[i][1];
        }
        Arrays.sort(begin);
        Arrays.sort(end);

        // 扫描过程中的计数器 -> Bộ đếm trong quá trình quét
        int count = 0;
        // 双指针技巧 ->技巧 hai con trỏ
        int res = 0, i = 0, j = 0;
        while (i < n && j < n) {
            if (begin[i] < end[j]) {
                // 扫描到一个红点 -> Quét tới một điểm đỏ
                count++;
                i++;
            } else {
                // 扫描到一个绿点 -> Quét tới một điểm xanh
                count--;
                j++;
            }
            // 记录扫描过程中的最大值 -> Ghi giá trị lớn nhất trong quá trình quét
            res = Math.max(res, count);
        }
        
        return res;
    }
}
```

Ở đây dùng [技巧 hai con trỏ](https://labuladong.online/algo/essential-technique/array-two-pointers-summary/), theo vị trí tương đối `i, j` mô phỏng quá trình đường quét tiến.

Tới đây, bài này就 làm xong. Đương nhiên, đề này cũng có thể biến dạng, ví dụ cho bạn vài cuộc họp, hỏi bạn `k` phòng họp có đủ không,其实 bạn套 code解法 bài này, cũng có thể rất轻松 giải.
