Cuối cùng, sau khi kiểm tra `logN` lần, bảo vệ thành công tìm được quyển gây báo động, lộ nụ cười đắc ý và嘲讽. Thế là A Đông cõng số sách còn lại đi.

Từ đó, thư viện mất `N - 1` quyển sách (mặt chó thủ công).

Tìm kiếm nhị phân并不 đơn giản, đại lão Knuth (vị phát minh thuật toán KMP)都 nói tìm kiếm nhị phân: **思路 rất đơn giản, chi tiết là ma quỷ**. Nhiều người thích拿 bug tràn số nguyên nói事, nhưng hố thật sự của tìm kiếm nhị phân căn bản就不是 vấn đề chi tiết đó, mà nằm ở rốt cuộc要 cho `mid` cộng một hay trừ một, trong while rốt cuộc dùng `<=` hay `<`.

Nếu bạn không hiểu đúng những chi tiết này, viết nhị phân肯定就是 lập trình玄学, có bug không chỉ能靠 bồ tát phù hộ, ai viết ai biết.

Bài này就来探究 vài cảnh tìm kiếm nhị phân常用 nhất: tìm một số, tìm biên trái, tìm biên phải. Hơn nữa, chúng ta chính là要深入 chi tiết, ví như dấu不等 có hẳn带 dấu bằng không, `mid` có hẳn cộng một không, v.v. Phân tích差异 của những chi tiết này cũng như nguyên nhân xuất hiện差异, đảm bảo bạn能 linh hoạt chính xác viết ra thuật toán tìm kiếm nhị phân đúng.

Ngoài ra声明 một chút, với mỗi cảnh của tìm kiếm nhị phân, bài này còn sẽ探讨 nhiều cách viết code, mục đích là để bạn hiểu nguyên nhân bản chất xuất hiện差异细微 này, chí ít bạn thấy code người khác时不会懵逼. Thực tế những cách viết này không có优劣, bạn thích loại nào就 dùng loại đó好了.

## Không, khung tìm kiếm nhị phân

```java
int binarySearch(int[] nums, int target) {
    int left = 0, right = ...;

    while(...) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) {
            ...
        } else if (nums[mid] < target) {
            left = ...
        } else if (nums[mid] > target) {
            right = ...
        }
    }
    return ...;
}
```

**技巧 phân tích tìm kiếm nhị phân là: đừng xuất hiện else, mà把 mọi tình huống dùng else if viết rõ, như vậy có thể清楚展现 mọi chi tiết**. Bài này都会 dùng else if, nhằm讲 rõ, độc giả hiểu xong có thể tự đơn giản hóa.

Trong đó phần đánh dấu `...`, chính là chỗ có thể xuất hiện vấn đề chi tiết, khi bạn thấy một code tìm kiếm nhị phân时, trước chú ý mấy chỗ này. Bài sau dùng ví dụ phân tích những chỗ này能 có biến hóa gì.

**Ngoài ra nói trước một chút, khi tính `mid` cần防 tràn**, code中 `left + (right - left) / 2`就和 kết quả của `(left + right) / 2` giống nhau, nhưng phòng hiệu quả `left` và `right` quá lớn, trực tiếp cộng dẫn đến tràn.

## Một, tìm một số (tìm kiếm nhị phân cơ bản)

Cảnh này đơn giản nhất, có thể cũng là thứ mọi người quen nhất, tức tìm kiếm một số, nếu tồn tại, trả về chỉ số của nó, nếu không trả về -1.

```java
class Solution {
    // Khung tìm kiếm nhị phân chuẩn, tìm chỉ số của phần tử mục tiêu, nếu không tồn tại trả về -1
    public int search(int[] nums, int target) {
        int left = 0;
        // Chú ý
        int right = nums.length - 1;

        while(left <= right) {
            int mid = left + (right - left) / 2;
            if(nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                // Chú ý
                left = mid + 1;
            } else if (nums[mid] > target) {
                // Chú ý
                right = mid - 1;
            }
        }
        return -1;
    }
}
```

Đoạn code này có thể giải LeetCode 704 「Tìm kiếm nhị phân」, nhưng chúng ta深入探讨 một chút chi tiết trong đó.

### Tại sao điều kiện vòng while là `<=` chứ không phải `<`?

Đáp: vì gán khởi tạo `right` là `nums.length - 1`, tức chỉ số của phần tử cuối cùng, chứ không phải `nums.length`.

Hai者 này có thể xuất hiện trong tìm kiếm nhị phân chức năng khác nhau, khác biệt là:者 trước相当于 hai đầu đều đoạn đóng `[left, right]`,者 sau相当于 đoạn đóng-trái mở-phải `[left, right)`. Vì大小 chỉ số là `nums.length`越界, nên chúng ta把 phía `right` này coi là đoạn mở.

Thuật toán này của chúng ta dùng là者 trước đoạn hai đầu đều đóng `[left, right]`. **Đoạn này thực ra chính là đoạn tìm kiếm mỗi lần**.

Lúc nào hẳn dừng tìm kiếm? Đương nhiên, khi tìm được giá trị mục tiêu có thể kết thúc:

```java
    if(nums[mid] == target)
        return mid;
```

Nhưng nếu không tìm được,就 cần vòng while kết thúc, rồi trả về -1. Vậy vòng while lúc nào hẳn kết thúc? **Khi đoạn tìm kiếm rỗng时 hẳn kết thúc**, nghĩa là bạn没得找了,就 bằng không tìm được嘛.

Điều kiện kết thúc của `while(left <= right)` là `left == right + 1`, viết thành dạng đoạn chính là `[right + 1, right]`, hoặc带 số cụ thể vào `[3, 2]`, có thể thấy **lúc này đoạn rỗng**, vì không có số既 lớn hơn bằng 3又 nhỏ hơn bằng 2吧. Nên lúc này vòng while kết thúc là đúng, trực tiếp trả về -1 là được.

Điều kiện kết thúc của `while(left < right)` là `left == right`, viết thành dạng đoạn chính là `[right, right]`, hoặc带 số cụ thể vào `[2, 2]`, **lúc này đoạn phi rỗng**, còn một số 2, nhưng lúc này vòng while kết thúc. Tức là nói đoạn `[2, 2]`被漏掉, chỉ số 2 không被 tìm kiếm, nếu lúc này trực tiếp trả về -1就是 sai.

Đương nhiên, nếu bạn nhất định要用 `while(left < right)` cũng được, chúng ta đã biết nguyên nhân lỗi,打个补丁好了:

```java
    // ...
    while(left < right) {
        // ...
    }
    return nums[left] == target ? left : -1;
```

### Tại sao là `left = mid + 1`, `right = mid - 1`?

Tại sao `left = mid + 1`, `right = mid - 1`? Tôi thấy có code là `right = mid` hoặc `left = mid`, không có cộng cộng trừ trừ này, rốt cuộc sao回事,判断 thế nào?

Đáp: đây cũng là một điểm khó của tìm kiếm nhị phân, có điều chỉ cần bạn能 hiểu nội dung phía trước, là có thể rất dễ判断.

刚才明确 khái niệm 「đoạn tìm kiếm」 này, mà đoạn tìm kiếm của thuật toán này là hai đầu đều đóng, tức `[left, right]`. Vậy khi chúng ta phát hiện chỉ số `mid` không phải `target`要 tìm时, bước tiếp hẳn đi tìm ở đâu?

Đương nhiên là đi tìm ở đoạn `[left, mid-1]` hoặc đoạn `[mid+1, right]` đúng không? **Vì `mid` đã tìm kiếm qua, hẳn từ đoạn tìm kiếm中去除**.

### Thuật toán này có khuyết điểm gì?

Đáp: đến đây, bạn hẳn đã nắm mọi chi tiết của thuật toán này, cũng như nguyên nhân xử lý như vậy. Nhưng, thuật toán này tồn tại局限性.

Ví như cho bạn mảng có thứ tự `nums = [1,2,2,2,3]`, `target` là 2, thuật toán này trả về chỉ số là 2, không sai. Nhưng nếu tôi muốn得到 biên trái của `target`, tức chỉ số 1, hoặc tôi muốn得到 biên phải của `target`, tức chỉ số 3, như vậy thuật toán này không thể xử lý.

Nhu cầu như vậy rất thường gặp, **bạn có lẽ会 nói, tìm được một `target`, rồi向左 hoặc向右 tìm tuyến tính không được sao? Được, nhưng không tốt, vì như vậy khó đảm bảo độ phức tạp cấp log của tìm kiếm nhị phân**.

Thuật toán tiếp theo của chúng ta就来 thảo luận hai loại thuật toán tìm kiếm nhị phân này.

## Hai, tìm kiếm nhị phân tìm biên trái

Dưới đây là dạng code thường gặp nhất, trong đó đánh dấu là chi tiết cần chú ý:

```java
int left_bound(int[] nums, int target) {
    int left = 0;
    // Chú ý
    int right = nums.length;

    // Chú ý
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) {
            right = mid;
        } else if (nums[mid] < target) {
            left = mid + 1;
        } else if (nums[mid] > target) {
            // Chú ý
            right = mid;
        }
    }
    return left;
}
```

### Tại sao trong while là `<` chứ không phải `<=`?

Đáp: dùng phương pháp giống nhau phân tích, vì `right = nums.length` chứ không phải `nums.length - 1`. Nên 「đoạn tìm kiếm」 mỗi lần lặp là `[left, right)` đóng-trái mở-phải.

Điều kiện kết thúc của `while(left < right)` là `left == right`, lúc này đoạn tìm kiếm `[left, left)` rỗng, nên có thể kết thúc đúng.

> [!NOTE]
> Chỗ này先要 nói một khác biệt của tìm kiếm biên trái-phải và thuật toán trên, cũng là thứ nhiều độc giả hỏi: **right vừa rồi chẳng phải `nums.length - 1` sao, tại sao chỗ này nhất định要 viết thành `nums.length` khiến 「đoạn tìm kiếm」 biến thành đóng-trái mở-phải**?
>
> Vì với tìm kiếm nhị phân tìm biên trái-phải, cách viết này比较 phổ biến, tôi就拿 cách viết này举例, đảm bảo sau này bạn gặp loại code này có thể hiểu. Bạn nhất định要用 cách viết hai đầu đều đóng ngược lại đơn giản hơn, tôi sẽ ở sau viết code liên quan,把 ba loại tìm kiếm nhị phân đều用 một loại cách viết hai đầu đều đóng thống nhất lại, bạn耐心看 tiếp là được.

### Khi `target` không tồn tại trả về gì?

Nếu trong `nums` không tồn tại giá trị `target` này, chỉ số tính ra hàm ý là gì? Nếu tôi muốn让 nó trả về -1, làm sao?

::: important Khi `target` không tồn tại, hàm ý giá trị trả về của `left_bound`

Đây là một câu hỏi rất hay且很重要, bạn把 chỗ này hiểu, trong cảnh ứng dụng thực tế của tìm kiếm nhị phân sẽ không懵逼.

Nói trực tiếp kết luận: **nếu `target` không tồn tại, tìm kiếm nhị phân tìm biên trái trả về chỉ số là chỉ số nhỏ nhất lớn hơn `target`**.

Lấy ví dụ, `nums = [2,3,5,7], target = 4`, hàm `left_bound` trả về là 2, vì phần tử 5 là phần tử nhỏ nhất lớn hơn 4.

Hơi绕晕了吧? Hàm `left_bound` này明明 là tìm biên trái, nhưng khi `target` không tồn tại,却 trả về chỉ số nhỏ nhất lớn hơn `target`. Kết luận này không cần học thuộc, nếu bạn拿不准,举 ví dụ đơn giản là có thể得到 kết luận này.

Nên mới nói với bạn thứ tìm kiếm nhị phân này思路 rất đơn giản, chi tiết là ma quỷ嘛, hố bên trong quá nhiều. Nếu thật muốn考你,总 có cách có thể把你考 đến hoài nghi人生.

Không phải tôi cố ý把 mẫu code tổng kết phức tạp như vậy, mà tìm kiếm nhị phân bản thân就很 phức tạp, những chi tiết này không thể绕开, nếu trước đây bạn chưa了解 những chi tiết này, chỉ能说明 trước đây bạn học không扎实. Dù không dùng mẫu tôi tổng kết, bạn cũng必须搞 rõ hành vi của thuật toán khi `target` không tồn tại, nếu không ra bug bạn cũng không biết sửa咋, thật严重 như vậy.

Nói lại, hành vi này của `left_bound` có một lợi. Ví như bây giờ让 bạn viết một hàm `floor`, là có thể trực tiếp dùng hàm `left_bound` để实现:

```java
// Trong một mảng có thứ tự, tìm 「chỉ số của phần tử lớn nhất nhỏ hơn target」
// Ví như nhập nums = [1,2,2,2,3], target = 2, hàm trả về 0, vì 1 là phần tử lớn nhất nhỏ hơn 2.
// Lại ví như nhập nums = [1,2,3,5,6], target = 4, hàm trả về 2, vì 3 là phần tử lớn nhất nhỏ hơn 4.
int floor(int[] nums, int target) {
    // Khi target không tồn tại, ví như nhập [4,6,8,10], target = 7
    // left_bound trả về 2, trừ một chính là 1, phần tử 6 chính là phần tử lớn nhất nhỏ hơn 7
    // Khi target tồn tại, ví như nhập [4,6,8,8,8,10], target = 8
    // left_bound trả về 2, trừ một chính là 1, phần tử 6 chính là phần tử lớn nhất nhỏ hơn 8
    return left_bound(nums, target) - 1;
}
```

Cuối cùng, khuyên của tôi là, nếu bạn必须 viết tay code nhị phân, vậy bạn nhất định要了解 rõ种种 hành vi của code, khung mà bài này tổng kết chính là đang giúp bạn理清 chi tiết trong đó. Nếu không cần thiết, đừng tự viết tay,尽肯能 dùng hàm thư viện chuẩn mà ngôn ngữ lập trình cung cấp, có thể tiết kiệm thời gian, mà hành vi của hàm thư viện chuẩn trong tài liệu đều có说明明确, không dễ lỗi.

:::

Nếu muốn khi `target` không tồn tại trả về -1 thực ra rất đơn giản, lúc trả về判断 thêm một chút `nums[left]` có bằng `target` không là được, nếu không bằng,就说明 `target` không tồn tại. Cần chú ý, trước khi thăm chỉ số mảng要 đảm bảo chỉ số không越界:

```java
while (left < right) {
    // ...
}
// Nếu chỉ số越界,说明 trong mảng vô phần tử mục tiêu, trả về -1
if (left < 0 || left >= nums.length) {
    return -1;
}
// Gợi ý: thực ra if trên判断 left < 0 này có thể lược, vì với thuật toán này, left không thể nhỏ hơn 0
// Bạn xem logic thực thi của thuật toán này, left khởi tạo chính là 0, mà chỉ có thể一直往右 đi, vậy chỉ có thể ở phía phải越界
// Có điều chỗ này tôi就 đồng thời判断, vì trước khi thăm chỉ số mảng đảm bảo chỉ số ở hai đầu trái phải都不越界 là một thói quen tốt, không có hại
// Một lợi nữa là让 mẫu nhị phân统一 hơn, giảm chi phí nhớ của bạn, vì lát nữa tìm biên phải cũng có判断 ra biên tương tự

// 判断 một chút nums[left] có phải target không
return nums[left] == target ? left : -1;
```

### Tại sao là `left = mid + 1` và `right = mid`?

Tại sao `left = mid + 1`, `right = mid`? Và thuật toán trước đó không giống?

Đáp: chuyện này giải thích rất dễ, vì 「đoạn tìm kiếm」 của chúng ta là `[left, right)` đóng-trái mở-phải, nên khi `nums[mid]`被 kiểm tra xong, bước tiếp hẳn đi đoạn trái hoặc phải của `mid` tìm kiếm, tức `[left, mid)` hoặc `[mid + 1, right)`.

### Tại sao thuật toán này能够 tìm biên trái?

Đáp: then chốt nằm ở xử lý với tình huống `nums[mid] == target`:

```java
    if (nums[mid] == target)
        right = mid;
```

Có thể thấy, khi tìm được target đừng立即 trả về, mà thu nhỏ上界 `right` của 「đoạn tìm kiếm」, trong đoạn `[left, mid)` tiếp tục tìm kiếm, tức không ngừng co sang trái, đạt mục đích khóa biên trái.

### Tại sao trả về `left` chứ không phải `right`?

Đáp: đều giống nhau, vì điều kiện kết thúc của while là `left == right`.

### Có thể thống nhất thành đoạn tìm kiếm hai đầu đều đóng không?

Có thể nghĩ cách把 `right` biến thành `nums.length - 1`, cũng chính là tiếp tục dùng 「đoạn tìm kiếm」 hai đầu đều đóng? Như vậy là có thể và tìm kiếm nhị phân loại thứ nhất ở某种程度上 thống nhất.

Đáp: đương nhiên được, chỉ cần bạn明白 khái niệm 「đoạn tìm kiếm」 này, là có thể phòng hiệu quả漏掉 phần tử, tùy bạn改 thế nào đều được. Dưới đây chúng ta nghiêm格根據 logic来 sửa:

Vì bạn nhất định让 đoạn tìm kiếm hai đầu đều đóng, nên `right` hẳn khởi tạo là `nums.length - 1`, điều kiện kết thúc của while hẳn là `left == right + 1`, cũng chính là trong đó hẳn dùng `<=`:

```java
int left_bound(int[] nums, int target) {
    // Đoạn tìm kiếm là [left, right]
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        // if else ...
    }
}
```

Vì đoạn tìm kiếm là hai đầu đều đóng, mà bây giờ là tìm biên trái, nên logic cập nhật `left` và `right` như sau:

```java
if (nums[mid] < target) {
    // Đoạn tìm kiếm biến thành [mid+1, right]
    left = mid + 1;
} else if (nums[mid] > target) {
    // Đoạn tìm kiếm biến thành [left, mid-1]
    right = mid - 1;
} else if (nums[mid] == target) {
    // Co biên phải
    right = mid - 1;
}
```

Và刚才 giống nhau, nếu muốn khi không tìm được `target` trả về -1, vậy kiểm tra một chút `nums[left]` và `target` có bằng nhau không là được:

```java
// Lúc này target比 mọi số đều lớn, trả về -1
if (left == nums.length) return -1;
// 判断 một chút nums[left] có phải target không
return nums[left] == target ? left : -1;
```

Đến đây, toàn bộ thuật toán就 viết xong, code đầy đủ như sau:

```java
int left_bound(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    // Đoạn tìm kiếm là [left, right]
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) {
            // Đoạn tìm kiếm biến thành [mid+1, right]
            left = mid + 1;
        } else if (nums[mid] > target) {
            // Đoạn tìm kiếm biến thành [left, mid-1]
            right = mid - 1;
        } else if (nums[mid] == target) {
            // Co biên phải
            right = mid - 1;
        }
    }
    // 判断 target có tồn tại trong nums không
    // Nếu越界, target肯定 không tồn tại, trả về -1
    if (left < 0 || left >= nums.length) {
        return -1;
    }
    // 判断 một chút nums[left] có phải target không
    return nums[left] == target ? left : -1;
}
```

## Ba, tìm kiếm nhị phân tìm biên phải

Tương tự thuật toán tìm biên trái, chỗ này cũng sẽ cho hai cách viết, vẫn先 viết cách viết đóng-trái mở-phải thường gặp, chỉ có hai chỗ và tìm biên trái khác nhau:

```java
int right_bound(int[] nums, int target) {
    int left = 0, right = nums.length;

    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) {
            // Chú ý
            left = mid + 1;
        } else if (nums[mid] < target) {
            left = mid + 1;
        } else if (nums[mid] > target) {
            right = mid;
        }
    }
    // Chú ý
    return left - 1;
}
```

### Tại sao thuật toán này能够 tìm biên phải?

Đáp: tương tự, điểm then chốt vẫn là chỗ này:

```java
if (nums[mid] == target) {
    left = mid + 1;
}
```

Khi `nums[mid] == target`时, đừng立即 trả về, mà tăng左界 `left` của 「đoạn tìm kiếm」, khiến đoạn không ngừng靠拢 sang phải, đạt mục đích khóa biên phải.

### Tại sao trả về `left - 1`?

Tại sao cuối cùng trả về `left - 1` mà không像 hàm biên trái, trả về `left`? Hơn nữa tôi thấy chỗ này nếu là tìm biên phải, hẳn trả về `right` mới đúng.

Đáp: trước hết, điều kiện kết thúc của vòng while là `left == right`, nên `left` và `right`一样的, bạn nhất định要 thể hiện đặc điểm phía phải, trả về `right - 1`好了.

Còn tại sao要 trừ một, đây là một điểm đặc biệt của tìm biên phải, then chốt ở判断 điều kiện khi khóa biên phải này:

```java
// Tăng left, khóa biên phải
if (nums[mid] == target) {
    left = mid + 1;
    // Nghĩ như vầy: mid = left - 1
}
```

![](https://labuladong.online/algo/images/binary-search/3.jpg)

Vì chúng ta với cập nhật `left`必须是 `left = mid + 1`, chính là nói khi vòng while kết thúc时, `nums[left]` nhất định不等于 `target` nữa, mà `nums[left-1]` có thể là `target`.

Còn tại sao cập nhật của `left`必须是 `left = mid + 1`, đương nhiên là để把 `nums[mid]` loại khỏi đoạn tìm kiếm, chỗ này就不赘述.

### Nếu khi `target` không tồn tại trả về gì?

Nếu trong `nums` không tồn tại giá trị `target` này, chỉ số tính ra hàm ý là gì? Nếu tôi muốn让 nó trả về -1, làm sao?

::: important Khi `target` không tồn tại, hàm ý giá trị trả về của `right_bound`

Nói trực tiếp kết luận, và `left_bound`讲 trước đó ngược nhau: **nếu `target` không tồn tại, tìm kiếm nhị phân tìm biên phải trả về chỉ số là chỉ số lớn nhất nhỏ hơn `target`**.

Kết luận này không cần học thuộc, nếu bạn拿不准,举 ví dụ đơn giản là có thể得到 kết luận này. Ví như `nums = [2,3,5,7], target = 4`, hàm `right_bound` trả về là 1, vì phần tử 3 là phần tử lớn nhất nhỏ hơn 4.

Cùng khuyên trước đó giống nhau, xét đến phức tạp chi tiết code tìm kiếm nhị phân, nếu không cần thiết, đừng tự viết tay,尽肯能 dùng hàm thư viện chuẩn mà ngôn ngữ lập trình cung cấp.

:::

Nếu bạn muốn khi `target` không tồn tại trả về -1, rất đơn giản, chỉ cần cuối cùng判断 một chút `nums[left-1]` có phải `target` không là được, tương tự tìm biên trái trước đó, làm chút判断 thêm là được:

```java
while (left < right) {
    // ...
}
// 判断 target có tồn tại trong nums không
// Chỉ số left - 1越界的话 target肯定 không tồn tại
if (left - 1 < 0 || left - 1 >= nums.length) {
    return -1;
}
// 判断 một chút nums[left - 1] có phải target không
return nums[left - 1] == target ? (left - 1) : -1;
```

**4、Có thể cũng把 「đoạn tìm kiếm」 của thuật toán này thống nhất thành dạng hai đầu đều đóng không? Như vậy ba cách viết này就 hoàn toàn thống nhất, sau này là có thể nhắm mắt viết ra**.

Đáp: đương nhiên được, tương tự cách viết thống nhất của tìm biên trái, thực ra chỉ cần đổi hai chỗ là được:

```java
int right_bound(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) {
            left = mid + 1;
        } else if (nums[mid] > target) {
            right = mid - 1;
        } else if (nums[mid] == target) {
            // Chỗ này đổi thành co biên trái là được
            left = mid + 1;
        }
    }
    // Cuối đổi thành trả về left - 1
    if (left - 1 < 0 || left - 1 >= nums.length) {
        return -1;
    }
    return nums[left - 1] == target ? (left - 1) : -1;
}
```

Đương nhiên, do điều kiện kết thúc của while là `right == left - 1`, nên bạn把 `left - 1` trong code trên đều đổi thành `right` cũng không vấn đề, như vậy có thể更有利于看出来 đây đang 「tìm biên phải」:

```java
int right_bound(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) {
            left = mid + 1;
        } else if (nums[mid] > target) {
            right = mid - 1;
        } else if (nums[mid] == target) {
            // Chỗ này đổi thành co biên trái là được
            left = mid + 1;
        }
    }
    // Cuối đổi thành trả về right
    if (right < 0 || right >= nums.length) {
        return -1;
    }
    return nums[right] == target ? right : -1;
}
```

Đến đây, hai cách viết của tìm kiếm nhị phân tìm biên phải cũng hoàn thành, thực ra把 「đoạn tìm kiếm」 thống nhất thành hai đầu đều đóng ngược lại dễ nhớ hơn, bạn nói是吧?

## Bốn, thống nhất logic

Có tìm kiếm nhị phân tìm biên trái-phải, bạn có thể đi giải LeetCode 34 「Tìm vị trí đầu và cuối của phần tử trong mảng có thứ tự」. Tiếp theo chải một chút logic nhân quả差异 chi tiết này:

**Thứ nhất, thuật toán tìm kiếm nhị phân cơ bản nhất**:

```java
Vì chúng ta khởi tạo right = nums.length - 1
Nên quyết định 「đoạn tìm kiếm」 của chúng ta là [left, right]
Nên quyết định while (left <= right)
Đồng thời cũng quyết định left = mid+1 và right = mid-1

Vì chúng ta chỉ cần tìm được một chỉ số của target là được
Nên khi nums[mid] == target时 có thể立即 trả về
```

**Thứ hai, tìm kiếm nhị phân tìm biên trái**:

```java
Vì chúng ta khởi tạo right = nums.length
Nên quyết định 「đoạn tìm kiếm」 của chúng ta là [left, right)
Nên quyết định while (left < right)
Đồng thời cũng quyết định left = mid + 1 và right = mid

Vì chúng ta需 tìm chỉ số trái nhất của target
Nên khi nums[mid] == target时 đừng立即 trả về
Mà要 thắt chặt biên phải để khóa biên trái
```

**Thứ ba, tìm kiếm nhị phân tìm biên phải**:

```java
Vì chúng ta khởi tạo right = nums.length
Nên quyết định 「đoạn tìm kiếm」 của chúng ta là [left, right)
Nên quyết định while (left < right)
Đồng thời cũng quyết định left = mid + 1 và right = mid

Vì chúng ta需 tìm chỉ số phải nhất của target
Nên khi nums[mid] == target时 đừng立即 trả về
Mà要 thắt chặt biên trái để khóa biên phải

Lại vì khi thắt chặt biên trái必须 left = mid + 1
Nên cuối cùng dù trả về left hay right,必須 trừ một
```

Với tìm kiếm nhị phân tìm biên trái-phải,手法比较 thường gặp là dùng 「đoạn tìm kiếm」 đóng-trái mở-phải, **chúng ta còn根據 logic把 「đoạn tìm kiếm」 toàn bộ thống nhất thành hai đầu đều đóng, tiện nhớ, chỉ cần sửa hai chỗ là có thể biến hóa ra ba cách viết**:

Nếu nội dung trên bạn đều能 hiểu, vậy chúc mừng bạn, chi tiết của thuật toán tìm kiếm nhị phân不过如此. Thông qua bài này, bạn học được:

1、Khi phân tích code tìm kiếm nhị phân, đừng xuất hiện else, toàn bộ展开 thành else if tiện hiểu.把 logic viết đúng xong rồi合并 nhánh, nâng hiệu suất chạy.

2、Chú ý 「đoạn tìm kiếm」 và điều kiện kết thúc của while, nếu tồn tại phần tử漏掉, nhớ cuối cùng kiểm tra.

3、Nếu cần định nghĩa 「đoạn tìm kiếm」 đóng-trái mở-phải để tìm biên trái-phải, chỉ cần khi `nums[mid] == target`时 làm sửa là được, khi tìm phía phải cần trừ một.

4、Nếu把 「đoạn tìm kiếm」 toàn bộ thống nhất thành hai đầu đều đóng, dễ nhớ, chỉ cần稍改 code chỗ điều kiện `nums[mid] == target` và logic trả về là được, khuyên lấy sổ nhỏ记下来, làm mẫu tìm kiếm nhị phân.

Cuối cùng tôi muốn nói, khung tìm kiếm nhị phân trên thuộc phạm畴 「thuật」, nếu上升 đến层面 「đạo」, **tinh túy của tư duy nhị phân chính là: thông qua thông tin đã biết尽可能多 co (gập đôi) không gian tìm kiếm**, từ đó tăng hiệu suất穷举, nhanh chóng tìm mục tiêu.

Hiểu bài này có thể đảm bảo bạn viết ra code tìm kiếm nhị phân đúng, nhưng đề thực tế sẽ không trực tiếp让 bạn viết code nhị phân, tôi sẽ trong [Vận dụng tìm kiếm nhị phân](https://labuladong.online/algo/frequency-interview/binary-search-in-action/) và [Thêm bài tập tìm kiếm nhị phân](https://labuladong.online/algo/problem-set/binary-search/)讲 thêm làm sao把 tư duy nhị phân vận dụng vào nhiều đề thuật toán hơn.
