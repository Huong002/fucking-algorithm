Đề rất đơn giản:

Cho bạn nhập một mảng `nums` và một số nguyên dương `k`, hãykiểm tra `nums` có thể được chia đều thành `k` tập con có tổng phần tử giống nhau không.

Chữ ký hàm như sau:

```java
boolean canPartitionKSubsets(int[] nums, int k);
```

## ý tưởng đề bài

Trở lại vấn đề chính, bài thuật toán này bắt chúng ta tìm phân hoạch tập con, vấn đề tập con và vấn đề hoán vị tổ hợp có khác biệt, nhưng chúng ta có thể học hỏi trừu tượng "mô hình bóng-hộp", dùng haigóc nhìn khác nhau để giải vấn đề phân hoạch tập con này.

đem mảng `nums` đựng `n` số chia thành `k` tập có tổng giống nhau, bạn có thể tưởng tượng đem `n` số phân vào `k` cái "thùng", cuối cùng tổng số trong `k` "thùng" này cần giống nhau.

Bài trước [Dùng mô hình bóng-hộp hiểu thuật toán quay lui](https://labuladong.online/algo/practice-in-action/two-views-of-backtrack/) từng nói, then chốt của thuật toán quay lui ở đâu?

Then chốt cần biết "làm lựa chọn" thế nào, như vậy mới có thể lợi dụng hàm đệ quy tiến hànhvét cạn.

Vậy mô phỏngý tưởng suy dẫn công thức hoán vị, đem `n` số phân vào `k` thùng, chúng ta cũng có thể có haigóc nhìn:

**góc nhìn một, nếu chúng ta chuyển sanggóc nhìn của `n` số này, mỗi số đều cần chọn vào một trong `k` thùng**.

![](https://labuladong.online/algo/images/set-split/5.jpeg)

**góc nhìn hai, nếu chúng ta chuyển sanggóc nhìn của `k` thùng này, với mỗi thùng, đều cần duyệt `n` số trong `nums`, rồi chọn có đem số duyệt hiện tại xếp vào thùng này của mình không**.

![](https://labuladong.online/algo/images/set-split/6.jpeg)

Bạn có thể hỏi, haigóc nhìn này có khác gì?

Tương tự hoán vị tập congiảng trước đó, dùnggóc nhìn khác nhau tiến hànhvét cạn, tuy kết quả giống nhau, nhưng logic code cách giải khác nhau, cài đặt code cụ thể cũng khác nhau, có thể sinh độ phức tạp thời-không khác nhau. Chúng ta cần chọn cách giải độ phức tạp thấp hơn.

## Lấygóc nhìn số

Dùng vòng for lặp duyệt mảng `nums` mọi người chắc chắn đều sẽ:

```java
for (int index = 0; index < nums.length; index++) {
    print(nums[index]);
}
```

Duyệt đệ quy mảng bạn sẽ không? Thực ra cũng rất đơn giản:

```java
void traverse(int[] nums, int index) {
    if (index == nums.length) {
        return;
    }
    print(nums[index]);
    traverse(nums, index + 1);
}
```

Chỉ cần gọi `traverse(nums, 0)`, và hiệu quả vòng for hoàn toàn giống nhau.

Vậy trở lại bài này, lấygóc nhìn số, chọn `k` thùng, dùng vòng for viết ra là như dưới:

```java
// k thùng (tập hợp), ghi tổng số mỗi thùng đựng
int[] bucket = new int[k];

// vét cạn mỗi số trong nums
for (int index = 0; index < nums.length; index++) {
    // vét cạn mỗi thùng
    for (int i = 0; i < k; i++) {
        // nums[index] chọn có cần vào thùng thứ i không
        // ...
    }
}
```

Nếu đổi thành dạng đệ quy, chính là logic code dưới đây:

```java
// k thùng (tập hợp), ghi tổng số mỗi thùng đựng
int[] bucket = new int[k];

// vét cạn mỗi số trong nums
void backtrack(int[] nums, int index) {
    // base case
    if (index == nums.length) {
        return;
    }
    // vét cạn mỗi thùng
    for (int i = 0; i < bucket.length; i++) {
        // Chọn xếp vào thùng thứ i
        bucket[i] += nums[index];
        // Đệ quyvét cạn lựa chọn của số tiếp theo
        backtrack(nums, index + 1);
        // Hủy lựa chọn
        bucket[i] -= nums[index];
    }
}
```

Tuy code trên vẻn vẹn là logicvét cạn, còn chưa thể giải vấn đề của chúng ta, nhưng chỉ cần lược thêm hoàn thiện là được:

```java
class Solution {
    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Loại một số tình huống cơ bản
        if (k > nums.length) return false;
        int sum = 0;
        for (int v : nums) sum += v;
        if (sum % k != 0) return false;

        // k thùng (tập hợp), ghi tổng số mỗi thùng đựng
        int[] bucket = new int[k];
        // Về lý mỗi thùng (tập hợp) tổng số
        int target = sum / k;
        // vét cạn, xem nums có thể chia thành k tập con tổng target không
        return backtrack(nums, 0, bucket, target);
    }

    // Đệ quyvét cạn mỗi số trong nums
    boolean backtrack(
        int[] nums, int index, int[] bucket, int target) {

        if (index == nums.length) {
            // Kiểm tra tổng số mọi thùng có đều target không
            for (int i = 0; i < bucket.length; i++) {
                if (bucket[i] != target) {
                    return false;
                }
            }
            // nums thành công chia đều thành k tập con
            return true;
        }

        // vét cạn thùng mà nums[index] có thể xếp vào
        for (int i = 0; i < bucket.length; i++) {
            // Cắt tỉa, thùng xếp đầy rồi
            if (bucket[i] + nums[index] > target) {
                continue;
            }
            // đem nums[index] xếp vào bucket[i]
            bucket[i] += nums[index];
            // Đệ quyvét cạn lựa chọn của số tiếp theo
            if (backtrack(nums, index + 1, bucket, target)) {
                return true;
            }
            // Hủy lựa chọn
            bucket[i] -= nums[index];
        }

        // nums[index] xếp vào thùng nào cũng không được
        return false;
    }
}
```

Có làm nền trước đó, tin rằng đoạn code này khá dễ hiểu, thực ra chúng ta có thể làm thêm một tối ưu.

Chủ yếu xem phần đệ quy của hàm `backtrack`:

```java
for (int i = 0; i < bucket.length; i++) {
    // Cắt tỉa
    if (bucket[i] + nums[index] > target) {
        continue;
    }

    if (backtrack(nums, index + 1, bucket, target)) {
        return true;
    }
}
```

**Nếu chúng ta để càng nhiều tình huống trúng nhánh if cắt tỉa, là có thể giảm số lần gọi đệ quy, nhất định mức độ trên giảm độ phức tạp thời gian**.

Làm sao trúng càng nhiều nhánh if này? cần biết tham số `index` của chúng ta tăng dần từ 0, cũng chính là đệ quy duyệt mảng `nums` từ 0.

Nếu chúng ta sắp xếp trước mảng `nums`, đem số lớn xếp phía trước, vậy số lớn sẽ trước được phân vào `bucket`, với số về sau, `bucket[i] + nums[index]` sẽ lớn hơn, dễ kích hoạt điều kiện if cắt tỉa hơn.

Nên có thể trong code trước đó thêm một số code:

```java
boolean canPartitionKSubsets(int[] nums, int k) {
    // Code khác không đổi
    // ...
    // Sắp xếp giảm dần mảng nums
    Arrays.sort(nums);
    // Lật mảng, nhận được mảng giảm dần
    for (i = 0, j = nums.length - 1; i < j; i++, j--) {
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
    // *****************
    return backtrack(nums, 0, bucket, target);
}
```

cách giải này có thể nhận được đáp án đúng, nhưng tốn thời gian khá nhiều, đã không thể qua hết test case, tiếp theo xem cách giải góc nhìn còn lại.

## Lấygóc nhìn thùng

Đầu bài nói, **lấygóc nhìn thùng tiến hànhvét cạn, mỗi thùng cần duyệt tất cả số trong `nums`, quyết định có đem số hiện tại xếp vào thùng không; khi xếp đầy một thùng xong, còn cần xếp thùng tiếp theo, cho đến khi mọi thùng đều xếp đầy**.

ý tưởng này có thể dùng đoạn code dưới biểu thị ra:

```java
// xếp đầy mọi thùng mới thôi
while (k > 0) {
    // Ghi tổng số trong thùng hiện tại
    int bucket = 0;
    for (int i = 0; i < nums.length; i++) {
        // Quyết định có đem nums[i] đặt vào thùng hiện tại không
        if (canAdd(bucket, num[i])) {
            bucket += nums[i];
        }
        if (bucket == target) {
            // xếp đầy một thùng, xếp thùng tiếp theo
            k--;
            break;
        }
    }
}
```

Vậy chúng ta cũng có thể đem vòng while này viết lại thành hàm đệ quy, có điều hơn vừa rồi hơi phức tạp, trước viết một hàm đệ quy `backtrack` ra:

```java
boolean backtrack(int k, int bucket, int[] nums, int start, boolean[] used, int target);
```

Đừng bị nhiều tham số này dọa, tôi sẽ từng cái một giải thích những tham số này. Nếu bạn đủ thấu đáo hiểu bài trước [Dùng mô hình bóng-hộp hiểu thuật toán quay lui](https://labuladong.online/algo/practice-in-action/two-views-of-backtrack/), cũng có thể được tâm nên tay viết ra hàm quay lui như vậy.

Tham số của hàm `backtrack` này có thể giải thích như sau:

Bây giờ thùng số `k` đang suy nghĩ có hẳn đem phần tử `nums[start]` này xếp vào không; hiện tại trong thùng số `k` đã xếp tổng số là `bucket`; `used` đánh dấu một phần tử nào đó có đã được xếp vào thùng không; `target` là tổng mục tiêu mỗi thùng cần đạt thành.

căn cứ định nghĩa hàm này, có thể gọi hàm `backtrack` như sau:

```java
class Solution {
    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Loại một số tình huống cơ bản
        if (k > nums.length) return false;
        int sum = 0;
        for (int v : nums) sum += v;
        if (sum % k != 0) return false;

        boolean[] used = new boolean[nums.length];
        int target = sum / k;
        // Thùng số k ban đầu gì sao cũng chưa xếp, từ nums[0] bắt đầu làm lựa chọn
        return backtrack(k, 0, nums, 0, used, target);
    }
}
```

Trước khi cài đặt logic hàm `backtrack`, lặp lại một lượt, từgóc nhìn thùng:

1, Cần duyệt tất cả số trong `nums`, quyết định số nào cần xếp vào thùng hiện tại.

2, Nếu thùng hiện tại xếp đầy (tổng số trong thùng đạt `target`), thì để thùng tiếp theo bắt đầu thực thi bước 1.

Code dưới thì thực hiện được logic này:

```java
class Solution {
    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Xem bài trên
    }

    boolean backtrack(int k, int bucket,
        int[] nums, int start, boolean[] used, int target) {
        // base case
        if (k == 0) {
            // Mọi thùng đều được xếp đầy, mà nums nhất định toàn bộ dùng hết
            // Vì target == sum / k
            return true;
        }
        if (bucket == target) {
            // xếp đầy thùng hiện tại, đệ quyvét cạn lựa chọn của thùng tiếp theo
            // để thùng tiếp theo từ nums[0] bắt đầu chọn số
            return backtrack(k - 1, 0 ,nums, 0, used, target);
        }

        // Từ start dò xét về sau nums[i] hiệu quả xếp vào thùng hiện tại
        for (int i = start; i < nums.length; i++) {
            // Cắt tỉa
            if (used[i]) {
                // nums[i] đã được xếp vào thùng khác
                continue;
            }
            if (nums[i] + bucket > target) {
                // Thùng hiện tại xếp không nổi nums[i]
                continue;
            }
            // Làm lựa chọn, đem nums[i] xếp vào thùng hiện tại
            used[i] = true;
            bucket += nums[i];
            // Đệ quyvét cạn số tiếp theo có xếp vào thùng hiện tại không
            if (backtrack(k, bucket, nums, i + 1, used, target)) {
                return true;
            }
            // Hủy lựa chọn
            used[i] = false;
            bucket -= nums[i];
        }
        // vét cạn mọi số, đều không thể xếp đầy thùng hiện tại
        return false;
    }
}
```

**Đoạn code này có thể rút ra đáp án đúng, nhưng hiệu suất rất thấp, chúng ta có thể suy nghĩ có còn không gian tối ưu không**.

Trước hết, trong cách giải này mỗi thùng đều có thể coi là không có差异, nhưng thuật toán quay lui của chúng ta nhưng lại sẽ đối xử phân biệt chúng, chỗ này sẽ sẽ xuất hiện tính toán trùng lặp.

Thuật toán quay lui sẽ quay lui về thùng đầu, bắt đầu lạivét cạn, bây giờ nó biết trong thùng đầu xếp `1, 4` không khả thi, nó sẽ thử đem `2, 3` xếp vào thùng đầu:

Bây giờ thùng đầu xếp đầy, liền bắt đầu xếp thùng hai, thuật toán sẽ xếp vào `1, 4`:

Tốt, đến đây bạn hẳn nhận ra vấn đề, tình huống này thực ra và tình huống trước đó một kiểu. Tức là nói, đến đây bạn thực ra đã biết không cầnvét cạn nữa, tất yếu gom không ra `k` tập con tổng `target`.

Nhưng thuật toán của chúng ta vẫn sẽ ngốc nghếch tiếp tụcvét cạn, vì trong mắt nó, phần tử xếp trong thùng một và thùng hai không giống nhau, vậy đây chính là hai tình huống không giống nhau.

Vậy chúng ta làm sao để trí tuệ thuật toán nâng cao, nhận ra tình huống này, tránh tính toán dư thừa?

Bạn chú ý mảng `used` của hai tình huống này bằng lòng độ dài cố định được giống nhau, nên mảng `used` có thể coi là "trạng thái" trong quá trình quay lui.

**Nên, chúng ta có thể dùng một bảng nhớ `memo`, khi xếp đầy một thùng ghi lại trạng thái `used` hiện tại, nếu trạng thái `used` hiện tại là từng xuất hiện, vậy không cần tiếp tụcvét cạn, từ đó khởi tới cắt tỉa tránh tính toán dư thừa**.

Có độc giả chắc chắn sẽ hỏi, `used` là một mảng bool, làm key lưu thế nào? Chuyện này thực ra là vấn đề nhỏ, ví như chúng ta có thể đem mảng chuyển thành chuỗi, như vậy là có thể làm key của bảng băm để lưu.

Xem cài đặt code, chỉ cần sửa chút hàm `backtrack` là được:

```java
class Solution {

    // Bảng nhớ, lưu trạng thái của mảng used
    HashMap<String, Boolean> memo = new HashMap<>();

    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Xem bài trên
    }

    boolean backtrack(int k, int bucket, int[] nums, int start, boolean[] used, int target) {
        // base case
        if (k == 0) {
            return true;
        }
        // đem trạng thái của used chuyển thành chuỗi dạng [true, false,...]
        // Tiện lưu vào HashMap
        String state = Arrays.toString(used);

        if (bucket == target) {
            // xếp đầy thùng hiện tại, đệ quyvét cạn lựa chọn của thùng tiếp theo
            boolean res = backtrack(k - 1, 0, nums, 0, used, target);
            // đem trạng thái hiện tại và kết quả lưu vào bảng nhớ
            memo.put(state, res);
            return res;
        }

        if (memo.containsKey(state)) {
            // Nếu trạng thái hiện tại từng tính qua, sẽ trực tiếp trả về, đừng đệ quyvét cạn nữa
            return memo.get(state);
        }

        // Logic khác không đổi...
    }
}
```

Như vậy nộp cách giải, phát hiện hiệu suất thực thi vẫn khá thấp, lần này không phải vì tính toán dư thừa trên logic thuật toán, mà vấn đề cài đặt code.

**Vì mỗi lần đệ quy đều cần đem mảng `used` chuyển thành chuỗi, với ngôn ngữ lập trình cũng là một hao phí không nhỏ, nên chúng ta còn có thể sâu hơn tối ưu**.

Chú ý quy mô dữ liệu đề cho `nums.length <= 16`, tức là nói mảng `used` nhiều nhất cũng sẽ không vượt quá 16, vậy chúng ta hoàn toàn có thể dùngkỹ thuật "ảnh bit ", dùng một biến `used` kiểu int để thay mảng `used`.

Cụ thể, chúng ta có thể dùng bit thứ `i` của số nguyên `used` (`(used >> i) & 1`) là 1/0 để biểu thị true/false của `used[i]`.

Như vậy một tới, không chỉ tiết kiệm không gian, mà số nguyên `used` cũng có thể trực tiếp làm key lưu vào HashMap, bỏ qua hao phí chuyển mảng thành chuỗi.

Xem code cách giải cuối cùng:

```java
class Solution {
    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Loại một số tình huống cơ bản
        if (k > nums.length) return false;
        int sum = 0;
        for (int v : nums) sum += v;
        if (sum % k != 0) return false;

        // Dùngkỹ thuật bitmask
        int used = 0;
        int target = sum / k;
        // Thùng số k ban đầu gì sao cũng chưa xếp, từ nums[0] bắt đầu làm lựa chọn
        return backtrack(k, 0, nums, 0, used, target);
    }

    HashMap<Integer, Boolean> memo = new HashMap<>();

    boolean backtrack(int k, int bucket,
                    int[] nums, int start, int used, int target) {
        // base case
        if (k == 0) {
            // Mọi thùng đều được xếp đầy, mà nums nhất định toàn bộ dùng hết
            return true;
        }
        if (bucket == target) {
            // xếp đầy thùng hiện tại, đệ quyvét cạn lựa chọn của thùng tiếp theo
            // để thùng tiếp theo từ nums[0] bắt đầu chọn số
            boolean res = backtrack(k - 1, 0, nums, 0, used, target);
            // Cache kết quả
            memo.put(used, res);
            return res;
        }

        if (memo.containsKey(used)) {
            // Tránh tính toán dư thừa
            return memo.get(used);
        }

        for (int i = start; i < nums.length; i++) {
            // Cắt tỉa
            // kiểm tra bit thứ i có phải 1 không
            if (((used >> i) & 1) == 1) {
                // nums[i] đã được xếp vào thùng khác
                continue;
            }
            if (nums[i] + bucket > target) {
                continue;
            }
            // Làm lựa chọn
            // đem vị trí thứ i置 thành 1
            used |= 1 << i;
            bucket += nums[i];
            // Đệ quyvét cạn số tiếp theo có xếp vào thùng hiện tại không
            if (backtrack(k, bucket, nums, i + 1, used, target)) {
                return true;
            }
            // Hủy lựa chọn
            // Dùng phép xor đem bit thứ i khôi phục 0
            used ^= 1 << i;
            bucket -= nums[i];
        }

        return false;
    }
}
```

## Tổng kết cuối

Haiý tưởng mà bài này viết đều có thể tính ra đáp án đúng, có điều cách giải thứ nhất dù qua tối ưu sắp xếp, cũng rõ ràng hơn cách giải thứ hai chậm rất nhiều, đây là tại sao?

Chúng ta phân tích độ phức tạp thời gian của hai thuật toán này, giả sử số phần tử trong `nums` là `n`.

Nói trước cách giải thứ nhất, cũng chính là từ góc độ số tiến hànhvét cạn, `n` số, mỗi số có `k` thùng để chọn, nên số lượng kết quả tổ hợp ra là `k^n`, độ phức tạp thời gian cũng chính là $O(k^n)$.

cách giải thứ hai, mỗi thùng cần duyệt `n` số, với mỗi số có hai lựa chọn " xếp vào" hoặc "không xếp vào", nên kết quả tổ hợp có `2^n` loại; mà chúng ta có `k` thùng, nên tổng độ phức tạp thời gian là $O(k*2^n)$.

**Đương nhiên, đây là ước tính thô với cận trên độ phức tạp xấu nhất, độ phức tạp thực tế chắc chắn cần tốt rất nhiều, dù sao chúng ta thêm nhiều logic cắt tỉa như vậy**. Có điều, từ cận trên độ phức tạp đã có thể nhận ra ý tưởng thứ nhất cần chậm rất nhiều.

Nên, ai nói thuật toán quay lui không cókỹ thuật? Tuy thuật toán quay lui chính là bạo lựcvét cạn, nhưngvét cạn cũng chia cáchvét cạn thông minh và cáchvét cạn kém hiệu quả, then chốt xem bạn lấy "góc nhìn" của ai tiến hànhvét cạn.

Nói thông tục, chúng ta hẳn cố gắng "ít lượng nhiều lần ", chính là nói thà làm nhiều lần lựa chọn (quan hệ nhân), cũng đừng cho không gian lựa chọn quá lớn (quan hệ số mũ); làm `n` lần "`k` chọn một" chỉ lặp một lần ($O(k^n)$), hơn `n` lần "nhị chọn một" lặp `k` lần ($O(k*2^n)$) hiệu suất thấp rất nhiều.

Rồi, bài này chúng ta từ haigóc nhìn tiến hànhvét cạn, tuy lượng code trông nhiều, nhưng logic cốt lõi đều tương tự, tin rằng bạn thông qua bài này có thể hiểu sâu hơn thuật toán quay lui.
