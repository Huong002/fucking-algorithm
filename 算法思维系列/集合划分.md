Đề非常 đơn giản:

Cho bạn nhập một mảng `nums` và một số nguyên dương `k`, hãy判断 `nums` có thể被平分 thành `k` tập con có tổng phần tử giống nhau không.

Chữ ký hàm như sau:

```java
boolean canPartitionKSubsets(int[] nums, int k);
```

> Tại sao chia thành hai tập con bằng nhau có thể chuyển thành ba lô dùng思路 quy hoạch động giải, mà chia thành `k` tập con bằng nhau就不能 chuyển thành ba lô, chỉ能 dùng thuật toán quay lui bạo lực穷举? Hãy先 thử tự suy nghĩ.

> [!NOTE]
> Tại sao chia hai tập con bằng nhau có thể chuyển thành ba lô?
>
> Trong cảnh [Chia tập con của bài toán ba lô](https://labuladong.online/algo/dynamic-programming/knapsack2/), có một ba lô và若干 vật phẩm, mỗi vật phẩm có **hai lựa chọn**, lần lượt là 「装 vào ba lô」 và 「không装 vào ba lô」. Trong cảnh把 tập gốc `S` chia thành hai tập bằng nhau `S_1, S_2`, mỗi phần tử trong `S` cũng có **hai lựa chọn**, lần lượt là 「装 vào `S_1`」 và 「không装 vào `S_1` (装 vào `S_2`)」, lúc này思路穷举 thực ra giống bài toán ba lô.
>
> Nhưng nếu bạn muốn把 `S` chia thành `k` tập con bằng nhau,相当于 mỗi phần tử trong `S` có **`k` lựa chọn**, chuyện này và cảnh bài toán ba lô chuẩn có khác biệt bản chất, là không thể套思路 giải của bài toán ba lô.

## 思路 đề bài

Trở lại正题, bài thuật toán này bắt chúng ta求 phân hoạch tập con, vấn đề tập con và vấn đề hoán vị tổ hợp có khác biệt, nhưng chúng ta có thể借鉴 trừu tượng 「mô hình bóng-hộp」, dùng hai视角 khác nhau để giải vấn đề phân hoạch tập con này.

把 mảng `nums` đựng `n` số chia thành `k` tập có tổng giống nhau, bạn có thể tưởng tượng把 `n` số phân vào `k` cái 「thùng」, cuối cùng tổng số trong `k` 「thùng」 này要 giống nhau.

Bài trước [Dùng mô hình bóng-hộp hiểu thuật toán quay lui](https://labuladong.online/algo/practice-in-action/two-views-of-backtrack/) từng nói, then chốt của thuật toán quay lui ở đâu?

Then chốt是要 biết 「làm lựa chọn」 thế nào, như vậy mới能 lợi dụng hàm đệ quy tiến hành穷举.

Vậy mô phỏng思路 suy导 công thức hoán vị,把 `n` số phân vào `k` thùng, chúng ta cũng có thể có hai视角:

**视角 một, nếu chúng ta chuyển sang视角 của `n` số này, mỗi số đều要 chọn vào một trong `k` thùng**.

![](https://labuladong.online/algo/images/set-split/5.jpeg)

**视角 hai, nếu chúng ta chuyển sang视角 của `k` thùng này, với mỗi thùng, đều要 duyệt `n` số trong `nums`, rồi chọn có把 số duyệt hiện tại装 vào thùng này của mình không**.

![](https://labuladong.online/algo/images/set-split/6.jpeg)

Bạn có thể hỏi, hai视角 này có khác gì?

Tương tự hoán vị tập con讲 trước đó, dùng视角 khác nhau tiến hành穷举, tuy kết quả giống nhau, nhưng logic code解法 khác nhau, cài đặt code cụ thể cũng khác nhau, có thể sinh độ phức tạp thời-không khác nhau. Chúng ta cần chọn解法 độ phức tạp thấp hơn.

## Lấy视角 số

Dùng vòng for lặp duyệt mảng `nums` mọi người肯定都会:

```java
for (int index = 0; index < nums.length; index++) {
    print(nums[index]);
}
```

Duyệt đệ quy mảng bạn会 không? Thực ra cũng rất đơn giản:

```java
void traverse(int[] nums, int index) {
    if (index == nums.length) {
        return;
    }
    print(nums[index]);
    traverse(nums, index + 1);
}
```

Chỉ cần gọi `traverse(nums, 0)`, và hiệu quả vòng for hoàn toàn giống nhau.

Vậy trở lại bài này, lấy视角 số, chọn `k` thùng, dùng vòng for viết ra là như dưới:

```java
// k thùng (tập hợp), ghi tổng số mỗi thùng đựng
int[] bucket = new int[k];

// 穷举 mỗi số trong nums
for (int index = 0; index < nums.length; index++) {
    // 穷举 mỗi thùng
    for (int i = 0; i < k; i++) {
        // nums[index] chọn có要 vào thùng thứ i không
        // ...
    }
}
```

Nếu đổi thành dạng đệ quy, chính là logic code dưới đây:

```java
// k thùng (tập hợp), ghi tổng số mỗi thùng đựng
int[] bucket = new int[k];

// 穷举 mỗi số trong nums
void backtrack(int[] nums, int index) {
    // base case
    if (index == nums.length) {
        return;
    }
    // 穷举 mỗi thùng
    for (int i = 0; i < bucket.length; i++) {
        // Chọn装 vào thùng thứ i
        bucket[i] += nums[index];
        // Đệ quy穷举 lựa chọn của số tiếp theo
        backtrack(nums, index + 1);
        // Hủy lựa chọn
        bucket[i] -= nums[index];
    }
}
```

Tuy code trên vẻn vẹn là logic穷举, còn chưa thể giải vấn đề của chúng ta, nhưng chỉ cần略加 hoàn thiện là được:

```java
class Solution {
    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Loại một số tình huống cơ bản
        if (k > nums.length) return false;
        int sum = 0;
        for (int v : nums) sum += v;
        if (sum % k != 0) return false;

        // k thùng (tập hợp), ghi tổng số mỗi thùng đựng
        int[] bucket = new int[k];
        // Về lý mỗi thùng (tập hợp) tổng số
        int target = sum / k;
        // 穷举, xem nums có thể chia thành k tập con tổng target không
        return backtrack(nums, 0, bucket, target);
    }

    // Đệ quy穷举 mỗi số trong nums
    boolean backtrack(
        int[] nums, int index, int[] bucket, int target) {

        if (index == nums.length) {
            // Kiểm tra tổng số mọi thùng có đều target không
            for (int i = 0; i < bucket.length; i++) {
                if (bucket[i] != target) {
                    return false;
                }
            }
            // nums thành công平分 thành k tập con
            return true;
        }

        // 穷举 thùng mà nums[index] có thể装 vào
        for (int i = 0; i < bucket.length; i++) {
            // Cắt tỉa, thùng装 đầy rồi
            if (bucket[i] + nums[index] > target) {
                continue;
            }
            // 把 nums[index]装 vào bucket[i]
            bucket[i] += nums[index];
            // Đệ quy穷举 lựa chọn của số tiếp theo
            if (backtrack(nums, index + 1, bucket, target)) {
                return true;
            }
            // Hủy lựa chọn
            bucket[i] -= nums[index];
        }

        // nums[index]装 vào thùng nào cũng không được
        return false;
    }
}
```

Có铺垫 trước đó, tin rằng đoạn code này比较 dễ hiểu, thực ra chúng ta có thể làm thêm một tối ưu.

Chủ yếu xem phần đệ quy của hàm `backtrack`:

```java
for (int i = 0; i < bucket.length; i++) {
    // Cắt tỉa
    if (bucket[i] + nums[index] > target) {
        continue;
    }

    if (backtrack(nums, index + 1, bucket, target)) {
        return true;
    }
}
```

**Nếu chúng ta让 càng nhiều tình huống命中 nhánh if cắt tỉa, là có thể giảm số lần gọi đệ quy, nhất định程度上 giảm độ phức tạp thời gian**.

Làm sao命中 càng nhiều nhánh if này?要 biết tham số `index` của chúng ta递增 từ 0, cũng chính là đệ quy duyệt mảng `nums` từ 0.

Nếu chúng ta sắp xếp trước mảng `nums`,把 số lớn xếp phía trước, vậy số lớn sẽ先被 phân vào `bucket`, với số về sau, `bucket[i] + nums[index]` sẽ lớn hơn, dễ触发 điều kiện if cắt tỉa hơn.

Nên có thể trong code trước đó thêm một số code:

```java
boolean canPartitionKSubsets(int[] nums, int k) {
    // Code khác không đổi
    // ...
    // Sắp xếp giảm dần mảng nums
    Arrays.sort(nums);
    // Lật mảng,得到 mảng giảm dần
    for (i = 0, j = nums.length - 1; i < j; i++, j--) {
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
    // *****************
    return backtrack(nums, 0, bucket, target);
}
```

解法 này có thể得到 đáp án đúng, nhưng tốn thời gian比较 nhiều, đã không thể qua hết test case, tiếp theo xem解法视角 còn lại.

## Lấy视角 thùng

Đầu bài nói, **lấy视角 thùng tiến hành穷举, mỗi thùng cần duyệt tất cả số trong `nums`, quyết định có把 số hiện tại装 vào thùng không; khi装 đầy một thùng xong, còn要装 thùng tiếp theo, cho đến khi mọi thùng đều装 đầy**.

思路 này có thể dùng đoạn code dưới biểu thị ra:

```java
// 装 đầy mọi thùng mới thôi
while (k > 0) {
    // Ghi tổng số trong thùng hiện tại
    int bucket = 0;
    for (int i = 0; i < nums.length; i++) {
        // Quyết định có把 nums[i]放 vào thùng hiện tại không
        if (canAdd(bucket, num[i])) {
            bucket += nums[i];
        }
        if (bucket == target) {
            // 装 đầy một thùng,装 thùng tiếp theo
            k--;
            break;
        }
    }
}
```

Vậy chúng ta cũng có thể把 vòng while này viết lại thành hàm đệ quy, có điều比刚才 hơi phức tạp, trước viết một hàm đệ quy `backtrack` ra:

```java
boolean backtrack(int k, int bucket, int[] nums, int start, boolean[] used, int target);
```

Đừng bị nhiều tham số này dọa, tôi sẽ逐个 giải thích những tham số này. Nếu bạn đủ透彻 hiểu bài trước [Dùng mô hình bóng-hộp hiểu thuật toán quay lui](https://labuladong.online/algo/practice-in-action/two-views-of-backtrack/), cũng能得心应手 viết ra hàm quay lui như vậy.

Tham số của hàm `backtrack` này có thể giải thích như sau:

Bây giờ thùng số `k` đang suy nghĩ có hẳn把 phần tử `nums[start]` này装 vào không; hiện tại trong thùng số `k` đã装 tổng số là `bucket`; `used` đánh dấu một phần tử nào đó có đã被装 vào thùng không; `target` là tổng mục tiêu mỗi thùng cần đạt成.

根據 định nghĩa hàm này, có thể gọi hàm `backtrack` như sau:

```java
class Solution {
    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Loại một số tình huống cơ bản
        if (k > nums.length) return false;
        int sum = 0;
        for (int v : nums) sum += v;
        if (sum % k != 0) return false;

        boolean[] used = new boolean[nums.length];
        int target = sum / k;
        // Thùng số k ban đầu什么 cũng chưa装, từ nums[0] bắt đầu làm lựa chọn
        return backtrack(k, 0, nums, 0, used, target);
    }
}
```

Trước khi实现 logic hàm `backtrack`, lặp lại一遍, từ视角 thùng:

1、Cần duyệt tất cả số trong `nums`, quyết định số nào cần装 vào thùng hiện tại.

2、Nếu thùng hiện tại装 đầy (tổng số trong thùng đạt `target`),則让 thùng tiếp theo bắt đầu thực thi bước 1.

Code dưới就实现 logic này:

```java
class Solution {
    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Xem bài trên
    }

    boolean backtrack(int k, int bucket,
        int[] nums, int start, boolean[] used, int target) {
        // base case
        if (k == 0) {
            // Mọi thùng đều被装 đầy, mà nums nhất định toàn bộ dùng hết
            // Vì target == sum / k
            return true;
        }
        if (bucket == target) {
            // 装 đầy thùng hiện tại, đệ quy穷举 lựa chọn của thùng tiếp theo
            // 让 thùng tiếp theo từ nums[0] bắt đầu chọn số
            return backtrack(k - 1, 0 ,nums, 0, used, target);
        }

        // Từ start探查 về sau nums[i] hiệu quả装 vào thùng hiện tại
        for (int i = start; i < nums.length; i++) {
            // Cắt tỉa
            if (used[i]) {
                // nums[i] đã被装 vào thùng khác
                continue;
            }
            if (nums[i] + bucket > target) {
                // Thùng hiện tại装 không nổi nums[i]
                continue;
            }
            // Làm lựa chọn,把 nums[i]装 vào thùng hiện tại
            used[i] = true;
            bucket += nums[i];
            // Đệ quy穷举 số tiếp theo có装 vào thùng hiện tại không
            if (backtrack(k, bucket, nums, i + 1, used, target)) {
                return true;
            }
            // Hủy lựa chọn
            used[i] = false;
            bucket -= nums[i];
        }
        // 穷举 mọi số, đều không thể装 đầy thùng hiện tại
        return false;
    }
}
```

**Đoạn code này có thể得出 đáp án đúng, nhưng hiệu suất rất thấp, chúng ta có thể suy nghĩ có còn không gian tối ưu không**.

Trước hết, trong解法 này mỗi thùng đều có thể coi là không có差异, nhưng thuật toán quay lui của chúng ta却 sẽ đối xử phân biệt chúng, chỗ này就会 xuất hiện tính toán trùng lặp.

Ý gì? Thuật toán quay lui của chúng ta, nói到底 chính là穷举 mọi tổ hợp có thể, rồi xem có thể tìm ra `k` thùng (tập con) tổng `target` không.

Tốt, đến đây bạn hẳn看出 vấn đề, tình huống này thực ra và tình huống trước đó一样的. Tức là nói, đến đây bạn thực ra đã biết không cần穷举 nữa,必然凑 không ra `k` tập con tổng `target`.

Nhưng thuật toán của chúng ta vẫn sẽ ngốc nghếch tiếp tục穷举, vì trong mắt nó, phần tử装 trong thùng một và thùng hai không giống nhau, vậy đây chính là hai tình huống không giống nhau呀.

Vậy chúng ta làm sao让智商 thuật toán nâng cao, nhận ra tình huống này, tránh tính toán冗余?

Bạn chú ý mảng `used` của hai tình huống này肯定长得 giống nhau, nên mảng `used` có thể coi là 「trạng thái」 trong quá trình quay lui.

**Nên, chúng ta có thể dùng một bảng nhớ `memo`, khi装 đầy một thùng ghi lại trạng thái `used` hiện tại, nếu trạng thái `used` hiện tại là từng xuất hiện, vậy不用 tiếp tục穷举, từ đó起到 cắt tỉa tránh tính toán冗余**.

Có độc giả肯定会 hỏi, `used` là một mảng bool, làm key lưu thế nào? Chuyện này thực ra là vấn đề nhỏ, ví như chúng ta có thể把 mảng chuyển thành chuỗi, như vậy là có thể làm key của bảng băm để lưu.

Xem cài đặt code, chỉ cần sửa chút hàm `backtrack` là được:

```java
class Solution {

    // Bảng nhớ, lưu trạng thái của mảng used
    HashMap<String, Boolean> memo = new HashMap<>();

    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Xem bài trên
    }

    boolean backtrack(int k, int bucket, int[] nums, int start, boolean[] used, int target) {
        // base case
        if (k == 0) {
            return true;
        }
        // 把 trạng thái của used chuyển thành chuỗi dạng [true, false, ...]
        // Tiện存 vào HashMap
        String state = Arrays.toString(used);

        if (bucket == target) {
            // 装 đầy thùng hiện tại, đệ quy穷举 lựa chọn của thùng tiếp theo
            boolean res = backtrack(k - 1, 0, nums, 0, used, target);
            // 把 trạng thái hiện tại và kết quả存 vào bảng nhớ
            memo.put(state, res);
            return res;
        }

        if (memo.containsKey(state)) {
            // Nếu trạng thái hiện tại曾今 tính qua,就 trực tiếp trả về, đừng đệ quy穷举 nữa
            return memo.get(state);
        }

        // Logic khác không đổi...
    }
}
```

Như vậy nộp解法, phát hiện hiệu suất thực thi vẫn比较 thấp, lần này không phải vì tính toán冗余 trên logic thuật toán, mà vấn đề cài đặt code.

**Vì mỗi lần đệ quy đều要把 mảng `used` chuyển thành chuỗi, với ngôn ngữ lập trình cũng là một消耗 không nhỏ, nên chúng ta còn có thể进一步 tối ưu**.

Chú ý规模 dữ liệu đề cho `nums.length <= 16`, tức là nói mảng `used` nhiều nhất cũng sẽ không vượt quá 16, vậy chúng ta hoàn toàn có thể dùng技巧 「ảnh位」, dùng một biến `used` kiểu int để thay mảng `used`.

Cụ thể, chúng ta có thể dùng bit thứ `i` của số nguyên `used` (`(used >> i) & 1`) là 1/0 để biểu thị true/false của `used[i]`.

Như vậy一来, không chỉ tiết kiệm không gian, mà số nguyên `used` cũng có thể trực tiếp làm key存 vào HashMap,省去消耗 chuyển mảng thành chuỗi.

Xem code解法 cuối cùng:

```java
class Solution {
    public boolean canPartitionKSubsets(int[] nums, int k) {
        // Loại một số tình huống cơ bản
        if (k > nums.length) return false;
        int sum = 0;
        for (int v : nums) sum += v;
        if (sum % k != 0) return false;

        // Dùng技巧 ảnh位
        int used = 0;
        int target = sum / k;
        // Thùng số k ban đầu什么 cũng chưa装, từ nums[0] bắt đầu làm lựa chọn
        return backtrack(k, 0, nums, 0, used, target);
    }

    HashMap<Integer, Boolean> memo = new HashMap<>();

    boolean backtrack(int k, int bucket,
                    int[] nums, int start, int used, int target) {
        // base case
        if (k == 0) {
            // Mọi thùng đều被装 đầy, mà nums nhất định toàn bộ dùng hết
            return true;
        }
        if (bucket == target) {
            // 装 đầy thùng hiện tại, đệ quy穷举 lựa chọn của thùng tiếp theo
            // 让 thùng tiếp theo từ nums[0] bắt đầu chọn số
            boolean res = backtrack(k - 1, 0, nums, 0, used, target);
            // Cache kết quả
            memo.put(used, res);
            return res;
        }

        if (memo.containsKey(used)) {
            // Tránh tính toán冗余
            return memo.get(used);
        }

        for (int i = start; i < nums.length; i++) {
            // Cắt tỉa
            // 判断 bit thứ i có phải 1 không
            if (((used >> i) & 1) == 1) {
                // nums[i] đã被装 vào thùng khác
                continue;
            }
            if (nums[i] + bucket > target) {
                continue;
            }
            // Làm lựa chọn
            // 把 vị trí thứ i置 thành 1
            used |= 1 << i;
            bucket += nums[i];
            // Đệ quy穷举 số tiếp theo có装 vào thùng hiện tại không
            if (backtrack(k, bucket, nums, i + 1, used, target)) {
                return true;
            }
            // Hủy lựa chọn
            // Dùng phép xor把 bit thứ i khôi phục 0
            used ^= 1 << i;
            bucket -= nums[i];
        }

        return false;
    }
}
```

## Tổng kết cuối

Hai思路 mà bài này viết đều có thể算 ra đáp án đúng, có điều解法 thứ nhất dù qua tối ưu sắp xếp, cũng明显比解法 thứ hai chậm很多, đây là tại sao?

Chúng ta phân tích độ phức tạp thời gian của hai thuật toán này, giả sử số phần tử trong `nums` là `n`.

Nói trước解法 thứ nhất, cũng chính là từ góc độ số tiến hành穷举, `n` số, mỗi số có `k` thùng可供 chọn, nên số lượng kết quả tổ hợp ra là `k^n`, độ phức tạp thời gian cũng chính là $O(k^n)$.

解法 thứ hai, mỗi thùng要 duyệt `n` số, với mỗi số có hai lựa chọn 「装 vào」 hoặc 「không装 vào」, nên kết quả tổ hợp có `2^n`种; mà chúng ta có `k` thùng, nên tổng độ phức tạp thời gian là $O(k*2^n)$.

**Đương nhiên, đây là估算 thô với上界 độ phức tạp xấu nhất, độ phức tạp thực tế肯定要 tốt很多, dù sao chúng ta thêm nhiều logic cắt tỉa như vậy**. Có điều, từ上界 độ phức tạp đã có thể看出思路 thứ nhất要 chậm很多.

Nên, ai nói thuật toán quay lui không có技巧? Tuy thuật toán quay lui chính là bạo lực穷举, nhưng穷举 cũng分 cách穷举 thông minh và cách穷举 kém hiệu quả, then chốt xem bạn lấy 「视角」 của ai tiến hành穷举.

Nói thông tục, chúng ta hẳn尽量 「ít量多次」, chính là nói thà làm nhiều lần lựa chọn (quan hệ nhân), cũng đừng cho không gian lựa chọn quá lớn (quan hệ指数); làm `n` lần 「`k` chọn một」 chỉ lặp một lần ($O(k^n)$),比 `n` lần 「nhị chọn một」 lặp `k` lần ($O(k*2^n)$) hiệu suất thấp很多.

Rồi, bài này chúng ta từ hai视角 tiến hành穷举, tuy lượng code trông nhiều, nhưng logic cốt lõi đều tương tự, tin rằng bạn thông qua bài này có thể hiểu sâu hơn thuật toán quay lui.
