### Một, phân tích思路

Tại sao nói vấn đề này có tính chất đệ quy? Ví dụ chúng ta cần cài đặt một hàm như sau:

```java
// cakes là một đống bánh, hàm sẽ sắp xếp n chiếc bánh phía trước
void sort(int[] cakes, int n);
```

Nếu chúng ta tìm được chiếc lớn nhất trong `n` chiếc bánh phía trước, rồi设法 lật chiếc bánh này xuống dưới cùng:

![](https://labuladong.online/algo/images/pancakeSort/3.jpg)

Vậy, quy mô của bài toán gốc có thể giảm đi, gọi đệ quy `pancakeSort(A, n-1)` là được:

![](https://labuladong.online/algo/images/pancakeSort/4.jpg)

Tiếp theo, với `n - 1` chiếc bánh trên đây, sắp xếp thế nào? Vẫn là tìm ra chiếc bánh lớn nhất trước, rồi đặt chiếc bánh này xuống dưới, rồi gọi đệ quy `pancakeSort(A, n-1-1)`……

Bạn xem, đây chính là tính chất đệ quy, tổng kết思路 như sau:

1、Tìm chiếc lớn nhất trong `n` chiếc bánh.

2、Chuyển chiếc bánh lớn nhất này xuống dưới cùng.

3、Gọi đệ quy `pancakeSort(A, n - 1)`.

base case: khi `n == 1`, sắp xếp 1 chiếc bánh thì không cần lật.

Vậy, cuối cùng còn một vấn đề, **làm sao设法 lật một chiếc bánh nào đó xuống cuối cùng**?

Thực ra rất đơn giản, ví dụ chiếc bánh thứ 3 là lớn nhất, chúng ta muốn đổi nó xuống cuối, tức đổi xuống chiếc thứ `n`. Có thể thao tác như sau:

1、Dùng xẻng lật 3 chiếc bánh phía trước một cái, vậy chiếc bánh lớn nhất就被 lật lên trên cùng nhất.

2、Dùng xẻng lật toàn bộ `n` chiếc bánh phía trước, vậy chiếc bánh lớn nhất就被 lật xuống chiếc thứ `n`, tức chiếc cuối cùng.

Sau khi hiểu hai quy trình trên, cơ bản có thể viết ra lời giải, có điều đề bài yêu cầu chúng ta viết ra dãy thao tác lật cụ thể, chuyện này cũng rất đơn giản, chỉ cần mỗi lần lật bánh thì ghi lại là được.

### Hai, cài đặt code

Chỉ cần cài đặt思路 trên bằng code là được, duy nhất cần chú ý là, chỉ số mảng bắt đầu từ 0, mà kết quả chúng ta trả về tính từ 1.

```java
class Solution {
    // Ghi lại dãy thao tác lật
    LinkedList<Integer> res = new LinkedList<>();

    public List<Integer> pancakeSort(int[] cakes) {
        sort(cakes, cakes.length);
        return res;
    }

    void sort(int[] cakes, int n) {
        // base case
        if (n == 1) return;

        // Tìm chỉ số của chiếc bánh lớn nhất
        int maxCake = 0;
        int maxCakeIndex = 0;
        for (int i = 0; i < n; i++)
            if (cakes[i] > maxCake) {
                maxCakeIndex = i;
                maxCake = cakes[i];
            }

        // Lần lật thứ nhất, lật chiếc bánh lớn nhất lên trên cùng
        reverse(cakes, 0, maxCakeIndex);
        res.add(maxCakeIndex + 1);
        // Lần lật thứ hai, lật chiếc bánh lớn nhất xuống dưới cùng
        reverse(cakes, 0, n - 1);
        res.add(n);

        // Gọi đệ quy
        sort(cakes, n - 1);
    }

    void reverse(int[] arr, int i, int j) {
        while (i < j) {
            int temp = arr[i];
            arr[i] = arr[j];
            arr[j] = temp;
            i++; j--;
        }
    }
}
```

Thông qua giải thích chi tiết vừa rồi, đoạn code này hẳn là rất rõ ràng.

Độ phức tạp thời gian của thuật toán rất dễ tính, vì số lần gọi đệ quy là `n`, mỗi lần gọi đệ quy đều cần một vòng for, độ phức tạp thời gian là O(n), nên tổng độ phức tạp là O(n^2).

**Cuối cùng, chúng ta có thể suy nghĩ một câu hỏi**: theo思路 này của chúng ta, độ dài dãy thao tác thu được hẳn là `2(n - 1)`, vì mỗi lần đệ quy đều tiến hành 2 lần lật và ghi lại thao tác, tổng cộng có `n` tầng đệ quy, nhưng do base case trả về trực tiếp kết quả, không tiến hành lật, nên độ dài dãy thao tác cuối cùng hẳn là cố định `2(n - 1)`.

Hiển nhiên, kết quả này không phải tối ưu (ngắn nhất), ví dụ một đống bánh `[3,2,4,1]`, dãy lật mà thuật toán của chúng ta thu được là `[3,4,2,3,1,2]`, nhưng cách lật快捷 nhất hẳn là `[2,3,4]`:

```
Trạng thái ban đầu:[3,2,4,1]
Lật 2 cái đầu:[2,3,4,1]
Lật 3 cái đầu:[4,3,2,1]
Lật 4 cái đầu:[1,2,3,4]
```
